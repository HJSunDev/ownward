# 第一版验收

第一版的信息组织与检索采用固定回归、动态未见和公开前沿三类互补证据。固定回归防止已知问题复发；动态未见在候选版本冻结后生成，验证具体内容、语义组合和表达未参与调优时产品仍然成立；公开基准验证检索质量与时效达到同类前沿。三类证据不能相互替代，并与交付定义中的其他完成条件共同构成最终验收。

`v1/` 至 `v5/` 永久保留历史基线及其修正过程。`v5/` 已经参与实现诊断与调优，因此从最终验收基线降为当前固定回归基线；它继续验证已知行为，但不能作为通用性和第一版完成的独立证明。

固定数据全部是合成信息，不包含用户的真实个人信息。动态验收只预先冻结生成方法、覆盖范围、真值形成方式、裁判方式、增量补充顺序、资源预算和通过标准；冻结候选前先验证数据路径，正式内容在候选版本冻结后生成，并保留随机来源与完整证据。

当前固定回归由 [`fixed/verify.py`](fixed/verify.py) 执行：候选发布包提供本地向量能力，同一个外部智能体经正式语义协作契约完成内容理解；语义阶段无法接触查询、答案和关系金标。固定集的既有精确关系标签只输出诊断结果，不判定开放语义质量；资产、语义协作完成、检索和已知行为回归仍是硬性条件。旧模型服务与启发式语义路径不再构成验收入口。

## 动态未见验收契约

1. 先生成机器可读的隐藏语义场景及其权威关系、适用条件和查询答案，再生成供 Ownward 接收的自然语言信息；被测产品只能看到自然语言信息和查询。
2. 生成过程组合需求规定的信息范围、跨时间关系、多重归属、层级、交叉、组合、场景依赖、更新顺序和表达变化，不预设具体内容。
3. 关系真值遵循协议冻结的统一关系定义与方向。独立于被测语义能力的验证者在运行前检查信息是否充分表达隐藏真值；能够合理解释为其他关系类型、多个类型或相反方向的样本直接废弃。各类场景增量验证，合格项即时冻结，只补固定数量缺口；所有生成结果、废弃理由、未验证备用项和验证结论完整保留，不依据 Ownward 输出修正真值。
4. 候选提交、生成方法、覆盖分布、裁判方法、增量补充顺序、资源预算、统计判定规则和质量阈值全部绑定报告。候选冻结前必须以每类最小样本通过生成与独立验证预检；候选冻结后按预定且可审计的方法产生一次随机种子和候选池，达到各类有效数量后立即停止数据验证。符合规则的有效项不得选择性放弃或重跑；产品、配置或候选发生变化，整批未见数据立即失效。
5. 以独立语义场景为统计单位，比例指标按预先冻结的置信区间规则判定；资产损坏、明确语义改变、身份变化及错误合并或拆分等零容忍事件一经出现立即失败，达到资源上限仍无法明确判定时按失败处理。
6. 候选必须使用正式发布默认的本地向量能力和[语义理解路径](../../docs/modules/semantics/README.md)。第一版由接入的外部智能体兼任语义能力，经统一契约提供带来源、依据和不确定性的候选判断；不得注入旧版模型服务、测试向量能力或专用语义实现。动态规模保持统计规则下的最小充分值；Ownward 自身操作按冻结时延验收，外部语义协作记录真实耗时与成本并受异常停止约束，检索按公开前沿验收。不能用无依据的绝对门槛或多个宽松超时制造假失败或无边界长任务。

## 组织结构增益对照

同一批动态未见数据必须使用同一候选发布二进制，在同一环境分别运行完整 Ownward 和无组织关系基线。除关闭内核维护的关系组织状态、关系信号和关系导航外，基线的长期资产、配置、模型、词法与向量检索、外部智能体、查询和预算必须与完整系统相同；不得换用独立实现或降低基线能力。

跨时间、多步关联、场景适用和信息更新四类任务必须分别判定。最小有效差异、等价界限和统计规则在候选冻结前确定；任何一类超过等价界限的退化均不通过，且至少一类必须在端到端质量、时效或总成本上达到最小有效优势。总成本必须覆盖该批信息的沉淀、组织、索引维护以及全部检索和模型调用，不得通过汇总平均或排除组织成本制造优势；简单检索不承担证明组织增益的职责。

## 检索编排校准

当前编排首先由动态未见、组织能力消融和公开前沿共同验证，不为生成独立报告而重复运行同一证据。只有现有证据无法收敛，且已经形成可能改变第一版结论的具体替代方案时，才在查看结果前固定该方案、任务类别、质量、时效、资源指标和选择规则，复用同一批动态数据执行最小定向对照。

发生对照时，所有方案使用同一候选发布二进制、动态未见数据、模型、外部智能体和检索预算，只改变被比较的编排路径，并逐类报告质量、时效和资源成本。不得针对结果调整候选或口径，也不得重新执行与变化无关的生成、组织和查询。最终方案不得在任何硬性完成条件上退化，并与[检索体系演进](../../docs/modules/retrieval/README.md)的当前有效版本一致；验证要求改变编排时追加新版本，不改写既有记录。

## 模块生命周期验收

同一最终候选必须验证存储、向量与语义能力的完整生命周期：派生世代完整生成、校验、原子切换、失败回退和旧状态回收；模型、运行时、向量空间、派生向量和索引的世代一致性与新旧空间隔离；语义工作与资产版本绑定，候选来源、依据和不确定性完整，冲突与过期结果被正确处理；向量或语义能力不可用时信息安全写入并保留明确待处理状态，恢复后能够继续处理或重新评估。所有故障必须由真实生产路径触发，不得以测试替身、旁路语义实现或人工改写状态作为通过证据。
