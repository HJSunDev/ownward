# 架构演进方向的研究依据

研究日期：2026-11-18。本文解释[架构演进方向](../architecture/evolution-direction.md)的依据、取舍和适用边界，不作为已实现能力或具体技术选型的声明。

## 研究问题与范围

OWNWARD 面向的是用户长期持有、可供不同智能体共同使用的个人信息体系。决定架构方向的关键问题是：模型能处理更多历史后，哪些结构仍有必要；信息如何跨越技术更替；新的组织与理解如何增长而不丢失依据、越过用户控制；信息使用如何随任务与智能能力变化。

研究对照了外部记忆、图谱、模型内记忆、长上下文与持续学习等路线，也追溯数据独立性、长期数字保存、来源追溯、端到端分工、分布式认知和情境隐私。选择依据是能否改变上述判断，不以新旧、名气或论文数量排序。既有总纲用于核对产品边界，不充当这些方向成立的证明。

## 重要来源及其边界

## 从根本需要推导结构取舍

### 信息与控制不能依附各个接入者

个人信息的使用期跨越应用、模型和提供者。若每个接入者都独立决定当前资料、授权与遗忘是否有效，就无法保证换入口后仍沿用用户的同一决定。因此，接入方式可以变化，有效状态与控制规则必须有共同权威；协议适配不能另立私有裁决。

这不是指定单机、数据库或网络拓扑。共同权威可以更换实现，也可通过不同部署维持；评价依据是控制规则和有效状态是否一致，而不是节点数量。使用权与管理权可以授予同一接入者，但前者不自动包含后者。

代价是维护稳定的能力语义及各入口共同遵守的控制边界。若产品改为彼此独立、无需共享控制的多个信息库，这条方向的前提才改变；只提升模型能力不会改变该前提。

### 长期资产不能等同于一次加工的结果

若两份有关键差异的资料被压成同一份摘要，而未来的问题恰好需要那个差异，仅凭摘要就无法可靠区分两种情况。增加推理能力不能补回既未保留、又没有其他来源的事实。这是信息损失本身的限制，不只是当前模型容易犯错。

因此，要区分承担独立保留义务的信息，与可以根据保留依据重新生成的组织结果。区分不取决于文件格式或谁写的：用户采纳的总结、新关系、明确更正和经验都能成为资产；索引、图或模型侧表示只有在所需含义可重建时，才可视为可丢弃结果。派生组织应积极帮助使用，但不能凭加工身份取得改写依据的权力。

这会增加必要来源、语境和依赖维护的成本，却使新任务、纠错和新能力有机会重新解释信息。保留范围服从用户意图：允许只留摘要或主动删源，不要求保存每次编辑，更不要求无差别收集。遗忘约束受控派生物及恢复过程，不承诺擦除不受控的外部副本；独立资产是否一并删除仍由用户意图决定。

存储与上下文成本大幅下降，会降低保留和直接读取的代价，却不会让已经丢失的差异重新出现；存储便宜也不构成扩大收集或拒绝遗忘的理由。反过来，若信息只服务确定的一次性用途、无需长期保留或重新判断，就不必建立资产与派生的长期分工；若新的表示能完整恢复所需含义，它也可以成为资产载体，无须额外保存原格式。方向保护的是信息及其保留义务，不是某种原件格式。

### 固定处理流程不能成为智能进步的上限

信息维护需要可靠的操作与控制，具体问题所需的组织、查找和推理深度却会随任务与模型变化。将两者绑定，会迫使简单任务支付无用处理成本，也使更强模型被旧流程限制；全部取消组织，又会丢失确有价值的关联和经验积累。

因此，让语义策略与可靠操作的支撑分开演进：提供可组合能力，具体处理方式按任务质量与总成本选择。复杂任务可以采用多阶段处理、预先组织或反思；这些方式必须有可替换、可简化的边界，不能因为曾经有用就成为所有请求的固定前提。当前由外部智能体主导任务的职责来自[产品需求](../product/requirements.md)，不是从端到端论文直接推出的事实。

代价是保留清晰契约并检验适用条件，不能依靠一条固定流水线覆盖所有情形。更强模型可以减少补偿步骤，也能使更深的组织变得值得；方向要求开放这种选择，不预言流程数量只能下降。

上下文大幅增长、推理和存储成本下降，会改变预先组织、直接读取及多步处理的收益，仍不会把“模型认为可以”变成实际授权或已提交状态。这里的解耦针对异构智能体与持续变化的用途；在任务、输入和模型长期固定的专用系统中，一体化流程经验证可以更合适，无须为本不存在的变化预设替换层。无具体查询时的预先组织也不被排除，其价值同样以实际使用效果和总成本衡量。

## 竞争路线与边界检验

| 提案 | 判断 |
| --- | --- |
| 只靠模型的长期记忆持有用户信息 | 模型内记忆是可用载体候选；若用户退出或换实现后无法继续理解、恢复和控制信息，则不满足方向。不能仅凭其非文本形态否定 |
| 所有源记录永久不删，更新只能追加 | 不采纳。保留依据服务用户，不能阻止其正常编辑、选择只留总结或遗忘；历史陈述与有效更正仍须准确区分 |
| 一切加工结果均可丢弃 | 不采纳。已采纳且不可从保留依据重建的新含义须独立保留；不能按“模型生成”这一标签判定 |
| 每个入口各自更新资料与权限，再无条件合并 | 不采纳其绕开共同权威的做法，但不一概否定复制或 CRDT。[Automerge 的并发值保留](https://automerge.org/docs/reference/documents/conflicts/)就是“自动合并必然抹平所有分歧”的反例；采用任何技术仍须另证授权、冲突及遗忘合同 |
| 默认所有请求经过固定的多阶段提示词管线 | 不采纳无条件固定。处理深度须有实际价值，且能随任务与模型变化替换；复杂任务的有效多阶段处理不被禁止 |
| 取消所有组织，只保存原记录供模型搜索 | 不作为统一方向。直接搜索可以最优，结构化组织也能提供增益；比较质量、总成本与真实使用条件后选择 |
| 用来源可追溯替代真实性判断 | 不成立。可追溯说明信息如何产生，不证明内容正确、仍适用或有权支配当前行动 |

这三条分别约束共同权威、资产与派生的分界、语义处理的演进方式。只满足其中一条不足以满足其余两条：可导出的资料仍会在加工中丢失含义；完整保留依据仍会因各入口自立权限而失控；前两者做对也仍会被固定重流程拖累。

## 结论的有效范围

这些方向以个人信息跨工具长期持有、用户保持控制、用途与智能能力持续变化为前提。模型更强、上下文更长、存储更便宜不会自动消除这些关系；但本研究没有证明某个具体架构永久最优，也没有证明现有产品已完整实现它们。

若新的载体能提供更好的信息延续、控制与可重判能力，应允许替换；若实际使用证明某项组织或处理不再有净收益，应简化或取消。改变产品归属、控制义务或交付范围，则应先重新确认产品要求，不能借演进方向自行扩大授权。
