# 信息使用能力探索记录

记录日期：2026-09-07。本文保留探索依据与实验结论；产品职责以[核心需求](../product/requirements.md#信息使用能力)为准。

探索方法见[持续探索方法](../engineering/information-use-exploration.md)。当前接续：**82、114、116 已完成本轮修复验证；原样能力对剩余 72、87、89、97、112 的五题验证关闭 0 题，97 有部分改善。** 保留原三题成果，以及五题中已出现但未被最终采用的合理候选；当前未修改能力、未运行固定 24 题或续跑最终测试，后续状态以[迭代任务](../tasks/kernel-v2-final-test-failure-analysis.md)为准。

## 一、背景

V2 最终测试最初取得 110 道有效结果：单对话题 68／68 正确，跨对话题仅 35／42 正确（83.33%），7 个错误全部集中在跨对话汇总。修复信息获取短板后，后续九道失败的复核仍发现：多题关键事实已经交付，Reader 却自行增加限制、错误合并事件，或未能合理处理时间与事实冲突。

已有能力核验支持继续使用 Qwen3.8 Flash，但模型具备能力、内核提供信息，并不自动保证任务完成质量。由此产生独立需求：工程上不仅要帮助智能体取得信息，还要帮助它有效使用已经取得的信息，不能把这部分失败一概归为模型问题而停止改进。

## 二、核心思路

**将“信息使用”作为与“信息获取”同等重要的独立产品能力，通过设计外部智能体处理信息的工作过程，提高它在真实、不完美的信息环境中完成用户目标的质量。**

外部智能体始终是主角，提供理解、推理与取舍；Ownward 提供必要的协作支撑，不内置模型，不用确定性代码代替语义判断，也不把增加提示词或处理步骤当成效果。实现路径保持开放，以实际收益选择方案，不预设必须采用工作区、固定流程或多个角色。

方向判断已写入核心需求：产品方向成立且具备工程可行性，具体方案暂时失败不等于方向错误。信息存在冲突不构成放弃任务的理由，只要预期结果合理可行，就应努力完成；无法由事实合理支持的标答，则与系统能力缺陷分别判断。

核心三题 82、114、116 的问题与已验证收益见[三题登记](../tasks/kernel-v2-final-test-failure-analysis.md#信息使用工程优先解决的三题)；剩余五题的责任归因与本轮结果统一留在同一任务文档。
