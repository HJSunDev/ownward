# 多阶段信息使用方案记录

本文记录低等待方案替换前的信息使用组件，保留其有效机制与停用原因；现行实现见[模块说明](../modules/information-use/README.md)。

## 实现方式

内核提供原始信息后，由外部智能在多个独立上下文中分步处理；Ownward 只编排材料交接、结构校验和明确修订，不内置模型。

1. **按需启动：** 智能体完成取证并形成初稿，选择是否使用组件；选择直接交付时，另一次独立判断检查是否仍需协作。
2. **理解与起草：** 独立理解原文；没有初稿时，与起草并行，已有初稿则直接复用。
3. **竞争与比较：** 基于原文、理解和初稿生成另一份有据方案，再独立比较两个方案、选取并提出必要修改；代码应用明确的文本修改，不重新生成整份结果。
4. **查漏与补充：** 寻找尚未覆盖的有用结果；有补充才另开上下文核验，成立后追加。
5. **按需核验依赖：** 判断结论是否依赖未成立的事实连接，需要时回到原文核验并局部修订。

各阶段保留原始需求和相应材料，模型产物不升级为事实；中断时续接同一步的工作笔记，避免从头重复推演。每次调用只交付当前阶段的职责，而非把整套要求塞入一次请求。

## 为什么能提升质量

**它将取得信息与正确使用信息分开处理。** 独立理解减少初稿对原文解释的牵引，有据的竞争方案暴露单一路径遗漏的解释，比较回到原始需求与证据做取舍；局部修订保留正确部分，补充核验控制新增错误，依赖检查避免把未知前提当成事实。

已验证收益包括：82区分相似事件、114避免擅自收窄“替换”的含义、116结合近期澄清处理日期冲突；三题均由原有错误转为通过，并扩展形成[固定六题保底能力](../engineering/information-use-exploration.md#组件迭代基线与固定保底集)。逐项实验与适用边界见[历史探索记录](information-use-exploration.md)。

## 耗时短板与取舍

历史实测平均每题**组件后处理508.80秒，完整交付等待584.64秒（约9分45秒）**；信息已存好仍需等待，裁判评分不计入。计时构成见[耗时分析](../tasks/single-task-latency.md#原方案合计与用户实际等待)。

多数步骤依赖前一步产物，重复处理同批原文并串行调用模型；按需分派本身也需模型判断，中断重试进一步增加成本。**质量收益真实，但高成本纠偏位于用户等待结果的关键路径，无法作为可接受的常规交付方式。**

保留分工、原文取舍和条件结果等机制的研究价值，正式流程不保留旧复核链。旧实现可从 Git 提交 `8bb5e04` 的 `integrations/python/ownward_information_use.py` 恢复；[新旧方案对照](../tasks/single-task-latency.md#方案变化与质量保持)记录替代方式及质量验证。
