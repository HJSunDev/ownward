# V1 最终测试质量偏差分析

> 纠偏：本记录分析的是旧宿主固定预取口径。后续已确认该观察器越过外部智能体主动检索职责，因此本文分数、回归与缺口只能解释旧被动评测流程，不能证明 V0/V1 产品能力、内核根因或晋升结论。权威处置见[《评测观察器越权事故》](evaluation-observer-product-boundary-violation.md)。本文保留为历史分析，不再作为 V2 优化依据。

> **状态**：历史记录。旧结果只证明被动评测流程，不再裁决 V1 产品能力、根因或晋升资格。

## 结论

- V1 为 `285/500`、`57.00%`，相对 V0 的 `242/500` 净增 43 题、准确率提高 8.6 个百分点、剩余错误减少 16.7%，不符合“大版本整体跃升”的要求。
- 实际有 101 道 V0 错题转为正确，同时有 58 道 V0 正确题退化，净收益才是 43。问题不是只修好了少量样本，而是收益伴随大面积回归。
- 快速优化集没有复制正式题目、答案、Gold ID 或会话内容，不存在直接记题或样本泄漏；但它过度拟合了人工构造的机制代理，未证明真实长会话中的证据片段仍完整、正确、时序有效并足以回答问题。
- V1 的存储、沉淀和召回改进真实存在，但端到端质量泛化未成立。不能据此判断全部内核工作无价值，也不能再宣称当前迭代方法足以保证用户环境质量。

## 质量为什么没有达到预期

| 首个可观察缺口 | V0 | V1 | 含义 |
| --- | ---: | ---: | --- |
| 目标证据未被搜索返回 | 116 | 6 | 语义表示与召回大幅改善 |
| 目标证据未被读取 | 133 | 69 | 组织粒度与装载有所改善 |
| 读取目标资产后仍答错 | 9 | 140 | 证据交付质量发生严重退化 |

V1 把平均上下文从 `16,474` 字符压缩到 `3,043` 字符，并把 Reader 输入从 `3.26M` Token 降到 `1.95M` Token。压缩后的证据以细粒度片段交付，但诊断仍只按资产 ID 判断“目标证据已读”。同一长会话中读取了错误片段、缺少必要上下文或同时读取新旧冲突事实，也会被计为命中。

真实结果已经证明这一错位：

- `7161e7e2` 中，V1 命中了包含轮班表的资产，却没有交付含 Admon 最终周日班次的完整片段，V0 正确而 V1 回答“没有该信息”。
- `07741c45` 中，V1 同时交付“床下”和后来更新为“鞋架”的片段，缺少可靠的新旧状态裁决，Reader 选择了旧答案；诊断仍将其记为已读取目标资产。

因此，快速视图中的“证据召回 100%”只证明某个资产或人工片段进入链路，不等价于真实问题所需事实被完整、无歧义地交给 Reader。

## 上一次迭代方法的问题

V0 的 258 道错题确实全部进入问题池，并被归为组织粒度、上下文装载、语义表示和 Reader 边界四类；但正式内容没有直接进入快速集。快速集由少量合成视图代替：组织视图 20 个资产、10 个查询，语义视图 6 个资产、6 个查询，预算装载视图 8 个案例，且大量使用单事实资产、固定语义和理想化向量。

根本原因是证据职责混淆：依据已知失败构造的局部代理既用于反复开发，又用于证明方向完成；在最终测试前，没有独立未见数据检验泛化，也没有真实端到端回归集保护旧能力。问题不在样本少本身，而在样本失真、评价目标错位以及开发证据被当成晋升证据。

这保证了无数据泄漏，却造成三个验证缺口：

1. **代理目标错误**：以资产身份或人工片段召回代替精确事实片段、时序冲突和最终回答充分性。
2. **分布覆盖不足**：合成样本没有覆盖真实长会话中的多事实、多轮角色、更新冲突、表格边界和干扰片段。
3. **缺少真实回归保护**：方向保护仍是同类内部视图，没有代表性留出集证明原有正确能力不退化，因而漏掉了 58 道回归。

内部 `24/24` 和五方向关闭证明的是这些局部合同，不是全链路回答质量。把局部指标的翻倍或归零外推为最终准确率的大幅提升，是本次误判的直接原因。

## 是否属于测试集过拟合

**不是题目级过拟合，但属于机制代理过拟合。**

- 否：正式题目、答案、Gold ID、会话正文与内部快速集不重合；V1 实际修复了 101 道正式错题，远多于任何单个快速视图的样本量。
- 是：快速集把已知失败压缩成过于理想的玩具结构，候选只需通过这些结构即可关闭方向，没有证明同一机制在未见的真实复杂结构中成立。

其后果与用户担忧一致：当前证据不足以证明 V1 在真实用户信息中能够稳定泛化。正式 500 题即使以后全部通过，也必须依靠独立、未见、结构真实的内部留出验证，不能继续用同一问题池及其定向代理同时指导优化和证明泛化。

## 后续迭代要求

- 保留既定优化方向及优先级；每个大版本先审视全部方向，只优化存在真实瓶颈和有效提升空间的方向，不为覆盖清单强行修改已经足够优秀的部分。需要重建的是失真的迭代与验证方法。
- 从本文确认的根因出发设计优化，候选必须在端到端质量与性能上形成大幅整体提升，并保护既有正确能力；局部代理指标改善不能作为完成依据。
- 在既有优化集、回归集和正式测试之外，新增一次性反过拟合抽检；原有数据仍按各自职责保留和复用，不适用一次性废弃规则。候选阶段性冻结后，独立流程按照固定高质量标准临时、随机生成少量精品盲测数据；随机只改变具体内容，不降低场景复杂度、事实一致性、答案确定性和评价质量。该数据只用于检验改进是否依赖已知样本或狭窄代理，每组仅使用一次，测试结束立即废弃；候选继续调整后重新生成。
- 日常定位、优化和重复验证必须保持分钟级，只重跑受影响部分并尽早淘汰无效路线；只有多组独立验证均证明大幅提升且无实质退化，才运行高成本最终测试。
- 最终方法必须同时证明提升真实、迭代高效且不依赖固定测试集或精选样本成立；对未知数据和真实用户场景缺少泛化证据时，不得晋升内核。

## 最终判断

- V1 不晋升，不作为已完成的大版本。
- 正式结果应冻结为新的诊断证据；在重建端到端验证门槛前，不再运行完整 500 题。
- 后续方向关闭必须同时证明精确证据片段充分性、冲突与时间裁决、最终回答效用及既有正确能力不退化；仅有资产召回、合成视图满分或内部场景全通过不得关闭。
- V0 与 V1 的测试工具及阶段身份不同，报告自身也未形成等价参考判定；`+43` 只能作为描述性差异，不能作为严格的内核因果提升。下一轮必须先建立同一评测身份下的稳定对照与独立留出证据。
