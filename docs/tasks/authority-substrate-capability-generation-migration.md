# 权威基座—能力世代架构迁移

> **状态**：已完成；第 1—8 项已在同一终态组合、唯一 v6 binding 与唯一 v3 state 上完成验证。
> **职责**：把当前实现迁移到[《架构总纲》](../architecture/overview.md)规定的目标架构。总纲只定义“是什么”，本文负责“如何从现状到达”。

## 一、目标

在不改变当前稳定内核、V1 及其他现存有效内核候选的能力、效率、质量、直接依赖和候选状态，并保持其身份连续性，也不改变产品能力与用户资产的前提下，落地权威运行基座、四类状态、显式装配、能力世代、无损替换生命周期及精确证据身份。

迁移完成后，当前稳定内核原样成为第一内核世代；资产、内核、模型、存储和接入按真实直接依赖独立演进。无关文档、接入、评测工具或项目功能变化不再迫使稳定内核重测。

## 二、依据与基线

- 唯一目标架构：[《架构总纲》](../architecture/overview.md)。
- 产品边界：[《产品需求》](../product/requirements.md)。
- 当前实现、测试和证据只确定迁移起点，不得反向降低目标架构。
- 开始迁移时，机械冻结当前活动产品、已晋升内核、研发候选、配置、直接依赖、有效证据和可观察行为；三者必须分别登记，不得以源码 HEAD、研发候选或对话结论代替活动事实。
- 现有记录将 V0 标为唯一正式基线，并另行保留已经完成内核迭代的 V1 候选及内部证据；第 1 项必须按制品、活动状态和原始证据核定真实关系。架构迁移只能改变承载边界，不能重新解释、降级、重新实现或丢弃 V1 的实现、配置、直接依赖、能力表现、有效证据及未晋升状态。

## 三、当前事实与迁移差距

- `internal/core.Service` 只持有稳定资产权威、语义和向量契约，继续拥有派生状态及词法与语义检索；迁移期旧构造器与旧 Provider 适配已删除，活动 `cmd/ownward` 只由唯一显式入口决定 collaborative 产品语义。
- `authoritysubstrate.Substrate` 是具体资产存储与 `control-state/v1` 的唯一运行所有者；无状态、派生状态和权威持久化三类替换均已有独立离线入口、耐久检查点、受控晋升、观察与安全回退。
- MCP 只依赖 `product-capability/v1`；协作规则由唯一的 `product-rules/v1` 来源经统一产品能力发布。接入、智能能力、权威基座和内核之间已经形成稳定同进程契约边界；三类状态影响均已具备与其风险相称的替换生命周期，正常产品请求路径不加载迁移实现。
- Acceptance Binding 已以组件内容与直接依赖表达产品、权威基座、内核、智能能力、接入、组合、制品、环境、观察者和验收工具；Git 只保留为审计来源。V0/V1 既有报告、检查点和基线历史已无损映射；活动入口只接受 v6 binding 与 v3 state，旧格式仅由一次性迁移和冻结审计入口只读解释。
- 现有资产、派生世代、检查点及验收绑定均已承载有效状态，迁移必须先证明新结构成立，再切换并清理旧路径。

### 第 2 项实施边界

第 2 项只建立稳定契约、独立组件身份与唯一显式装配，不迁移状态、不切换候选或控制状态：

1. 先为资产权威、最小控制状态、统一能力、内核生命周期、语义与向量端口建立版本化契约，保持冻结的活动产品、V0、V1 行为不变。
2. 由直接内容与声明依赖产生组件身份和组合清单；Git 来源只保留审计属性，不能再充当产品或能力身份。
3. 用唯一装配入口显式表达现有三类构造语义及退化行为，并机械拒绝缺失、错绑和不兼容组合；本项结束前不得删除旧入口。
4. 以本节冻结清单为输入证明新旧装配等价；V0 的正式基线历史、V1 的未晋升状态和四个内部检查点必须保持原样。

### 第 2 项第一条问题链终态

版本化契约位于 [`internal/contract`](../../internal/contract)，以强类型产品端口和可摘要的契约目录共同表达当前产品语义：

| 契约 | 当前实现对应关系 | 本轮边界 |
| --- | --- | --- |
| `asset-authority/v1` | `authoritysubstrate.Substrate` 持有的 `authorityport.Current` 无损适配 `assetlog.Store` | 覆盖耐久提交、按资产 revision 的版本化读取、变化范围、维护和备份；没有新增全局变化序列，已接管活动装配路径 |
| `control-state/v1` | `authoritysubstrate.Substrate` 的最小耐久控制存储 | 只保存活动组合、活动内核世代和 CAS 修订；不包含候选资格、Acceptance baseline 或运行易失状态 |
| `product-capability/v1` | `core.Service` 编译期满足；原 `core` DTO 保留类型别名 | 覆盖规则、创建、更新、读取、证据、检索、导航和语义协作，不暴露存储、模型或部署类型 |

唯一组合描述是 [`current-collaborative.json`](../../manifests/compositions/v1/current-collaborative.json)：它以 7 个角色、9 项版本化组合契约和 69 个直接内容文件描述当前协作产品的权威基座、内核、语义、向量、接入、产品规则及现有命令装配，当前组合身份为 `bdebd16f…8bc5`。组件身份只包含内容摘要、契约定义内容摘要、非秘密配置和声明的直接依赖，组合身份只包含组件身份及依赖图。候选提交 `3e712f2` 与迁移来源只在 `audit` 中登记，不参与任何身份；令牌、PID、端口和活动数据不进入清单。装配角色明确绑定 `internal/assembly.Open` 与 collaborative 产品语义，活动装配在打开产品资源前确定性初始化或校验同一组合的控制状态。


### 第 2 项装配终态

5. **证据精确失效**：Git 提交、文档、外层打包和无关模块变化不能充当内核身份；只有真实直接依赖变化才重验，既有证据通过可审计等价映射保留。
6. **性能不得退化**：边界默认在 Go 单体内直接调用；不引入无依据的进程、网络、序列化、轮询、复制、常驻组件、通用插件或长期双写。
7. **一次收口**：统一迁移运行时、持久化、装配、发布身份、验收身份、直接说明和测试；不得只增加接口、改名或永久保留兼容双轨。
8. **安全边界不降级**：保留现有权限、冲突、耐久、备份恢复和产品不变量；不能用范围缩减、重新跑分或用户接受风险代替等价性证明。
9. **Git 权限不扩张**：执行者不得暂存、提交、改写历史或推送；提交只由持续调度提示词授权的协调者在独立复核后执行。

## 六、调度、验证与回退

- 协调者依据本文依赖顺序、未完成项和最新证据，按[“持续协调项目推进”](../workbench/development-workbench.md#持续协调项目推进)选择当前价值最高的一条问题链。工作包必须说明基线、负责边界、不做什么、完成证明和安全回退点；不得跨越未成立的前置边界。
- 开发期间只运行覆盖真实变化的最小充分验证；相同组件和直接依赖复用有效检查点，只重跑失效部分。不得反复准备环境或以数小时正式基准补偿身份、装配或等价性缺陷。
- 状态迁移和候选准备必须幂等且可从最近有效检查点恢复；重复执行不得重复写入、改变身份或破坏当前能力。
- V0 与 V1 分别以自身冻结输入对迁移前后入口做差分验证，覆盖输出、资产与派生副作用、冲突、失败恢复、质量、时效、资源、身份映射和状态；其他有效候选采用同一规则。直接依赖未变的证据以等价映射保留，无法证明等价即为迁移失败，不得通过重新优化内核或接受退化关闭。
- 每个阶段在新边界验证前保持旧活动路径不变；候选失败即丢弃。权威状态切换前必须完成可恢复备份和新状态校验，回退时恢复唯一写入权并验证已接受更新完整。
- 终态在同一最终组合上完成全量自动测试、构建、架构不变量、行为等价、状态迁移与回退、故障隔离、备份恢复、冷启动和必要性能验证，并以架构总纲为唯一判据进行一次对抗式复审。

## 七、结束条件

- [x] 架构总纲中的职责、四类状态、契约、依赖、组合和生命周期均有唯一、可验证的实现落点，没有未归属状态或越权路径。
- [x] V0 正式基线已原样成为第一内核世代；V1 及其他有效候选已原样成为对应候选世代。迁移前后各自的输入输出、组织与检索语义、模型与索引、质量、时效、资源、退化行为、身份连续性、证据和晋升状态等价，未混入效果迭代。
- [x] 系统只由一个显式、可校验的组合清单装配；构造入口、接入适配或隐含默认值不能改变产品语义。
- [x] 当前能力持续服务时，候选可以按三类状态生命周期独立准备；基线、增量追平、晋升、观察和可追平回退均成立，失败不污染当前能力。
- [x] 向量模型、外部智能能力、组织、检索、完整内核、派生存储、权威持久化和接入实现均具备与自身状态相符的无损替换边界。
- [x] 长期资产与最小控制状态只由权威基座管理；全部写入经过唯一权威，并发冲突显式，接入、内核、模型和存储没有旁路写权。
- [x] 组件、组合、环境、观察者和 Git 来源身份相互独立；证据只因真实直接依赖变化而失效，无关项目变化不触发内核重测。
- [x] 现有资产、控制状态、派生状态、有效检查点和证据已无损迁移；等价映射可审计，备份恢复、迁移回滚及晋升回退均不丢失更新。
- [x] 旧装配、隐式行为模式、全仓提交绑定和同义双轨已删除；未遗留通用插件、微服务、长期双写、永久兼容或未来功能债务。
- [x] 正常请求没有新增非必要开销；全部必要测试、构建和冷启动通过，对抗式复审不再发现与架构总纲的真实偏差。
- [x] 当前产品能力、安全边界和用户数据未受影响，任务状态与最终证据一致。

只有全部条件在同一最终组合上真实成立，才能将任务标记为完成。发现内核效果差异、证据无法等价映射或资产风险时，必须回到安全基线继续修复。
