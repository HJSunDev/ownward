# 信息可用时效与按需处理

## 一、需求梳理

保留智能体主动构建记忆的核心能力，同时满足不同使用场景对信息存入后可用速度及取用响应速度的需求。结合用户任务与数据特征，识别哪些场景能够以更少的处理快速满足需求，哪些场景需要深入组织、多轮取证，并具有可接受的等待空间。快速处理必须满足对应场景的质量要求，并与深度处理能力协同，避免所有任务承担相同的时间与调用成本。用户只需表达需求，无须理解或手动选择内部机制；系统承担处理方式的选择与衔接，持续兼顾质量、等待时间和使用成本。

## 二、产品设计

**同一入口、同一份权威数据，提供快速与深度两条处理路径。** 快速路径满足无需完整组织或多轮取证即可完成的需求；深度路径保留原有能力，可直接进入，不以先试快速路径为前提。

### 存入：先可用，再完善

```text
原文 → 可靠保存＋必要索引 ┬→ 快速路径：直接读取、基础查找
                         └→ 原有组织路径：生成摘要、证据单元、跨资料关系
```

“已保存”只确认可靠保存；快速路径提供实际读取和查找能力，不只是提前返回回执。原有组织继续服务深度使用，不因快速交付而取消、降低质量或重新启动；当前需求不依赖的组织工作不成为等待条件。

### 取用：能完成就结束，有缺口再深入

```text
用户需求 ┬→ 明确来源或有限依据足以完成：快速读取、检索 → 满足需求即交付
         └→ 需要综合、消歧或核对变化：直接进入原有深度路径
快速处理中发现证据缺口 → 携带有效材料接入深度路径
```

例如，“取回刚存的合同”可直接读取；“比较多份合同的责任差异”直接深度取证。选择依据是任务所需证据、时效与冲突，不是文字长短或命中数量；无法确认适用快速路径时保留深度处理。语义判断复用外部智能当前任务过程，不新增独立AI分流调用；切换时复用有效材料，不重复取证。

### 质量与成本边界

- 本次范围是新增快速路径及其与原有深度路径的必要衔接；同等条件下，不得降低深度路径的质量，也不得因分流、衔接或资源竞争增加其等待时间。深度路径自身的持续提速另行迭代，不作为本次完成前提。
- 快速交付必须满足当前需求；未完成组织或未搜到，不能当成信息不存在，命中资料也不等于依据完整。
- 更正、权限与遗忘沿用既有约束，不因走短路径或延后组织而失效；失效的旧理解不能继续作为有效依据。
- 同等条件下验证快速完成、直接深度处理及快速转深度三类场景，包括新增更正、冲突和资料未组织完整的情况。快速路径须有真实时效收益，深度路径须保持质量和等待水平；分流、衔接、后台、重试和存储成本全部计入。

## 三、架构设计

**快慢是同一体系内的执行路径，不是两套内核、记忆或质量标准。** 复用权威基座、存储和检索，主要通过省去不必要的模型阶段与等待提速。

### 分层与接入

| 部分 | 职责与改动 |
| --- | --- |
| 外部智能体 | 在已有任务理解中决定直接取用或深度处理；不确定时保留深度路径，不增设模型分流调用。 |
| 信息使用层 | 增加快速取证与接续入口；原深度入口及其模型、提示词、取证预算保持不变。 |
| 统一契约与内核 | 写入增加可选的“延后组织准备”；读取和搜索复用原接口、同一授权与更正交付，原调用默认行为不变。 |
| 权威存储 | 同一事务提交原文、基础索引、明确关系、待组织任务和回执；不建立第二份成功状态或快慢数据副本。 |
| 正式宿主适配 | 承担路径选择、组织接续、材料与用量恢复；Codex适配通过App Server运行独立组织任务，Hook只通知和唤醒适配器。随正式接入包交付，不以测试运行器代替真实接入。 |

### 存入：可靠提交与智能组织分离

```text
原文、索引、明确关系与待办原子提交
  ├─ 默认调用 → 原有组织准备 → 返回
  └─ 延后调用 → 返回可读原文与组织待办 → 宿主接续原有组织
```

延后调用不执行返回前的 `prepareStoredWork`；本地向量、候选准备及AI组织在接续时沿用原机制。返回资产身份、修订、直接读取入口及组织状态，基础可读不依赖组织成功。资料未组织完整时仍可按原文查找，不以旧摘要或旧向量冒充当前内容；所需组织未完成只影响依赖它的任务。

沿用 `semantic_jobs`，为异步领取补充绑定体系、主体、资产修订、世代的有期限执行凭据；前后台组织共用领取与提交约束，同一工作只允许一个有效持有者，续期、释放与结果提交均校验凭据及权限。旧接入保留默认行为，不与新执行器混领同一工作；异步能力须经接入协商启用。中断可重新领取，有效已完成部分复用，发布继续校验输入版本并原子更新结果与待办。过期执行者不能覆盖新结果；远端调用结果不明时如实计入重试成本，不承诺外部调用绝不重复。

宿主在写入后和恢复接入时承接待办，不要求用户手工启动整理；待办返回不等于工作已启动。只有经验证能够脱离当前响应接续工作的宿主才启用延后写入；不支持时保留原写入行为，不以阻塞用户下一次请求补做后台任务。宿主关闭时待办持久保留，重新接入恢复；无执行资源时明确保持待处理，不假装仍在运行。

### 宿主执行：独立任务与资源准入

**组织执行者是宿主侧适配器管理的智能体任务；内核不持有模型或代行推理。** Codex适配使用App Server的任务启动、中断与恢复接口，组织任务与用户对话分开；沿用宿主已验证的组织能力、模型档位、规则与预算，不能以换模型冒充路径提速。组织任务仅取得当前主体获准使用的材料和必要组织工具，不继承主对话的无关内容、管理权限或通用执行工具。Hook只通知适配器，不承担智能执行。

| 时机 | 执行动作 |
| --- | --- |
| 写入前 | 核对执行器可用、授权及资源资格；不具备条件时沿用原写入方式，不返回虚假的后台运行状态。 |
| 原文提交后 | 先交付可读取原文；适配器领取同一内核待办，在独立任务中执行原有组织。待办以内核持久记录为准，不另建业务队列。 |
| 接入、任务结束或资源恢复 | 通过内核待办的有界等待与拉取持续取件，先注册等待再复查待办，不能仅依赖Hook通知或重连补领。暂时失败沿用原恢复预算，持续失败保留明确状态并让其他待办继续；不忙轮询或无限重试。 |
| 执行与提交 | 按领取凭据续期，工具调用和发布继续核对权限、版本、世代；同一工作不被前后台重复执行。宿主仅保存任务身份、恢复位置和用量，成功以内核接受结果为准。 |
| 中断或退出 | 停止派发、中断所属组织任务并回收所属子进程；内核保留未完成待办。恢复前核对当前权威、授权和全部输入依据；已完成不重做，已失效不重交。 |

**后台准入不等于提高并发。** 保持原前台资源配额和总预算；同一模型资源池、同一宿主机器和同一内核的后台用量分别汇总，包含执行器进程及工作材料，不能靠增加接入数扩大预算。第一版每个接入至多一个后台组织任务，该限制不替代总量准入。共享不可抢占通道、限流关系不明或本机无余量时不自主派发；另一进程、另一线程或“空闲启动”不等于隔离。前台依赖同一待办时提升原任务优先级、复用其结果，不重开组织；等待如实计入。

恢复状态与材料复用沿用[信息变化契约](../modules/information-change/README.md#宿主如何沿用材料)。含失效材料的旧模型上下文不得直接恢复，须移除失效材料及依赖结论、保留其他有效进展；宿主不能安全剔除时，以核对后的材料恢复新上下文。适配器控制的工作副本遵守既有撤销、遗忘与有界回收要求，不积累为另一套长期记忆。

适配器随接入启动和退出，执行器按需启动，不新增定时任务、额外模型套餐要求或内核常驻智能体。共享资源条件下仍提供快速取用，延后写入按上述能力条件启用；这种降级不能计作后台功能通过验收。

### 取用：共享检索能力，缩短智能处理路径

```text
明确来源、局部事实 → 直接读取或原有搜索 → 外部智能使用依据并交付
综合判断或证据范围不明 → 原深度流程
快速处理中出现缺口 → 带着有效材料和实际用量接入深度流程
```

快速路径省去独立 `FRAME` 调用和固定前三条初始读取，在宿主已有任务中按需取证；不强制关闭已就绪的向量和图，以免用降低召回质量换取微小提速。原有搜索根据可用组织提供候选，检索摘要只作线索，事实结论依据实际读取的原文与必要说明。全量、当前状态、冲突等不能由一次局部命中证明；未搜到或组织待完成不代表信息不存在。

接续状态统一保存原始需求、已有需求解释、实际读取材料及 `basis`、待读说明和累计用量；语义笔记与原文分开。深度入口接受该状态，不重置预算或重复初始读取；缺少需求准备时只补原有准备步骤，材料失效时按原核对规则重取。快速与深度交付沿用同一结果契约和原样呈现规则，代码不按置信度、命中数或答案措辞判断完成。

当前需求确实依赖组织时，由智能体定向请求对应资料的原有组织工作；已有任务共用有效结果，不能跨主体复用不可访问的候选或材料。快速试探耗尽预算、再把未完成结果当作达标深度结果的行为不允许；该分流若不能保住原质量与完整等待，不得启用。

### 不拖慢原路径的边界

- 原深度调用不经过快速试探或新增模型判断；快速接入独立启停。停用后恢复原调用，资产、有效派生与待办继续保留，无须重新导入。
- 延后组织与前台需求复用同一待办；资源准入遵循上节，有前台工作时停止派发无关后台任务，不以提高并发或牺牲深度响应兑现后台承诺。
- 更正、授权撤销、遗忘和迁移资格仍由权威基座即时约束；延后组织及恢复旧任务不能绕过。执行凭据不授予额外的数据权限。

### 交付验证

先用正式宿主证明保存后可实际读取、用户可继续其他请求、组织可接续及中断可恢复，并验证通知遗漏、失败任务不阻塞后续工作、领取竞争与撤销后恢复；不满足宿主条件时不能宣布本需求全部完成。再固定同等资料、模型、预算与负载，比较快速完成、直接深度、快速转深度，覆盖新旧资料混用、更正、冲突、误分流及多个接入共享资源的竞争。

验收同时要求快速场景有端到端收益、原深度质量和等待不退化、全部调用及持续成本可接受；不能靠提前回执、漏读或将成本移到后台过关。必要验证通过后同步正式产品、架构、契约与流程文档，并按既有能力世代规则启用；实现前不改写正式现状。

机制依据：[最小闭环验证](../../.tmp/information-availability-preflight-20260919/host-probe-output.txt)使用真实宿主与内核、受控模型响应，支持执行机制可行性，不替代真实模型质量与性能验收；宿主接口参见[App Server](https://developers.openai.com/zh-Hans/docs/app-server)与[Hooks](https://developers.openai.com/zh-Hans/docs/hooks)。
