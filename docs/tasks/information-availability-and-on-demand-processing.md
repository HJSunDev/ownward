# 信息可用时效与按需处理

## 一、需求梳理

保留智能体主动构建记忆的核心能力，同时满足不同使用场景对信息存入后可用速度及取用响应速度的需求。结合用户任务与数据特征，识别哪些场景能够以更少的处理快速满足需求，哪些场景需要深入组织、多轮取证，并具有可接受的等待空间。快速处理必须满足对应场景的质量要求，并与深度处理能力协同，避免所有任务承担相同的时间与调用成本。用户只需表达需求，无须理解或手动选择内部机制；系统承担处理方式的选择与衔接，持续兼顾质量、等待时间和使用成本。

## 二、产品设计

**同一入口、同一份权威数据，提供快速与深度两条处理路径。** 快速路径满足无需完整组织或多轮取证即可完成的需求；深度路径保留原有能力，可直接进入，不以先试快速路径为前提。

### 存入：先可用，再完善

```text
原文 → 可靠保存＋必要索引 ┬→ 快速路径：直接读取、基础查找
                         └→ 原有组织路径：生成摘要、证据单元、跨资料关系
```

“已保存”只确认可靠保存；快速路径提供实际读取和查找能力，不只是提前返回回执。原有组织继续服务深度使用，不因快速交付而取消、降低质量或重新启动；当前需求不依赖的组织工作不成为等待条件。

### 取用：能完成就结束，有缺口再深入

```text
用户需求 ┬→ 明确来源或有限依据足以完成：快速读取、检索 → 满足需求即交付
         └→ 需要综合、消歧或核对变化：直接进入原有深度路径
快速处理中发现证据缺口 → 携带有效材料接入深度路径
```

例如，“取回刚存的合同”可直接读取；“比较多份合同的责任差异”直接深度取证。选择依据是任务所需证据、时效与冲突，不是文字长短或命中数量；无法确认适用快速路径时保留深度处理。语义判断复用外部智能当前任务过程，不新增独立AI分流调用；切换时复用有效材料，不重复取证。

### 质量与成本边界

- 本次范围是新增快速路径及其与原有深度路径的必要衔接；同等条件下，不得降低深度路径的质量，也不得因分流、衔接或资源竞争增加其等待时间。深度路径自身的持续提速另行迭代，不作为本次完成前提。
- 快速交付必须满足当前需求；未完成组织或未搜到，不能当成信息不存在，命中资料也不等于依据完整。
- 更正、权限与遗忘沿用既有约束，不因走短路径或延后组织而失效；失效的旧理解不能继续作为有效依据。
- 同等条件下验证快速完成、直接深度处理及快速转深度三类场景，包括新增更正、冲突和资料未组织完整的情况。快速路径须有真实时效收益，深度路径须保持质量和等待水平；分流、衔接、后台、重试和存储成本全部计入。

## 三、架构设计

**快慢是同一体系内的执行路径，不是两套内核、记忆或质量标准。** 复用权威基座、存储和检索，主要通过省去不必要的模型阶段与等待提速。快通道＝确定性快存／快查／快接续；语义组织仍由外部智能经统一契约完成；**产品核心不拥有执行机构**。

### 判定与场景边界

需求可行，边界如实——并非所有场景都快：

| 场景 | 数据特征 | 路径 |
| --- | --- | --- |
| 取回已知目标 | 有身份/明确指向 | 按 ID 直读，零额外 AI 轮次 |
| 有限依据即可完成的查找 | 词法/名称/显式关系可命中；向量仅短文本或已组织后可用 | 单轮检索+读取 |
| 新存即用 | 原文未组织但可读、词法可查 | 原文直读+基础检索 |
| 跨资料综合、消歧、多跳关系 | 依赖组织状态与多轮取证 | 深度路径（可接受等待空间） |

### 分层与接入

| 部分 | 职责与改动 |
| --- | --- |
| 外部智能体 | 在已有任务理解中决定直接取用或深度处理；不确定时保留深度路径，不增设模型分流调用。 |
| 信息使用层 | 增加快速取证与接续入口；原深度入口及其模型、提示词、取证预算保持不变。 |
| 统一契约与内核 | 写入增加可选的“延后组织准备”；读取和搜索复用原接口、同一授权与更正交付；组织状态机器可读；待组织信号可枚举（见“硬条件”）。 |
| 权威存储 | 同一事务提交原文、基础索引、明确关系、待组织任务和回执；不建立第二份成功状态或快慢数据副本。 |

### 存入：返回前不等组织

```text
原文、索引、明确关系与待办原子提交
  ├─ 快存（deferred 语义）→ 立即返回可读原文与组织待办
  └─ 默认路径（等组织）→ 兼容形态保留
```

**快存＝“返回前不等组织”（deferred 语义），交互与批量同一语义。** 返回资产身份、修订、直接读取入口及组织状态；基础可读不依赖组织成功；资料未组织完整时仍可按原文查找，不以旧摘要或旧向量冒充当前内容；所需组织未完成只影响依赖它的任务。

**快存不得以执行器就绪为门。** 启用由客户端能力与系统显式选择决定，与任何执行器是否就绪无关；执行器就绪只影响“是否有人提前组织”，不影响保存速度。无执行器时组织保持显式 pending；默认“等组织”不得成为无执行器时的静默回退。长文（>320B）组织前无向量为显式边界；短文本由本地模型直接生成向量。

沿用 `semantic_jobs`，为异步领取补充绑定体系、主体、资产修订、世代的有期限执行凭据；同一工作只允许一个有效持有者，续期、释放与结果提交均校验凭据及权限。中断可重新领取，有效已完成部分复用，发布继续校验输入版本并原子更新结果与待办。过期执行者不能覆盖新结果；远端调用结果不明时如实计入重试成本，不承诺外部调用绝不重复。

### 组织：外部智能经统一契约完成

**内核不持有模型或代行推理；产品不交付任何执行器实现、不建常驻通道、不承担调度。** 组织由已连接的外部智能完成，三种合法形态：

1. **按需**：`ownward_organize` 薄化保留——返回“租约 + 工作材料 + 期望提交结构”；已有持有者时返回持有状态与接续信息；不唤醒后台；调用者自行组织后经同一提交契约提交；互斥与权限校验保留；暴露条件为“调用者可组织”。
2. **机会式（回执驱动）**：保存方对回执的合法处置只有三条——委托 worker／会话后续机会完成（**不得在返回用户结果前同步组织**）／保留为可见待办按需完成。
3. **可选 worker**：宿主适配器或部署方可按同一契约运行 worker（opt-in），不随聊天宿主更换而变化；`background=true`／单后台持有者保留为可选执行者声明的并发约束。

恢复状态与材料复用沿用[信息变化契约](../modules/information-change/README.md#宿主如何沿用材料)。含失效材料的旧模型上下文不得直接恢复，须移除失效材料及依赖结论、保留其他有效进展；执行者不能安全剔除时，以核对后的材料恢复新上下文。执行者控制的工作副本遵守既有撤销、遗忘与有界回收要求，不积累为另一套长期记忆。

### 硬条件

- 搜索/交付面暴露**逐资产可枚举的待组织信号**：ID、名称/显式关系、确定性首段或词法摘要；有界、分页、当前主体范围、按确定性相关性排序；复用现有词汇（`pending/ready/uncertain` + `required_action`），不造平行状态词。
- **深度路径不得把“无结果”当“无信息”**：存在未组织资产时必须触发组织或显式返回部分覆盖。

### 取用：共享检索能力，缩短智能处理路径

```text
明确来源、局部事实 → 直接读取或原有搜索 → 外部智能使用依据并交付
综合判断或证据范围不明 → 原深度流程
快速处理中出现缺口 → 带着有效材料和实际用量接入深度流程
```

快速路径省去独立 `FRAME` 调用和固定前三条初始读取，在宿主已有任务中按需取证；不强制关闭已就绪的向量和图，以免用降低召回质量换取微小提速。原有搜索根据可用组织提供候选，检索摘要只作线索，事实结论依据实际读取的原文与必要说明。全量、当前状态、冲突等不能由一次局部命中证明；未搜到或组织待完成不代表信息不存在。

接续状态统一保存原始需求、已有需求解释、实际读取材料及 `basis`、待读说明和累计用量；语义笔记与原文分开。深度入口接受该状态，不重置预算或重复初始读取；缺少需求准备时只补原有准备步骤，材料失效时按原核对规则重取。快速与深度交付沿用同一结果契约和原样呈现规则，代码不按置信度、命中数或答案措辞判断完成。

当前需求确实依赖组织时，由智能体经 `ownward_organize` 定向请求对应资料的组织工作；已有任务共用有效结果，不能跨主体复用不可访问的候选或材料。快速试探耗尽预算、再把未完成结果当作达标深度结果的行为不允许；该分流若不能保住原质量与完整等待，不得启用。

### 不拖慢原路径的边界

- 原深度调用不经过快速试探或新增模型判断；快速接入独立启停。停用后恢复原调用，资产、有效派生与待办继续保留，无须重新导入。
- 快存与前台需求复用同一待办；资源纪律沿用原前台预算与准入，不靠提高并发兑现快通道，后台组织不增加常驻并发。
- 更正、授权撤销、遗忘和迁移资格仍由权威基座即时约束；延后组织及恢复旧任务不能绕过。执行凭据不授予额外的数据权限。

### 版本处置与保留/删除清单

| 版本 | 处置 |
| --- | --- |
| 变更前（宿主适配器后台执行） | 机制留宿主适配器侧、opt-in；HOST-01 注册/校验语义保留；不作产品能力前提。 |
| 变更后（产品自有常驻执行通道） | 从产品核心删除（不建）；执行者契约保留为通用能力接口。 |

- 保留：deferred-v1 契约、claim/renew/release/wait/submit、快速取用与接续（单元三）、HOST-01 注册/校验、`background=true` 可选并发约束。
- 删除：产品自有常驻通道与后台调度语义；`organization_host.go` 后台循环、机器锁、前台跟踪、预算 journal 归宿主适配器实现，不作产品前提。

### 交付验证

先证明保存后可实际读取、用户可继续其他请求、组织可接续及中断可恢复；验证通知遗漏、失败任务不阻塞后续工作、领取竞争与撤销后恢复。再固定同等资料、模型、预算与负载，比较快速完成、直接深度、快速转深度，覆盖新旧资料混用、更正、冲突、误分流及多个接入共享资源的竞争。组织链验收＝回执 → 按需/机会式组织 → 依赖取用，经任意已连接智能体完成，不要求特定执行者。

验收同时要求快速场景有端到端收益、原深度质量和等待不退化、全部调用及持续成本可接受；不能靠提前回执、漏读或将成本移到后台过关。必要验证通过后同步正式产品、架构、契约与流程文档，并按既有能力世代规则启用；实现前不改写正式现状。

机制依据：[最小闭环验证](../../.tmp/information-availability-preflight-20260919/host-probe-output.txt)支持领取与接续机制可行性，不替代真实模型质量与性能验收。
