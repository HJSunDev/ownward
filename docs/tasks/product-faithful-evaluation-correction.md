# 产品忠实评测纠偏（临时任务）

状态：已完成。主动检索适配器、失败关闭、非盲校准与 V0/V1/V2 同尺重比均已成立；V2 是后续唯一候选基线，尚未晋升或运行正式 LongMemEval-S。

## 根本错误

评测观察器越过产品职责边界，代替外部智能体完成了检索决策；项目验证了评测流程自身的一致性，却没有验证它是否忠实于产品。

## 目标

恢复符合产品与架构职责的主动检索评测，精确纠正受旧适配器影响的证据，在同一评测身份下重新比较 V0、V1、V2，并依据新证据确定后续唯一内核基线。

## 固定边界

- V0、V1、V2 保持独立冻结；不得在纠偏期间继续优化、晋升或删除任一内核。
- 官方 LongMemEval-S 数据、问题、答案隔离、评分语义和裁判保持不变；不得读取 Gold ID、答案或题型捷径。
- 比较时除内核及其直接依赖外，模型、推理强度、提示词、工具、资源预算、评分器、环境和计时边界必须相同。
- 只按直接依赖失效证据；不依赖旧适配器的资产、状态、恢复、内部正确性与性能证据继续有效。
- 不改写 Git 历史。错误结论通过后续提交纠正并保留审计链。

## 必须完成

1. 建立 V0、V1、V2 证据影响清单，逐项标明“继续有效 / 仅证明旧被动模式 / 失效待重测”及直接依赖；原始结果保留，不得继续冒充产品级证明。
2. 修正 V0、V1 版本档案和 V2 任务状态。提交 `be8e7b9` 记录的 25 题结果改判为评测流程无效，不得继续表述为 V2 内核失败；V2 尚未晋升，不创建虚假版本档案。
3. 在验收体系写入最高级不变量：评测适配器可以约束资源，但不得替代外部智能体承担主动检索、证据积累、方向调整、停止判断和结果组织；违反该边界的结果只能作为诊断，不能证明产品质量、内核根因或晋升资格。
4. 将 LongMemEval-S 产品评测口径冻结为 `external-agent-progressive`：问题交给外部智能体，智能体自主选择 Ownward 搜索、导航、证据检索与读取工具，依据观察结果继续、调整或停止，最终独立回答。宿主只执行工具和预算约束，不预选证据或决定读取顺序。
5. 从盲测和正式验收活动路径移除固定预取、固定八条证据交付及 Reader 禁用工具的行为。旧路径若保留，只能明确命名为被动排序诊断模式，不得进入产品验收、内核归因或晋升判断。
6. 增加失败关闭检查：产品评测若未向智能体暴露工具、禁止工具调用、启用宿主固定预取，或未保留多步主动检索能力，盲测与正式入口必须拒绝运行。
7. 建立事故记录，说明职责越界、影响范围、证据失效原则和修复结果；事故结论同步到验收权威与 LongMemEval-S 协议，不重复改写已经清楚的产品和架构职责。
8. 先用少量非盲材料校准主动检索闭环、预算、恢复、归因和成本；校准只验证评测可靠性，不形成候选结论。
9. 校准通过后，使用同一冻结评测身份重新比较 V0、V1、V2。现有高质量题目可继续作为材料，旧执行结果不得复用；只运行选择最佳内核所需的最小充分比较，不以三次正式 500 题代替筛选。
10. 依据新证据确定唯一后续基线：V0 最好则继续使用 V0；V1 或 V2 更好则保留其真实收益；只有被证明有害或无效的候选与改动才淘汰，不因观察器错误整体回退项目。

## 结束条件

- V0、V1、V2 的旧证据均完成直接依赖分类，权威文档不再把旧被动结果表述为产品能力证明。
- 主动检索评测真实执行产品定义的外部智能体闭环，资源受控且无答案泄漏；被动路径无法误入盲测或正式验收。
- 评测流程、归因、恢复、预算和失败关闭通过独立非盲校准。
- V0、V1、V2 已在同一新评测身份下完成最小充分比较，最佳内核及其有效收益、退化与淘汰范围均有可复核证据。
- 事故记录、验收不变量、协议、版本档案和 V2 任务状态一致；Git 历史未被改写。
- 未在纠偏完成前继续内核优化、运行正式 500 题或晋升 V2。

## 结果

主动检索干净校准为 `4/4`，零重试、中断和限流；随后三版在同一 20 题非盲集合上均为 `20/20`。V2 的累计墙钟 `261.608 s`、检索均值 `90.55 ms`、P95 `126 ms`、数据量 `730,994 B` 均为最低，因此选择冻结 V2 作为后续唯一候选基线。完整身份与报告摘要见[机器证据](../../benchmarks/acceptance/suite/iteration/evaluation-correction/product-faithful-comparison.json)。本结果不构成正式分数或晋升。
