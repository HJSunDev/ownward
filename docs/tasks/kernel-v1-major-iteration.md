## 第五方向业务问题与根因

- 场景：用户或接入智能体一次沉淀一批信息时，批量调用应保持逐项身份和耐久语义，但不应把同一批确认退化为每项两次串行磁盘屏障；后台重建的不可见世代也不应在每条派生记录后强制落盘。
- V0 表象：500 题共创建 `23,867` 项资产、形成 `1,498` 个语义批次；产品创建阶段累计 `2,750.038 s`，平均 `5.500 s/题`、p95 `9.593 s/题`。语义/Reader/裁判分别累计 `36,992.627 s`、`5,295.681 s`、`3,562.214 s`，属于模型与外部评测成本，不计入本根因；逐题隔离、审计和测试调度同样排除。
- 机械根因：公开 `CreateBatch` 先逐项调用权威资产 `Create`，再逐项写入待处理派生记录；每项写入都独立 `fsync`。完整派生世代已经与当前状态隔离，却仍逐记录 `fsync`，直到最后才封存和原子切换。批量和世代事务边界没有传递到持久层，造成可消除的串行耐久等待。
- 负责方向：执行架构与状态维护。该根因不属于正文存储放大、模型推理、语义质量或检索质量，前四方向只作为交叉保护。

## 存储方向架构与兼容边界

- 权威资产仍是唯一事实来源。活动恢复日志原子压实为每项当前资产一个快照；稳定 ID、当前 revision、正文、明确语义和来源不变。产品没有声明历史版本能力，因此旧完整文本版本不是永久资产；显式备份仍能完整恢复当前权威资产。
- 派生格式升级为 `ownward.derived/v4`：语义工作只持久化资产/候选 ID、revision、相似度、上一分析和工作身份；公开工作在读取时按原顺序从权威资产无损重建。
- 已接受提交只持久化能力身份、状态、接受时间和规范提交摘要；当前分析保留一份，重复提交通过摘要保持幂等，不再复制第二份完整分析。
- 松散 v3 状态首次打开时自动转换并原子压实；已封存世代继续沿现有完整重建、校验和原子切换路径迁移。没有双写或永久旧格式写入路径。
- 维护只保留每资产一个当前派生记录；反复维护结果字节稳定。更新失效、关闭重开、向量恢复、世代重建、备份和空白恢复均继续成立。
- 按需证据身份直接对已经验证的 UTF‑8 正文字节取摘要，删除 `string → []rune → string` 的等价往返分配；证据 ID 字节和公开合同不变，确保已关闭检索链在当前候选上满足相对成本保护。

## 执行状态终态架构

- `CreateBatch` 先逐项完成输入、关系和身份校验，再以一个有界权威日志批次写入；只有整批日志完成一次耐久屏障后才发布内存状态。输入级错误仍逐项返回，已确认结果在返回前全部持久化。
- 新资产的待处理派生状态保持原有候选顺序和语义工作身份：内核用隔离的批内索引合并既有与本批语义候选，校验全部记录后由 `PutBatch` 一次持久化，再发布运行索引，避免未落盘状态对并发读取可见。
- 完整派生世代在独立、不可见目录中顺序构建，不再逐记录落盘；封存时统一 `fsync`、校验记录与资产快照、写入清单，最后原子切换当前指针。失败或竞争继续丢弃候选世代并保留上一代。
- 单项创建、更新和已发布世代的增量写入仍保持逐项耐久；日志格式、稳定身份、迁移、备份和公开合同均未改变，不存在双写或永久兼容路径。
