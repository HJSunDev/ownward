## 当前业务问题

- 场景：外部智能体沉淀长会话后完成语义组织，再用不同措辞或跨语言查询召回相关记忆。
- 预期：完整正文继续作为唯一权威事实；语义提交应形成可持久、可恢复且能被公开搜索消费的紧凑检索表示。
- 实际：V0 把整段长正文送入本地嵌入运行时，超过 512 物理批次后失败；后续语义提交只保存分析，不补建向量，因此全部检索退化为词法通道。
- 原因链：长正文直接嵌入 → 运行时拒绝 → 派生记录无向量 → 语义提交未恢复表示 → 查询只有词法候选 → 116 项首次缺口表现为目标证据未返回。
- 已达状态：长正文不再进入受限原始嵌入批次；完成的语义分析按稳定字段无损规范化，在确定性总字节边界内分批嵌入并聚合为每资产唯一向量。接受后的同一提交可在暂时失败后幂等恢复；公开 search、关闭重开和批量语义提交均消费同一表示。

## 最终架构与影响

- 权威正文、稳定 ID、revision、来源、语义工作与提交合同不变；没有复制事实、引入子资产、修改持久格式或增加第二套索引。
- 创建阶段只把确定不会超过本地 512-token 物理批次的短输入送入嵌入通道；批量调用同时限制单项和整批字节。长资产保持 `pending`，等待既有外部语义能力完成分析。
- 语义提交把 summary、topics、cues、inferred contexts 与 relation evidence 全部纳入检索表示；超界只按 UTF‑8 边界确定性拆分，不截断字段。每个嵌入请求受同一总字节上限约束，分块向量归一聚合后只持久化一个来源向量。
- 单项与批量提交共用恢复路径；已接受但向量暂时失败的相同提交可安全重试，冲突提交仍被拒绝。来源更新继续由 revision 使旧表示失效，关闭重开直接复用当前派生记录。
- 公开 `ownward_search` 无需新工具或适配器分支即可消费恢复后的 semantic 信号；上一 `ownward_evidence_search/read` 两阶段细粒度证据链保持原样。
