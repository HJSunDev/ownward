## 当前业务问题

- 场景：外部智能体回答跨会话、时间或更新问题，需要同时取得多个来源事实。
- 预期：内核在固定检索预算内交付完整、可追溯且可组合的必要证据。
- 实际：V0 以完整会话作为不可分检索单元；119 个错误即使已找全目标会话，其必要正文自身仍无法同时进入 24,000 字符上下文，最后一项或多项证据因预算被截断。
- 原因链：会话级权威资产同时承担检索单元 → 单元过粗 → 必要证据总量超过上下文 → 已命中的目标证据无法被读取 → 回答失败。
- 已达状态：原始资产仍是唯一事实权威；资产级检索命中后，调用方按当前问题在该来源内取得源绑定、可重建的证据引用，并在同一预算内组合读取必要原文。冻结视图的预算召回从 `0.3889` 升至 `1.0000`，错误率从 `0.6111` 降至 `0`。

## 最终架构与影响

- 权威与组织层不变：长期资产继续保存完整正文、稳定 ID、来源和 revision；创建、更新、语义提交与重建仍只处理每项权威资产的一份正文、一个派生记录和一个来源向量。机器证据逐函数证明这些路径与 V0 等价。
- 检索分两阶段：既有 `ownward_search` 的资产级排序、关系扩展和返回合同逐字保持；只有已命中的长资产需要局部原文时，才调用 `ownward_evidence_search`，按当前查询对真实正文的自然分区做一次性词法相关性排序。查询词只编译一次，内部选段直接复用已验证区间，避免对每段重复扫描来源前缀。
- 证据不持久化：只为最终选中的区间生成自包含引用，绑定 `source_id + source_revision + rune/byte range + content digest`；`ownward_evidence_read` 每次从当前权威资产校验并解析。它不是子资产，不复制正文、不建向量、不进入派生存储或全局索引。
- 生命周期：来源更新后旧引用因 revision/摘要不符立即失效；进程重启后引用无需旁表即可重建。`ownward_read` 仍读取完整资产，调用方可按任务需要选择完整或局部原文。
- LongMemEval-S `retrieve` 已只经公开能力接通该流程：每个资产线索先尝试证据检索，短资产保持完整读取，长资产按来源读取至多三条证据；全部来源合计仍受原 8 条、24,000 字符门槛约束。检索留痕分别保留资产 ID、证据引用 ID、完整/局部读取模式和各阶段时延，不接触问题之外的答案、Gold、题型或评分信息。
- 受影响依赖仅为新增证据领域值、按需分区/相关性选择、核心与 MCP 的两个只读入口、LongMemEval-S 检索适配及快速候选的规模保护；公开 CRUD、既有 search/navigate、组织/重建、v3 持久格式、V0 固定材料及正式验收状态均未改动。
