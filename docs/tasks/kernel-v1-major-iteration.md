## 当前业务问题与根因

- 场景：用户长期沉淀大量正文，语义能力需要取得当前资产及候选上下文；内核必须持久保留权威信息与可恢复状态，但不能把可重建上下文反复复制成长期成本。
- V0 表象：500 个问题隔离目录中的产品数据共 `8,652,582,167` 字节，其中权威资产日志 `261,996,462` 字节、派生日志 `8,390,585,705` 字节；基准另外保留的语义轨迹、分析与提交审计约 `4,724,195,023` 字节，不属于产品存储。
- 机械根因：23,867 个当前资产形成 47,734 条派生记录；`semantic_work` 占 `8,330,782,630` 字节，即派生日志的 `99.2873%`。每项待处理记录把当前资产及候选的完整权威正文复制一次，接受后又随完整工作和完整提交复制一次；这些正文与提交分析均可从权威资产和当前分析重建。
- 排除项：500 题逐题隔离、基准审计副本、模型调用输入和不可消除的当前权威正文均不冒充产品内核缺陷。正式正文总量 `248,978,442` 字符及 96.91M 语义输入 Token 只用于区分产品写入与基准执行成本。

## 最终架构与兼容边界

- 权威资产仍是唯一事实来源。活动恢复日志原子压实为每项当前资产一个快照；稳定 ID、当前 revision、正文、明确语义和来源不变。产品没有声明历史版本能力，因此旧完整文本版本不是永久资产；显式备份仍能完整恢复当前权威资产。
- 派生格式升级为 `ownward.derived/v4`：语义工作只持久化资产/候选 ID、revision、相似度、上一分析和工作身份；公开工作在读取时按原顺序从权威资产无损重建。
- 已接受提交只持久化能力身份、状态、接受时间和规范提交摘要；当前分析保留一份，重复提交通过摘要保持幂等，不再复制第二份完整分析。
- 松散 v3 状态首次打开时自动转换并原子压实；已封存世代继续沿现有完整重建、校验和原子切换路径迁移。没有双写或永久旧格式写入路径。
- 维护只保留每资产一个当前派生记录；反复维护结果字节稳定。更新失效、关闭重开、向量恢复、世代重建、备份和空白恢复均继续成立。
- 按需证据身份直接对已经验证的 UTF‑8 正文字节取摘要，删除 `string → []rune → string` 的等价往返分配；证据 ID 字节和公开合同不变，确保已关闭检索链在当前候选上满足相对成本保护。
