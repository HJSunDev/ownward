# 用户控制、跨地点访问与信息变化待办

建设属于用户、方便迁移、能被不同地点的授权智能体持续访问的信息体系，并使信息变化在后续使用中有效传递。相关依据见[产品增益方向](../research/personal-information-product-opportunities.md)与[跨设备接入分析](../architecture/product-capability-gap-analysis.md)，后续扩展见[未来能力登记](../product/future-capabilities.md)。

## 执行顺序

三个工作包分别负责用户控制、跨地点访问与迁移、信息变化；共享必要的基础，独立实现和验收。按以下顺序推进：

| 顺序 | 工作 | 完成后进入 |
| --- | --- | --- |
| 1 | 工作包一第4—5项：实现并验收授权、撤销和遗忘。 | 工作包二 |
| 2 | 工作包二第1—5项：完成跨地点访问与迁移的产品设计、专项审查、架构、实现与验收，复用工作包一的授权能力。 | 工作包三 |
| 3 | 工作包三第1—5项：完成信息变化的产品设计、专项审查、架构、实现与验收。 | 本任务关闭 |

工作包一已完成的前三项及部署位置无关性复核构成其实现依据，无需等待工作包二完整设计；未失效的审查和验证证据继续复用。

## 共同准备

- [x] **基础审查。** 核对资产存储、权威控制、版本保护、关联更新及本机接入，修复已确认缺陷；适用范围见下方审查结论。
- [x] **用户控制与信息变化的共享边界。** [用户控制架构](../modules/information-control/README.md#结构与共享边界)明确共同使用的权威基座、身份、资产版本、停止使用状态及有效性检查；跨地点与迁移的补充边界由工作包二第3项完成，信息变化的具体语义与宿主行为由工作包三设计。
- [x] **部署位置无关性复核。** 已修正所有者入口的本地限定，明确体系与主体身份独立于地址及目录，分清初始化、正常接续、管理凭据恢复与旧备份恢复；结论见下方工作包一专项审查。该项完成设计复核，不代表跨地点能力已经实现。

## 工作包一：用户掌控信息

目标：用户能够决定谁可以怎样使用信息，并撤销访问或遗忘指定信息。

1. [x] **产品设计。** [用户掌控信息](../product/information-control.md)定义使用过程、独立授权、撤销、遗忘和恢复边界；范围与完成标准已纳入[第一版交付定义](../delivery/first-version-delivery-definition.md#用户掌控信息)。
2. [x] **专项审查。** 已对照产品行为核查身份、调用入口、删除与恢复链路；保留、扩展及替换结论见下方专项审查。复用仍有效的共同审查证据，不把设计认可当作新增功能已通过验证。
3. [x] **架构设计。** [用户控制架构](../modules/information-control/README.md)明确授权执行、撤销生效、停止使用与派生清理，涵盖并发、恢复、旧工作及世代切换；核心职责已同步到架构总纲与存储架构。
4. [ ] **实现。** 完成接入者权限管理、信息遗忘和至少一种真实宿主的确认与原任务接续；搜索、读取、证据引用和派生重建不能继续暴露已遗忘内容，后台清理不等待外部模型或阻塞用户任务。
5. [ ] **验证与关闭。** 验证真实宿主的首次接入、普通连接发起管理、拒绝及恢复，连同权限隔离、撤销、遗忘、重启和回执接续；分别核对前台等待、清理与重建成本及未受影响任务的质量，确认原有功能和体验未退化，保存证据后关闭工作包一。

## 工作包二：跨地点访问与便捷迁移

目标：不同地点的授权智能体能够方便、稳定地使用同一份 Ownward；更换部署位置后，用户的信息和控制权完整保留，连接能够便捷接续。

1. [ ] **产品设计。** 明确首次接入、持续使用、断线恢复和迁移后的体验与完成标准，包括所支持部署的在线条件和维护责任；按易用性、持续可用性及成本确定交付范围。
2. [ ] **专项审查。** 核查本机连接限制、身份认证、所有者入口、备份恢复和唯一写入权，决定保留、修复或替换；本机已验证的安全与运行假设须按跨地点用途重新核对。
3. [ ] **架构设计与共享边界补充。** 复用已确定的身份、授权和所有者恢复边界，设计跨地点连接、认证传递、运行恢复及迁移时唯一权威的切换与接续；新增依赖按实际影响补审。将确定的范围与契约落实到产品、交付和架构文档。
4. [ ] **实现。** 工作包一验收后，复用其授权能力，完成所选部署形态的跨地点接入、运行恢复与迁移衔接；保持同一信息权威和内核能力。
5. [ ] **验证与关闭。** 在不同网络的真实接入中验证授权访问、撤销、断线及服务重启恢复；迁移后核对资产完整、授权边界和连接接续，确认无双重写入、质量退化或不合理等待，保存证据后关闭工作包二。

## 工作包三：信息随用户变化

目标：用户纠正或改变信息后，后续使用能够采用有效依据，同时保留有用的历史含义。

1. [ ] **产品设计。** 区分纠错、现实变化与停止使用；定义用户更新信息及智能体交接、恢复、重新使用旧材料时的行为与完成标准。
2. [ ] **专项审查。** 对照上述行为审查版本保护、证据有效性、关联刷新和宿主协作，找出实际缺口；共同审查已经成立的证据直接复用。
3. [ ] **架构设计。** 在统一的共享边界下，明确变化状态、依据核对和宿主协作的职责；独立演进信息使用能力，保住已确认的内核质量。
4. [ ] **实现。** 补齐缺失的变化语义及按需核对能力；智能体仅重新获取受影响的信息，再自主判断和行动。
5. [ ] **验证与关闭。** 验证并发更新、旧证据失效、关联刷新、交接与恢复，并覆盖与用户控制、跨地点访问及迁移共同使用的路径；确认质量和用户等待未退化，保存证据后关闭工作包三。

## 执行约束

- 权限与版本检查由确定性能力承担，语义理解与行动由外部智能体承担；不增加模型复核链或每轮全量重读。
- 产品设计和架构设计分别落实到产品需求、交付定义与架构文档；不能以实现完成代替设计明确，或以设计完成代替功能交付。
- 既有设计和代码都须经过当前用途的审查与验证；质量、边界或体验不合适就修复或替换，新增依赖或改变用途时补审。跨设备接入的[既有设计](../architecture/product-capability-gap-analysis.md)同样只是待审参考。
- 按真实受影响行为选择验证，复用未失效证据；不因功能名称或代码位置决定是否重跑全量测试。

共同准备及三个工作包全部关闭、验证依据保存后结束本任务；500题续跑单独安排。

## 依赖审查结论

审查日期：2026-09-10。以下结论限定于已检查的职责，不代表新增授权、遗忘或跨设备产品已通过验证。

| 对象 | 结论与复用边界 |
| --- | --- |
| 资产存储与版本端口 | 源码审查及 `assetlog`、`authorityport` 测试通过，可保留已验证的耐久写入、并发版本保护、压实与备份恢复；尚无删除能力，不能当作遗忘机制。 |
| 权威控制与生命周期 | 发现并修复关闭后的旧控制接口仍可覆盖新实例状态的问题；关闭先终止控制写入再释放资产锁。`authoritysubstrate`、`capabilitylifecycle` 测试通过，可保留修复后的生命周期机制；其中尚无产品授权决策，不能称为已完成的授权基座。 |
| 版本化证据与关联更新 | `core` 的8项定向测试通过，覆盖更新、并发冲突、旧证据失效、旧派生隔离及关联刷新；可保留这些机制，不据此宣称宿主已经会核对缓存或已解决所有语义变化。 |
| MCP接入 | 协议适配测试及4项连接认证测试通过；仅支持已验证的本机连接职责。共享令牌没有区分用户与各智能体，不能直接充当独立授权与撤销设计，也不能外推跨设备安全性。 |
| 接入设计与协作规则 | 旧文档和提示词不能承担授权检查；独立授权与遗忘采用工作包一的产品和架构设计，宿主核对旧材料仍待工作包三设计。跨设备接入不能直接沿用未经验证的本机假设。 |

关闭后覆盖问题的可复现回归：[TestClosedControlCannotOverwriteTheNewAuthorityOwner](../../internal/authoritysubstrate/substrate_test.go)。修复前该测试失败，修复后拒绝旧接口写入且新状态可重新打开；相关验证使用隔离测试数据，未调用外部模型。

## 工作包一专项审查

审查日期：2026-09-10。依据上述产品行为检查源码；新增能力尚未实现，以下是设计与实现取舍，不是功能通过报告。

| 对象与依据 | 发现与处理 |
| --- | --- |
| [共享连接](../../cmd/ownward/shared_mcp.go)、[连接认证](../../cmd/ownward/main.go) | 共享令牌只证明本机连接，不区分接入主体和管理权。保留协议转发，改为独立主体凭据及可信管理入口；来源标签不能充当身份。 |
| [产品契约](../../internal/contract/product.go)、[MCP工具](../../internal/adapter/mcpserver/server.go)、[命令行入口](../../cmd/ownward/main.go) | 尚无统一产品授权，语义工作也能取得信息；只保护搜索和读取会留下旁路。所有读取、维护、语义工作、管理及备份恢复统一按能力授权。 |
| [控制状态](../../internal/contract/control.go)、[资产端口](../../internal/contract/asset.go) | 有修订与版本保护，但未保存授权决定，也没有删除契约。保留经验证的权威与并发机制，补齐授权修订、耐久删除屏障及清理恢复状态。 |
| [资产日志](../../internal/assetlog/store.go) | 回放仅支持创建、更新和快照，普通写入要求非空正文，不能通过置空伪装删除。增加条件删除与回放语义，并清理旧日志中的正文。 |
| [派生存储](../../internal/derived/store.go)、[语义工作引用](../../internal/semantics/work.go) | 版本失效不等于遗忘；旧记录、候选输入与此前分析可能残留内容。保留版本引用和失效机制，按实际输入依赖清理派生材料、拒绝旧提交，保护无关原文。 |
| [权威基座](../../internal/authoritysubstrate/substrate.go)、[资产备份](../../internal/assetlog/backup_stream.go) | 既有恢复验证不能证明新增删除和授权状态可恢复。扩展备份覆盖与恢复顺序，排除删除目标和活动凭据；明确恢复旧快照与普通崩溃恢复的区别。 |
| [既有接入设计](../architecture/product-capability-gap-analysis.md)、[协作规则](../../internal/productrules/rules.go) | “任一受信任智能体可管理”和所有接入者看到全部信息的假设不成立，相关文档已校正。实现时规则只说明能力和状态，授权由确定性服务执行。 |
| [本机实例标识](../../cmd/ownward/shared_mcp.go)、[控制契约](../../internal/contract/control.go) | 本机描述符的 `DataIdentity` 来自目录哈希，只适用于实例定位；控制契约尚无体系和主体身份。设计已明确独立持久身份及所属体系的授权，位置变化不重建主体或扩大权限。 |
| [所有者与恢复设计](../modules/information-control/README.md#初始化与恢复契约) | 原设计把所有者入口限定为本地，并混用了首次初始化与恢复表述。已改为部署适配验证所有者控制权，分开正常接续、管理凭据恢复和旧快照恢复；本机来源不自动获得管理权。 |
| [管理交互](../modules/information-control/README.md#宿主内的管理闭环) | 已补齐普通连接提出请求、可信入口批准、执行及回到原任务的契约，单次批准不授予长期管理权；真实宿主中的可用性由第4—5项实现与验证。 |
| [遗忘体验与清理](../product/information-control.md#用户何时可以继续工作) | 已分开前台生效、清理完成与语义恢复，明确中断接续、回执和依赖传播边界。整资产删除保留为范围限制，局部请求不支持时不执行、不诱导扩大删除；清理成本与质量仍须实测。 |

部署位置复核只修正产品与架构契约；本机回环限制及实例定位代码保持其现有用途，独立身份和授权随工作包一实现，远程接入随工作包二实现。
