# 架构演进方向提炼

## 目标

广泛研究前沿成果、经典原理和跨领域思想，结合 OWNWARD 的产品本质独立判断，提炼少量具有长期指导力的架构演进方向，落入 `docs/architecture/evolution-direction.md`。

成果必须说明根本矛盾、各部分应承担的职责以及长期演进取舍。它指导具体架构的形成与调整，不预定某个框架、模块图、算法或实施方案。愿景、产品定位、当前架构和模块设计各按既有职责维护。

## 要求

- 按调研技能开展开放研究。不限学科、年代、个体、团队或资料形式，主动寻找同类领先实践、基础理论、跨领域认识和最强反例。以贡献和依据判断价值，不按名气、资料数量或固定参考名单择优。
- 核读一手来源，区分来源观点、实证结果和我们的推导。现有架构只是被审视的一个实例，不能用其已有条目代替外部研究或把现状重新命名为方向。
- 从用户长期需要与系统必须面对的事实推导取舍。每条方向都须说明为什么成立、模型更强或实现变化后为何仍成立，以及适用前提、代价和可推翻它的反例。
- 少而精。只保留能独立改变高层架构判断的命题，合并同义内容，剔除泛化口号、功能清单、具体设计和当前模型局限下的补偿手段。不预设条数。
- 正文采用清晰简洁的表达。核心判断独立成行，紧接简短的矛盾、边界与机制说明，不用自造名词或抽象术语代替结构取舍。研究依据、候选取舍与限定另存研究记录，不能让正文依赖对话背景才能理解。

## 推进与未达标处置

1. 双方分别理解产品需求，明确决定性研究问题，独立广泛调研与推导，记录候选、依据和最强反例。独立稿形成前不读取对方观点。
2. 对读质询，查找遗漏的思想来源、推导跳步、暂时性假设、层级错位和互相冲突的承诺。各自重判，按证据保留、修准或淘汰候选，形成可直接审阅的正文。
3. 将候选正文、研究依据与必要引用落入实际交付文件，双方分别按下表审查同一版本，先记录具体达成依据或缺口再交换。增加一名未读讨论历史的读者，用正文判断新的架构取舍，检查其实际指导力与误读风险。审后修改须复核受影响部分，验收最终绑定实际交付版本。
4. 任一标准未满足，就针对缺口继续取证、推导、质询、修订与复验。补查和复验以真实未决问题为单位，轮次、搜索次数、文稿完成或双方意见一致均不能替代达标。
5. 全部标准有据通过后交付并停止。确有不可自行解除的事实或授权障碍时，如实说明未达项及补齐条件，不降低标准报完成。

## 完成标准

| 标准 | 必须给出的依据 |
|---|---|
| 研究充分 | 已考察有望改变方向的同类、前沿、基础及跨领域候选，关键判断可回溯到实际读过的一手资料，重要分歧有处置 |
| 推导扎实 | 每条方向从根本需求、矛盾和约束推导，说明机制与取舍，外部材料提供启发或印证而非替代判断 |
| 长期成立 | 在模型能力显著增强、上下文/存储成本变化、接入者和部署技术更换的情况下重新检验，区分稳定需求与临时方案，给出反例及适用边界 |
| 层级准确 | 命题具有全局结构意义，能容纳不同具体架构，既不复述愿景或产品功能，也不写成模块规格与执行流程 |
| 有效且相容 | 每条能改变一个真实架构选择，保留命题互不重复且能同时兑现，符合产品授权、持有与使用信息的根本需要 |
| 清晰可用 | 独立读者仅凭正文能理解取舍并在新场景正确运用，关键误读已修正，正文没有作者旁白与多余解释 |
| 共同验收 | 双方各自有明确依据确认全部标准通过，定稿和验证对象一致，尚未证实的内容不写成已证事实 |

## 分工与状态

Codex 与 Antigravity 分别调研和判断，Codex 整合文稿，Antigravity 独立复核。共用资源遵循现行协作规则，研究不启动模型评测或产品开发。本轮只修改任务、研究、方向文档及必要的引用，不操作暂存、提交或推送。
