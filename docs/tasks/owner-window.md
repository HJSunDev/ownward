# 物主窗口：信息世界的可见面

> 用户界面用语（2026-09-23）：本文件标题及“物主”等词属于需求与架构概念，不作为用户界面的命名依据。窗口仅显示 Ownward；导航为“文稿、资料、关联、动态、设置”。呈现以用户需要知道的内容、操作结果及必要的下一步为准，不展示身份自证、内部实现说明或无信息量的口号。

> 状态（2026-09-29）：单元四已按当前可用环境完成实现与验证。实现保持跨平台；按用户最新验收要求，macOS／Linux 图形桌面的实机验证延期，不阻塞本次任务关闭。具体证据与边界见文末收尾记录。

> 协作补充（2026-10-01）：日常操作以用户长期授权的主智能体为中心，页面仅供查看与手动管理。主智能体工作与限域协作共用同一契约；当前修订已完成实现与验证，记录见文末；早期仅覆盖页面发起的结论不代表完整产品流程。

## 一、需求梳理

体系为用户做的核心工作——可靠保存、持续组织与关联、按需取用——必须对用户可见、可核对、可掌控：看得见自己拥有什么（原文与来源，不经任务智能体转述）、信息之间怎么关联（体系组织成果的直接呈现，用于导航、发现与验收）、正在发生什么（用户语义的过程与事件）。心血来潮想梳理思绪或修改已存内容时，要有一个像文档那样有头有尾、连贯积累的地方——从空开始或从一篇原文开始，完成后整体存入、所见即所存。接入、授权、遗忘、备份在属于自己的入口直接完成，不必每次在会话中发起。体系内化的是组织劳动，不是成果的可见性：用户看图不养图，改自己的字不做组织；覆盖还是删除、版本与并发属内部设计，用户不承担保存形式的选择与版本管理。

## 二、产品设计

**一个物主专用、与用户活动权威同在的窗口：呈现核心过程与存储，提供纯文字成形与掌控入口。** 理解与语义操作仍由智能体完成；窗口不是第二权威，不是第二任务交互面。接入方式（本机或随部署位置）由部署适配决定，迁移后随权威位置接续可达。打开即有界概貌——文稿与资料、近期变动、待决事项直达；窗口由五个面构成。

### 打开 Ownward：入口属于产品

**用户表达使用意图，智能体完成准备并打开；以后既能请智能体打开，也能自己点击 Ownward，进入同一份资料。** 遵循[项目哲学](../philosophy.md)，用户只处理必要授权、资料选择及重要后果，安装和运行细节由系统承担。

本单元覆盖 Windows、macOS 和 Linux 的本机入口，三者使用同一产品流程和能力；操作系统差异留在入口实现内部。入口只负责启动现有本机能力并打开网页，不另做独立桌面客户端，不要求应用商店上架、付费开发者账号或应用注册，也不为入口新增系统服务或开机自启。

| 场景 | 使用流程 |
| --- | --- |
| 第一次使用 | 用户将项目链接交给具备本机执行权限的智能体，说“帮我安装并打开 Ownward”。智能体依据官方说明获取、校验和安装产品，核实既有资料或初始化新用户资料；已明确的意图不再要求重复点击向导 |
| 已经使用过 Ownward | 直接接续原资料，只补缺失入口；位置无法核实或多个候选尚无既有选择时，请用户选择一次并记住 |
| 安装完成 | 自动在默认浏览器打开资料页面，同时创建本机可发现的 **Ownward** 入口并告知用户；按用户要求增加桌面快捷入口。图标随产品提供，入口在升级后仍可用 |
| 日常打开 | 对智能体说“打开 Ownward”，或点击系统入口。关窗、服务停止或电脑重启后都能重开；点击方式不要求智能体在线，不等待全库整理 |
| 重复打开 | 保留正在编辑的内容；能可靠唤回已有页面时唤回，否则打开同一资料的新页面 |
| 待确认事项 | 默认由已有管理授权的主智能体在原任务办理；用户想手动处理时，可打开同一待确认队列。进入页面不代表批准 |
| 恢复备份后 | 在完成结果中选择“打开恢复的资料”，经本机验证后打开；原资料和原入口保持。用户明确选择“以后打开这份资料”后，才更新日常入口；取消或失败可从恢复结果继续，无需复制命令或路径 |
| 关闭网页 | 只关闭当前页面，Ownward 继续在后台运行；再次点击系统入口复用已有运行，只打开页面 |
| 停止 Ownward | 在设置页选择“停止 Ownward”，停止这份资料的本机服务及相关连接。未保存输入先核对，已保存资料和草稿保留；再次点击系统入口自动启动并打开 |

用户主动手动安装时，可双击正式程序选择“开始使用”或“打开已有资料”，关闭起始面不建库；此辅助路径共用安装能力。

| 操作系统 | 用户日常找到入口的位置 |
| --- | --- |
| Windows | 开始菜单和系统搜索；可选桌面快捷方式 |
| macOS | 用户的应用程序目录和系统搜索；可选桌面替身 |
| Linux 桌面环境 | 应用菜单；可选桌面启动入口，遵循当前桌面环境的正常信任确认 |

这些都是用户级本地启动文件或轻量启动外壳，调用同一打开流程；创建入口不涉及商店注册或付费。无图形桌面的设备保留自动化调用，并如实报告无法在该设备显示网页，不把远程浏览器访问混入本单元。

**等待与失败有明确去处。** 智能体代办时在原会话反馈并接续；用户点击时立即得到可见响应，较慢时显示真实阶段，失败保留有效操作。系统自行处理可恢复问题，只向用户呈现必要决定；技术详情折叠，资料是否改变仅按核实结果说明。

| 情况 | 用户可采取的下一步 |
| --- | --- |
| 原资料暂不可达 | 重试或通过系统选择器重新定位，无需抄写路径；保留原绑定，不以新空库替代 |
| 需要验证身份 | 经既有可信系统验证后继续，无需另设密码或抄写凭据 |
| 浏览器未打开 | 在启动界面重试打开 |
| 会话失效 | 清除受保护内容，提示从 Ownward 系统入口重新进入；重开按钮仅在确实可用时显示 |
| 需要升级或迁移 | 告知必要处理；改变资料前说明后果并确认，保留失败恢复路径 |
| 资料已迁往另一设备 | 有已验证且受支持的路径则接续，否则指引到资料所在设备打开 |

### 文稿（暂名，终名待定）：一次有头有尾的工作

与随时可开可断的对话相对：有始有终、跨轮次持续、内容在其中成形。七条承诺：**有界、连贯、所属（可留可弃）、可见、存续（关窗不丢稿，重开继续；输入自动保存、保存状态如实可见，异常时未同步输入尽力救回；冲突保留双方内容；弃稿不留痕）、整体保存、所见即所存。** 三种用法同一形态：

```text
创作：从空开始 → 与智能体交互（窗口不承载对话）→ 积累可见 → 整体入库
编辑：从任一原文打开（资料/关系/文稿面均可发起）→ 直接改字或经智能体（同一套提交契约）→ 对照预览 → 保存生效
预览：提交前见"现在"与"将成为"；确认类材料（如遗忘确认）复用同一形态
```

保存语义：保存后看到的就是生效的；信息仍以同一身份存在。**直接编辑＝明确表示修改当前文档**：自撰内容按文档编辑器语义改写当前；带来源证据的资料——原始来源内容保留为证据，修订内容作为当前使用，二者在呈现与取用中始终可区分（不改写历史发言；对照预览同时呈现"原件保留为证据／修订成为当前"）。分支仅由确定性元数据（是否带来源证据）决定，窗口不做语义推断、不设歧义检测。涉及历史含义的处理（更正性质、适用条件等）由用户明确发起、经智能体理解，窗口不承担该判断，用户不选择保存形式。内容被别处改动时如实告知，不静默覆盖；编辑以整条信息为单位，只想删一部分时如实说明粒度；不承诺回溯任意旧版本。已入库的文稿享有与资料同等的可见、关联、遗忘、备份、迁移待遇，可重新打开继续积累。

#### 交给智能体协助

**常用流程在主智能体中完成，窗口供看稿、改字和手动管理。** 用户告诉长期授权的主智能体要写什么、改什么、何时加入资料；主智能体沿已有授权处理同一份文稿，不必打开页面或另取一小时许可。页面可以随时查看和继续编辑，关闭页面不影响智能体使用。

需要另一个智能体临时协助时，主智能体发出单稿邀请，收到实际接入者的申请后按用户意愿授权或拒绝；用户不用搬到页面批准。临时协作者只可读写该草稿一小时，不能入库、枚举其他草稿或再授权；主智能体可随时结束协作。

从页面发起是辅助路径：“更多 → 交给智能体协助 → 复制请求”，发到智能体对话并说明修改要求。已授权的主智能体直接接续；普通协作者申请后，可由可信主智能体处理，也可在页面手动核对。修改自动呈现在原稿中，入库由用户在主智能体中明确要求或在页面预览确认；授权状态不冒充工作进度。

已有工具连接或本机执行能力均可接入，不依赖品牌；复制材料不含正文与权限，复制失败提供可选取文本。无可用接入能力时如实说明，拒绝、到期可重新发起。主智能体身份来自现有授权，不从名称或复制请求推定。
### 其余四面

- **资料**：清单含已入库文稿，来源可读地显示"我创建的"（文稿面管进行中与可继续，资料面呈现全部，一物两视角）；原文与来源直接核对，不以摘要代替；逐条状态如实——已整理／待整理／已停止使用，不伪装完成；核对性查找可用，通用检索仍由智能体承担；遗忘从这里发起：确认材料 → 停止使用 → 清理 → 完成。
- **关系**：邻域为主（围绕选中项看关联），总览为辅（世界的形状、聚类与孤岛）；节点＝文稿与资料，边＝以用户语言呈现的关系依据（对象、事项、理由），每条可溯源原文与来源；未组织的信息如实显示为未连上，不伪装完整；只看不编，发现问题告诉智能体或走掌控面。
- **动态**：用户语义事件流——存入、更新与更正、遗忘、授权变更、文稿入库；仍有效的资产可追溯原文，资料遗忘后仅保留有界、无正文的操作事实，呈现为不可打开的“已遗忘的资料”，不展示旧正文或来源。文稿保存使旧关联失效时，说明数量与原因（引文不再匹配、无法唯一定位、目标不可用），不将目标已遗忘一概归因为本次改字；旧事件没有该记录时不声称历史上零失效。内部管道（队列、耗时、失败、世代）不进入，只以状态与健康聚合呈现。
- **掌控**：接入者清单（同名连接可区分）、各自能力与状态、撤销与调整；待批准事项以决策卡呈现——对象、范围、后果一句话，批准后接回原任务（接入、迁移与草稿协作确认均在此；已中断会话在重连或下次调用接续）；备份与健康（"正常／需要注意"）、恢复入口。

### 边界与完成标准

- **单一入口、单一队列**：待决事项同一队列、两种到达（会话内发起被带来；物主主动打开见同一队列），任一处决定即时约束另一处；无链接能力的宿主保留文本回退，队列与结果一致。
- **随时可达＋有事必达**：物主通过系统中可发现的 Ownward 入口随时打开，不依赖任何智能体连接或命令知识；有待决事项时入口必须可达、不藏页签后；日常使用不要求物主常驻或自行启动额外进程。
- **物主验证**：复用既有所有者验证，不新增账号、密码或凭据负担；入口失效可经所有者验证重建，不丢失掌控。
- **同源一致**：呈现与内核权威状态同源，不产生只在窗口成立的状态；撤销即时生效。
- **独立成立**：原文与掌控的呈现仅凭资产与掌控状态成立；关系呈现经稳定契约，派生重建中或不可用时如实显示状态、不伪装完整；内核换代后仍然正确。
- **用户语言**：只呈现对象、范围、后果与关系依据；不出现内部编号、协议、凭据、世代等术语（覆盖全部视图，含关系视图）。
- **不做**：语义生成／建议／改写（智能体职责）、富文本与协同编辑、图编辑与手工整理（结构维护是体系职责）、统计仪表盘与虚荣指标、内部机制暴露、云端服务与账号体系。
- **不打扰**：窗口不是任何能力的前置，关闭页面时体系照常；明确选择“停止 Ownward”才停止当前资料的本机运行。
- **验收要点**：无任何智能体连接时，物主可完成创建文稿、查看内容与关联（关联可溯源原文）、编辑一条原文并保存生效（带来源证据的资料呈现原件保留＋修订当前两种结果）、撤销一个接入者、走完一次遗忘、得到一份可恢复备份；创作与编辑端到端须可见中间态与过程（只展示最终结果不达标），存入内容与所见一致，关联随组织如实呈现；资料达长期规模后上述任务仍可完成（查找与聚焦进入，不做全量倾泻）。
- **入口先验收**：从用户向智能体表达安装意图开始，走完正式安装及首次打开，再验证脱离智能体后的独立重开；具体场景见单元四。

## 三、架构设计

**物主窗口＝活动权威的可视投影与物主入口：只呈现与发起，不新增智能、不新增权威、不新增常驻组件。** 它作为"物主接入"进入窄腰（与 MCP 适配平级）：上方多一种接入者形态，腰部契约增加有界投影与物主操作，权威基座扩展草稿、原件留证与事务账本；语义组织、推理职责及检索算法不变。判断标准：去掉窗口体系照常；换掉呈现形态，契约不变。

### 形态与挂载

- 呈现＝单二进制内嵌的本地网页（go:embed 静态资源、原生 JS、无前端构建链）；本版增加同一程序内的短生命周期系统启动交互，只负责首次准备、定位、验证与打开失败的可见处置，不另做五面原生客户端。完整桌面／移动／宿主内嵌客户端仍非本版必要。
- 挂载＝本地回环，复用既有控制面监听；未运行时按既有 connect-or-start 建立；不新增对外端口、不默认联网、不做云端。
- 主体＝复用既有所有者验证；窗口会话即 owner 主体，不新增权限主体。窗口全部 API 调用（含轮询与操作提交）须携物主凭据校验（静态资源除外），防回环跨源与本地假冒页面。
- **入口与首次验证（本模块设计项）**：系统中的 Ownward 入口及程序无参数启动进入同一打开流程；`owner-window` 保留为显式命令入口，共用定位、connect-or-start、所有者验证与浏览器启动逻辑。控制面在回环发布窗口入口与一次性引导令牌，浏览器凭令牌完成物主验证并建立设备会话；窗口路由继续执行同源与凭据策略，机器控制路径继续拒绝浏览器 Origin。迁移后入口经部署描述符核实新位置，失效时走已有所有者恢复。远程部署的首次验证路径仍由部署适配提供，本版交付本机路径；稳定系统入口不等于扩展远程浏览器能力。

### 日常入口的实现边界

1. **统一安装与打开能力。** 三个平台共享安装、资料绑定、验证与恢复逻辑，按平台构建产品程序；显式安装／启用、`owner-window` 和用户点击共用这一实现。入口的平台层承接目录约定、启动文件、浏览器调用、系统选择器及账户保护机制，不分叉业务规则；平台运行资源另按发布契约交付。自动化接口接受首次启用／复用已有资料、桌面入口及安装后打开等明确意图，返回版本化的阶段、结果、重试条件和必要决定。安装、入口就绪、浏览器启动分别报告；自动化调用不弹向导，浏览器仅响应打开意图启动。既有 CLI／MCP 标准流、退出行为及显式选址保持兼容，未指定目标的新调用使用下述统一默认规则。
2. **从未安装开始可执行。** 官方发布说明与制品清单按操作系统、处理器架构匹配程序和必要运行资源，提供版本、校验及统一调用方法；通用逻辑不硬编码 `.exe` 或 Windows 路径。清单明确支持的系统版本、处理器架构、桌面条件、程序入口、向量运行时及依赖文件、许可材料和校验身份；程序与资源整体校验后才激活安装。平台运行资源通过统一构建与组包流程交付，不能只交付启动文件；实机验证范围按单元四的验收口径记录。各目标按同一锁定源码、模型和计算规则构建并实机验证，以实际制品形成空间身份；沿[向量能力交付与世代边界](../modules/embedding/README.md#交付与运行)，不以平台移植为由混用既有向量或修改语义能力，降级读取不算完整交付通过。智能体凭已授权的设备能力取得制品后即可执行，无须预装 Ownward MCP 或专用安装适配器。缺少执行能力或匹配制品时明确报告，保留宿主授权边界；接入配置沿原机制，安装不自动授予智能体资料访问权。
3. **稳定交付位置。** 完整制品、资源及图标就位到各平台当前用户的持久目录，无需管理员权限；启动入口指向该程序，不绑定临时网页地址或会话，组包清单和接入引用同步。只创建用户级启动文件，必要外壳不承载业务；不依赖应用注册、商店审核、付费账号或新增常驻组件，不绕过平台安全检查。已有安装只补缺失项，升级保留资料绑定，替换失败保留可用版本。开发制品与真实安装、入口、资料隔离。
4. **统一定位，权限另验。** 安装、CLI、本机 MCP 和窗口共用目标解析，优先级为明确指定的 `--data-dir`／已有连接目标、CLI 环境配置 `OWNWARD_DATA_DIR`、用户默认绑定、唯一既有安装登记／系统默认位置。参数覆盖环境配置；同一请求同时提交不一致的目录参数与连接目标时拒绝猜选。无既有选择且发现多个候选时请求选择，不扫描全盘或宿主私有配置。系统入口以已保存绑定作为明确目标，不让启动时继承的环境变量覆盖它。绑定只记录体系身份与位置，使用前同库内 `owner-window.json` 一并核实权威及 Handoff；选定目标缺失或身份不符即修复，不能继续尝试低优先级位置或新建空库。首次安装将已确认的目标保存为绑定；普通指定目标的打开不改默认，更换日常目标须有明确意图且新目标验证成功，再按所见绑定版本原子更新，冲突时重新核对。默认变化只影响随后未指定目标的新调用，既有连接及活动会话仍固定原目标。仅明确首次启用且无既有数据冲突时执行 setup；绑定不授予权限，删除绑定不删除资料。
5. **复用身份链。** 定位校验 → connect-or-start → 系统账户保护的所有者验证 → 一次性浏览器入口 → 窗口会话。setup／所有者恢复留在可信本机侧，浏览器不得获得通用恢复能力；有效授权不重复请求。凭据及引导令牌不进入智能体结果、日志、快捷方式或错误详情，安装接口不自动建立智能体管理授权。保护边界是 Ownward 的服务接口及操作系统账户；拥有同一账户完整本机执行及数据访问能力的程序不属于接口权限能隔离的对象，沿[用户掌控边界](../product/information-control.md#恢复与完成标准)，不另造账号或宣称安装器能隔离此类程序。
6. **接续同一运行状态。** 并发启动沿现有互斥机制合并，幂等重试复用有效准备，不重复初始化或关闭已有编辑。浏览器重试取得新引导入口；快捷方式创建失败不回滚已建资料。普通打开不执行数据格式或组合身份迁移，升级与迁移沿正式确认流程；退休源不得恢复为活动库。
7. **有限启动交互。** 正常日常打开不弹原生向导、进度或连接对话框，准备好后直接展示网页；首次选择和确实无法恢复的错误由同一程序的短生命周期界面承接。请求具有有界超时及终态；安装／打开零模型调用，不阻塞于全库重建。Windows 新安装的账户资料与访问记录使用用户目录中的独立位置，安装前核验路径没有被宿主重定向，兼容已有独立位置。验收必须覆盖从系统外壳启动，不能仅凭同一宿主的子进程可用判断完成。保持单二进制、内嵌网页与既有服务，不增加常驻启动组件或另一套业务界面。
8. **恢复结果接回入口。** 本机恢复完成后，在用户级部署元数据中保存有界、可接续的恢复结果引用，关联源体系、恢复操作与系统实际生成的目标；不含凭据，也不充当授权。已验证的窗口只提交该结果引用和打开意图，由进程内受信本机回调复核当前所有者、结果归属及目标，调用同一打开流程建立目标所需的本机恢复入口和新会话。不得接受浏览器提供的任意目录、命令或地址，不向浏览器开放机器恢复端点，不复活备份内旧凭据。恢复结果与“打开／设为日常资料”分别记状态，重复打开不重复恢复；结果在刷新及重启后可继续查阅，失败保留可重试操作。新目标验证并打开后才提供明确的默认切换，切换失败保留原绑定；原页面及已指定目标的智能体连接不随之改址。不依赖自定义协议注册、额外常驻进程或用户运行命令。

入口绑定用户选定的资料，程序版本、端口和浏览器会话可以更换。本单元不扩展远程浏览器、多资料库管理或自动更新产品。

**停止的运行边界。** 设置页的“停止 Ownward”与日常导航分离，将“关闭网页”说明与“停止运行”动作分区呈现：前者写明后台照常运行且已连接应用不受影响，后者写明服务停止、连接断开、资料保留；两者各自说明再次点击系统入口的结果；桌面同行对齐，窄屏自然换行，不依赖健康状态的显隐定位。即使设置内容读取失败，也保留停止入口。操作经当前所有者及同源验证后，请求当前部署正常停止；复用运行时的取消与关闭机制，结束请求、连接、监听和进程，关闭仅限当前资料对应的部署。未保存内容的确认绑定所见内容，操作中或内容变化时重新核对；停止失败保留输入。点击后立即显示“正在停止…”并禁用重复提交，暂停页面轮询；关闭请求不排在正文读取队列之后，服务先返回停止回执再取消活动请求。失败在操作旁提示并恢复按钮；成功后保留静态结束页，明确服务已停止及再次点击系统入口的使用方式，无需刷新，不展示重新连接页。注销单个网页会话的旧接口保留兼容，不作为停止按钮的实现。

### 关键裁决

1. **草稿＝权威基座持有的耐久物主工作状态**（同库同事务域、独立状态域）：对普通检索与组织路径构造性不可见——零枚举零返回；可信主智能体沿明确的长期管理与维护授权操作工作域，临时工作项仅在授权期内可读取所涉草稿的必要内容与版本、并写入（一次性授权，提交或弃稿即失效；不触资产、不触发组织）。草稿域同样以句柄与条件提交防护并发，多端或双写不静默覆盖。晋升＝同事务的域迁移（创作＝create、编辑＝条件 update，按确定性分支映射两种 update 形态——替换当前使用／保留原件附加更正）；组合期间的草稿写入为独立工作状态事务，不持资产锁。弃稿即删、不进资产日志；闲置草稿不静默删除，仅用户明确弃稿（本人或授权主智能体代办）或遗忘清理时删除；随库备份与迁移；目标资产被遗忘时绑定草稿同失效。此为架构总纲四类状态的显式扩展登记。
2. **待决统一投影**：普通管理决定来自耐久 operations，接入来自 enrollment，迁移来自 Handoff，草稿协作决定归物主工作状态中的原工作项；物主端口统一投影这些权威记录，不另建批准队列。迁移确认必须写入原 Handoff 并在冻结前核验，接入批准记录实际批准者；任一路决定后，宿主按原调用接续。窗口补的是宿主不在时把物主带到待决面前的呈现与到达路径。已决条目保留有界、过期清理。
3. **过程可见＝游标增量＋短轮询**：轮询间隔与单次读取有界；草稿与账本写入产生游标增量；不承诺毫秒实时。
4. **输入保存与异常路径**：物主输入自动保存到草稿（节奏有界）；界面如实显示已保存状态；连接中断或句柄失效强制刷新时，未同步输入会话级暂存救回（不构成第二真相），恢复后合并或提请物主处理；冲突时保留双方内容（用户刚写的内容与权威新内容并存待决），不静默覆盖任一方；发布失败可重试且幂等。
5. **零智能呈现**：窗口路径无任何模型调用（含本地向量能力）。
6. **进程内直连**：投影查询同进程直调内核查询面，不开新服务链路。
7. **原件跨接入可取用**：统一读取及片段读取均以 `original.revision` 提示留存原件；`ownward_read` 的 `include_original=true` 按需返回原件正文与来源，独立于当前 `information`。原件是历史来源证据，不代表当前有效事实，`basis` 仍核对当前内容。默认读取只增加定点元数据查询，不重复传输原件；原件全文沿现有流式预算、权限与遗忘交付屏障。入口位置描述符属于可重建提示，写入失败如实提醒，不阻断已经由活动权威验证的物主入口或遮蔽已提交的迁移目标。

### 草稿协作交接

- **交接不授予权限**：复制材料仅含统一调用说明、目标体系定位和限时工作项引用，不含正文、凭据或授权。已有连接使用 `ownward_draft_work`；本机执行使用 `ownward draft-work`，复用共享服务、系统账户保护及零权限主体登记，凭据不交给智能体。连接与草稿授权分别核验，不自动授予全库权限；无工具连接且无法在资料所在电脑执行时，如实提示不能接续。
- **主智能体沿用长期授权**：同一 `ownward_draft_work` 契约提供文稿生命周期与协作管理。查看＋维护＋管理授权可直接列稿、建稿、读写及按用户要求发布／弃稿；管理授权可查申请、决定、结束和取消。普通资料权限不使草稿进入检索，也不开放私有工作域。发布复用原事务与操作回执，重启后可查询本人原发布结果。
- **申请与授权同源**：请求绑定真实认证主体；可信管理智能体与窗口决定同一工作项，版本检查在事务内完成。决定绑定请求方、草稿、范围及批准者修订；临时读写在提交和交付时核验双方当前权限与有效期。批准者撤权、换证或授权修订变化后，旧许可失效，重新授权不能复活旧决定。
- **有界接续**：等待不占用模型轮询，不无限占住工具调用；批准后仍在线则继续原调用，已中断则重连或下次调用接续，不承诺唤醒任意闲置会话。重试复用原申请，不重复授权；拒绝、取消、到期、撤销、发布、弃稿或绑定资产遗忘后，旧请求不得领取或恢复权限。记录数量、等待与保留期有界。
- **沿用原边界**：过程通过既有草稿增量呈现，冲突保护双方内容；不新增模型、智能体调度器、宿主专用协作协议或第二批准权威。

执行约束：临时协作请求有效一小时，批准后编辑授权一小时；主智能体的长期授权持续到用户收回，不套用此期限。`status` 每次最多等待 25 秒。交接记录最多 256 条，每条最多 16 个申请，每稿最多 64 个有效授权，列表游标分页；创建新交接时清理已超过所有可能授权期限的旧记录。恢复备份清除交接与授权，结束协助同步撤销权限并通知既有迁移等待方。

### 场景边界（如实）

| 场景 | 支撑 | 边界 |
| --- | --- | --- |
| 无智能体连接的全部掌控 | 视图端口＋权威 | 全部成立 |
| 创作填充过程可见 | 授权工作项写入草稿 → 游标增量 → 窗口呈现 | 时机由轮询与增量到达决定 |
| 智能体流程 | 任意宿主领取工作项执行；无宿主时明确保持待处理 | 内核不代跑模型、不调度智能体 |
| 大规模总览 | 邻域查询＋聚合视图 | 总览是聚合近似，非全图渲染 |
| 远程部署 | 契约支持随部署位置可达，本版交付本机路径，远程首验与接入由部署适配后置交付 | 远程传输安全依赖部署侧既有手段 |

### 硬条件

1. 物主视图契约显式版本化，与 MCP 契约同等稳定待遇；未来客户端只换呈现层。
2. 断开窗口并清除本地状态后，资产、授权、迁移不受影响；窗口不产生只在窗口成立的状态。
3. 遗忘覆盖窗口缓存、本地副本与工作状态域（含绑定目标资产的草稿）。
4. 单二进制不破坏：静态资源 embed，无外部文件依赖、无前端构建必经路径。
5. 零模型调用进入窗口路径。
6. 普通用户从系统入口到资料可操作全程不依赖终端、智能体代开或手动运行服务；启动交互在同一制品内交付，不新增常驻组件或第二权威。

### 架构级验证

1. **草稿构造性不可见**：任意智能体普通读取路径（检索、导航、状态、语义工作）枚举与返回均不出现草稿；授权工作项在授权期内可读所涉草稿，授权范围外读取仍零出现。
2. **晋升原子性**：草稿整体保存后，资产与其操作记录同事务生效，或整体未生效。
3. **遗忘覆盖**：遗忘清理同时覆盖工作状态域、窗口缓存与本地副本，绑定目标资产的草稿同失效。
4. **断窗重建**：断开并清除窗口本地状态后重连，五面全部从权威重建，无只在窗口成立的状态。
5. **双轨批准一致**：会话内呈现与窗口呈现同一待决队列，任一处决定后另一处即时受约束，不出现两份可各自批准的状态。
