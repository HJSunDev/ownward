# 物主窗口：信息世界的可见面

## 一、需求梳理

体系为用户做的核心工作——可靠保存、持续组织与关联、按需取用——必须对用户可见、可核对、可掌控：看得见自己拥有什么（原文与来源，不经任务智能体转述）、信息之间怎么关联（体系组织成果的直接呈现，用于导航、发现与验收）、正在发生什么（用户语义的过程与事件）。心血来潮想梳理思绪或修改已存内容时，要有一个像文档那样有头有尾、连贯积累的地方——从空开始或从一篇原文开始，完成后整体存入、所见即所存。接入、授权、遗忘、备份在属于自己的入口直接完成，不必每次在会话中发起。体系内化的是组织劳动，不是成果的可见性：用户看图不养图，改自己的字不做组织；覆盖还是删除、版本与并发属内部设计，用户不承担保存形式的选择与版本管理。

## 二、产品设计

**一个物主专用、与用户活动权威同在的窗口：呈现核心过程与存储，提供纯文字成形与掌控入口。** 理解与语义操作仍由智能体完成；窗口不是第二权威，不是第二任务交互面。接入方式（本机或随部署位置）由部署适配决定，迁移后随权威位置接续可达。打开即有界概貌——文稿与资料、近期变动、待决事项直达；窗口由五个面构成。

### 文稿（暂名，终名待定）：一次有头有尾的工作

与随时可开可断的对话相对：有始有终、跨轮次持续、内容在其中成形。七条承诺：**有界、连贯、所属（可留可弃）、可见、存续（关窗不丢稿，重开继续；输入自动保存、保存状态如实可见，异常时未同步输入尽力救回；冲突保留双方内容；弃稿不留痕）、整体保存、所见即所存。** 三种用法同一形态：

```text
创作：从空开始 → 与智能体交互（窗口不承载对话）→ 积累可见 → 整体入库
编辑：从任一原文打开（资料/关系/文稿面均可发起）→ 直接改字或经智能体（同一套提交契约）→ 对照预览 → 保存生效
预览：提交前见"现在"与"将成为"；确认类材料（如遗忘确认）复用同一形态
```

保存语义：保存后看到的就是生效的；信息仍以同一身份存在。**直接编辑＝明确表示修改当前文档**：自撰内容按文档编辑器语义改写当前；带来源证据的资料——原始来源内容保留为证据，修订内容作为当前使用，二者在呈现与取用中始终可区分（不改写历史发言；对照预览同时呈现"原件保留为证据／修订成为当前"）。分支仅由确定性元数据（是否带来源证据）决定，窗口不做语义推断、不设歧义检测。涉及历史含义的处理（更正性质、适用条件等）由用户明确发起、经智能体理解，窗口不承担该判断，用户不选择保存形式。内容被别处改动时如实告知，不静默覆盖；编辑以整条信息为单位，只想删一部分时如实说明粒度；不承诺回溯任意旧版本。已入库的文稿享有与资料同等的可见、关联、遗忘、备份、迁移待遇，可重新打开继续积累。

### 其余四面

- **资料**：清单含已入库文稿，来源可读地显示"我创建的"（文稿面管进行中与可继续，资料面呈现全部，一物两视角）；原文与来源直接核对，不以摘要代替；逐条状态如实——已整理／待整理／已停止使用，不伪装完成；核对性查找可用，通用检索仍由智能体承担；遗忘从这里发起：确认材料 → 停止使用 → 清理 → 完成。
- **关系**：邻域为主（围绕选中项看关联），总览为辅（世界的形状、聚类与孤岛）；节点＝文稿与资料，边＝以用户语言呈现的关系依据（对象、事项、理由），每条可溯源原文与来源；未组织的信息如实显示为未连上，不伪装完整；只看不编，发现问题告诉智能体或走掌控面。
- **动态**：用户语义事件流——存入、更新与更正、遗忘、授权变更、文稿入库；仍有效的资产可追溯原文，资料遗忘后仅保留有界、无正文的操作事实，呈现为不可打开的“已遗忘的资料”，不展示旧正文或来源。文稿保存使旧关联失效时，说明数量与原因（引文不再匹配、无法唯一定位、目标不可用），不将目标已遗忘一概归因为本次改字；旧事件没有该记录时不声称历史上零失效。内部管道（队列、耗时、失败、世代）不进入，只以状态与健康聚合呈现。
- **掌控**：接入者清单（同名连接可区分）、各自能力与状态、撤销与调整；待批准事项以决策卡呈现——对象、范围、后果一句话，批准后自动接回原任务（接入确认与迁移确认均在此）；备份与健康（"正常／需要注意"）、恢复入口。

### 边界与完成标准

- **单一入口、单一队列**：待决事项同一队列、两种到达（会话内发起被带来；物主主动打开见同一队列），任一处决定即时约束另一处；无链接能力的宿主保留文本回退，队列与结果一致。
- **随时可达＋有事必达**：物主随时可达且不依赖任何智能体连接；有待决事项时入口必须可达、不藏页签后；日常使用不要求物主常驻或启动额外进程。
- **物主验证**：复用既有所有者验证，不新增账号、密码或凭据负担；入口失效可经所有者验证重建，不丢失掌控。
- **同源一致**：呈现与内核权威状态同源，不产生只在窗口成立的状态；撤销即时生效。
- **独立成立**：原文与掌控的呈现仅凭资产与掌控状态成立；关系呈现经稳定契约，派生重建中或不可用时如实显示状态、不伪装完整；内核换代后仍然正确。
- **用户语言**：只呈现对象、范围、后果与关系依据；不出现内部编号、协议、凭据、世代等术语（覆盖全部视图，含关系视图）。
- **不做**：语义生成／建议／改写（智能体职责）、富文本与协同编辑、图编辑与手工整理（结构维护是体系职责）、统计仪表盘与虚荣指标、内部机制暴露、云端服务与账号体系。
- **不打扰**：窗口不是任何能力的前置，关闭时体系一切照常。
- **验收要点**：无任何智能体连接时，物主可完成创建文稿、查看内容与关联（关联可溯源原文）、编辑一条原文并保存生效（带来源证据的资料呈现原件保留＋修订当前两种结果）、撤销一个接入者、走完一次遗忘、得到一份可恢复备份；创作与编辑端到端须可见中间态与过程（只展示最终结果不达标），存入内容与所见一致，关联随组织如实呈现；资料达长期规模后上述任务仍可完成（查找与聚焦进入，不做全量倾泻）。

## 三、架构设计

**物主窗口＝活动权威的可视投影与物主入口：只呈现与发起，不新增智能、不新增权威、不新增常驻组件。** 它作为"物主接入"进入窄腰（与 MCP 适配平级）：上方多一种接入者形态，腰部契约增加有界投影与物主操作，权威基座扩展草稿、原件留证与事务账本；语义组织、推理职责及检索算法不变。判断标准：去掉窗口体系照常；换掉呈现形态，契约不变。

### 形态与挂载

- 呈现＝单二进制内嵌的本地网页（go:embed 静态资源、原生 JS、无前端构建链）；桌面／移动／宿主内嵌是同一契约的未来客户端，非本版必要。
- 挂载＝本地回环，复用既有控制面监听；未运行时按既有 connect-or-start 建立；不新增对外端口、不默认联网、不做云端。
- 主体＝复用既有所有者验证；窗口会话即 owner 主体，不新增权限主体。窗口全部 API 调用（含轮询与操作提交）须携物主凭据校验（静态资源除外），防回环跨源与本地假冒页面。
- **入口与首次验证（本模块设计项，非"复用既有"）**：CLI 引导打开——控制面在回环发布窗口入口与一次性引导令牌，浏览器凭令牌完成物主验证并建立设备会话；窗口路由为浏览器设计同源与凭据策略（现有控制面为机对机 Bearer 且拒绝 Origin，不预设可用）；迁移后入口经部署描述符发现新位置，失效时走所有者恢复。远程部署的首次验证路径由部署适配提供，本版交付本机路径。

### 分层与接入

| 部分 | 职责与改动 |
| --- | --- |
| 呈现层（网页） | 五面渲染＋纯文字工作面；零智能、零业务判断，无业务持久本地状态（异常救回性暂存除外，见输入保存），重连全部从权威重建 |
| 物主视图端口（窄腰新增，薄） | 有界读投影（资料／原文／状态／关系邻域／动态／健康；全部投影面统一游标或分页，无全库物化）＋物主操作（决策／撤销／遗忘发起／备份／提交）＋草稿生命周期＋不透明句柄（身份与版本封装，失效＝内容已变→强制刷新，不静默覆盖） |
| 统一能力契约（既有） | 读写复用 MCP 同语义、同路径、同权限、同版本核对；待决事项＝既有权威操作记录（awaiting_approval）的投影，"单一队列两种到达"由同一投影、两处呈现、决定即时约束兑现 |
| 权威运行基座 | 新增一类持久状态：物主工作状态域（草稿，独立于资产空间）；动态＝操作账本的用户语义投影——管理操作读既有权威记录，短期接入／迁移记录的已决公共事实在原提交事务进入同一有界账本，只读、不具有批准资格；资产类变更（存入、更新、更正、文稿入库）同事务增补用户语义操作记录；压实后历史深度不承诺 |
| 内核与派生 | 复用既有邻域导航、词法查询及关系依据；物主侧查找／筛选与有界聚合总览契约由单元二补齐，不声称既有产品契约已全部覆盖；不改语义组织和检索算法，不增加模型调用 |

### 关键裁决

1. **草稿＝权威基座持有的耐久物主工作状态**（同库同事务域、独立状态域）：对智能体构造性不可见——普通检索与组织路径零枚举零返回；授权工作项在授权期内可读取所涉草稿的必要内容与版本、并写入（一次性授权，提交或弃稿即失效；不触资产、不触发组织）。草稿域同样以句柄与条件提交防护并发，多端或双写不静默覆盖。晋升＝同事务的域迁移（创作＝create、编辑＝条件 update，按确定性分支映射两种 update 形态——替换当前使用／保留原件附加更正）；组合期间的草稿写入为独立工作状态事务，不持资产锁。弃稿即删、不进资产日志；闲置草稿不静默删除，仅物主弃稿或遗忘清理时删除；随库备份与迁移；目标资产被遗忘时绑定草稿同失效。此为架构总纲四类状态的显式扩展登记。
2. **待决可达而非新建**：普通管理决定来自耐久 operations，接入来自 enrollment，迁移来自 Handoff；物主端口统一投影这些权威记录，不另建批准队列。迁移确认必须写入原 Handoff 并在冻结前核验，接入批准记录实际批准者；任一路决定后，宿主接回原任务。窗口补的是宿主不在时把物主带到待决面前的呈现与到达路径。已决条目保留有界、过期清理。
3. **过程可见＝游标增量＋短轮询**：轮询间隔与单次读取有界；草稿与账本写入产生游标增量；不承诺毫秒实时。
4. **输入保存与异常路径**：物主输入自动保存到草稿（节奏有界）；界面如实显示已保存状态；连接中断或句柄失效强制刷新时，未同步输入会话级暂存救回（不构成第二真相），恢复后合并或提请物主处理；冲突时保留双方内容（用户刚写的内容与权威新内容并存待决），不静默覆盖任一方；发布失败可重试且幂等。
5. **零智能呈现**：窗口路径无任何模型调用（含本地向量能力）。
6. **进程内直连**：投影查询同进程直调内核查询面，不开新服务链路。
7. **原件跨接入可取用**：统一读取及片段读取均以 `original.revision` 提示留存原件；`ownward_read` 的 `include_original=true` 按需返回原件正文与来源，独立于当前 `information`。原件是历史来源证据，不代表当前有效事实，`basis` 仍核对当前内容。默认读取只增加定点元数据查询，不重复传输原件；原件全文沿现有流式预算、权限与遗忘交付屏障。入口位置描述符属于可重建提示，写入失败如实提醒，不阻断已经由活动权威验证的物主入口或遮蔽已提交的迁移目标。

### 场景边界（如实）

| 场景 | 支撑 | 边界 |
| --- | --- | --- |
| 无智能体连接的全部掌控 | 视图端口＋权威 | 全部成立 |
| 创作填充过程可见 | 授权工作项写入草稿 → 游标增量 → 窗口呈现 | 时机由轮询与增量到达决定 |
| 智能体流程 | 任意宿主领取工作项执行；无宿主时明确保持待处理 | 内核不代跑模型、不调度智能体 |
| 大规模总览 | 邻域查询＋聚合视图 | 总览是聚合近似，非全图渲染 |
| 远程部署 | 契约支持随部署位置可达，本版交付本机路径，远程首验与接入由部署适配后置交付 | 远程传输安全依赖部署侧既有手段 |

### 硬条件

1. 物主视图契约显式版本化，与 MCP 契约同等稳定待遇；未来客户端只换呈现层。
2. 断开窗口并清除本地状态后，资产、授权、迁移不受影响；窗口不产生只在窗口成立的状态。
3. 遗忘覆盖窗口缓存、本地副本与工作状态域（含绑定目标资产的草稿）。
4. 单二进制不破坏：静态资源 embed，无外部文件依赖、无前端构建必经路径。
5. 零模型调用进入窗口路径。

### 架构级验证

1. **草稿构造性不可见**：任意智能体普通读取路径（检索、导航、状态、语义工作）枚举与返回均不出现草稿；授权工作项在授权期内可读所涉草稿，授权范围外读取仍零出现。
2. **晋升原子性**：草稿整体保存后，资产与其操作记录同事务生效，或整体未生效。
3. **遗忘覆盖**：遗忘清理同时覆盖工作状态域、窗口缓存与本地副本，绑定目标资产的草稿同失效。
4. **断窗重建**：断开并清除窗口本地状态后重连，五面全部从权威重建，无只在窗口成立的状态。
5. **双轨批准一致**：会话内呈现与窗口呈现同一待决队列，任一处决定后另一处即时受约束，不出现两份可各自批准的状态。

## 四、执行单元

按以下顺序实施，每个单元完成实现、必要验证和审查修复后关闭；全部单元完成才代表本需求交付。开始实现前固定正式基线版本、对照材料及执行条件，保留可恢复版本与证据；复用已有前置验证和有效材料，仅重验实际受变更影响的内容。新增面在整体验收通过前不默认启用，各单元同步其实际改变的契约与现状文档。

核实推翻既有依赖断言、需要修改已过门架构的机制句时，先按协作规范 §3.13 对改写部分做轻量架构复审并登记裁决，再实施依赖该改写的代码；实现方不能自行修改后以代码测试代替架构复审。

### 单元一：权威基座扩展——物主工作状态域与操作账本

目标：草稿在权威基座耐久存在、构造性不可见、可安全晋升；资产类变更与待决形成完整投影数据源。

- [x] 实现草稿工作状态域（同库同事务、独立状态域）：创建、追加、编辑（句柄与条件提交防护并发）、一次性授权工作项读写、晋升（创作＝create、编辑＝条件 update 双形态映射）、弃稿删除不留痕、闲置保留、随库备份迁移、目标资产遗忘时绑定失效。
