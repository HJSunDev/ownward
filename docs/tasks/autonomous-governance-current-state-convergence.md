# 自主治理运行时当前态收敛

> **状态**：已完成。
> **职责**：将自主治理运行时从历史流水式持久化收敛为三个固定当前态文件；只改变治理运行时的内部持久化，不改变自主治理关系或 Ownward 产品。

## 二、必须完成的功能变更

- [x] **固定当前态边界**：日常运行只以 `state.json`、`review-request.json` 和 `review.json` 承载当前状态，不再生成历史 Review 目录或追加事件流水。
- [x] **统一原子生命周期**：三个文件分别按职责校验并原子覆盖；新请求使旧反馈失效，反馈校验通过后覆盖当前反馈，主 Agent 的回应和下一验证点进入 `state.json`。
- [x] **消除历史依赖**：恢复、触发、失败修复、完成判定和迁移幂等均不得依赖历史 Review 或事件重放；仍影响当前执行的事实直接存在于 `state.json` 或有效证据中，迁移幂等只使用明确迁移标记。
- [x] **无损迁移与清理**：保留现有有效目标、进展、证据、检查点、当前请求、当前有效反馈和主 Agent 回应；迁移成功并验证后，清理活动运行目录中的旧历史 Review、事件流水及其失效引用，不误删产品资产或关键工作留痕。
- [x] **实现与资产一致**：同步治理运行时源码、Schema、CLI、Hook、可复用模板、直接说明和测试，不能留下继续生成旧结构的入口或只改文档不改实现的假收敛。
- [x] **完整验证**：通过定向单元测试、治理运行时完整自检、构建、旧状态迁移验证和隔离冷启动，证明中断恢复、复核交互、失败开放与现有治理能力均未退化。

完成证据：治理模块完整测试、`go vet`、CLI 构建和隔离 `doctor` 自检通过；现有运行状态已由 `current-state-v1` 幂等迁移，原运行身份、执行焦点、有效证据、当前请求、当前反馈和主 Agent 回应保持一致，活动目录中的旧事件流与历史 Review 已清理；真实临时 Codex 冷启动正常加载 Hooks，普通消息未改变治理状态且未留下会话记录。

## 三、完成边界

- 三个当前态文件的职责、原子覆盖方式和生命周期与两份任务依据完全一致。
- 日常运行不再创建 `reviews/`、`events.jsonl` 或等价历史存储，也没有依赖这些历史恢复状态的代码路径。
- 有效现状无损迁移；旧流水和失效文件只在新状态验证成立后清理，迁移可重入且不会重复破坏状态。
- Governor 仍只提供顾问反馈，主 Agent 仍掌握执行决定；自然边界、幂等触发、普通消息隔离、单一治理支线和失败开放保持不变。
- 不新增轮转、摘要、归档、事件溯源或第二套记忆系统；长期结论继续由项目既有关键工作留痕体系负责。
- Ownward 产品代码、产品架构、模块职责、正式能力和用户数据均未改变。
- 本任务不运行 Ownward 产品正式验收，不执行 `git add`、`git commit`、历史改写或 `git push`。
