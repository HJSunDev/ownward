# 关键工作留痕

本目录是长期自主工作历史的稀疏索引，只保留真正影响后续工作的关键事实和判断，不承担工作日志职能。

## 文件组成

```text
records/
├─ README.md                    — 体系规则与分卷索引
└─ work-log-NNNN.md             — 每 50 条递增的统一工作留痕分卷
```

## 记录准入

只有删除一条记录会导致后续智能体误判关键方向、重复高成本错误，或无法确认重要阶段状态时，才允许记录；无法证明必要性时默认不记录。

1. **关键进展**：完成了改变项目阶段或后续工作起点的结果。
2. **关键决策**：确定或改变了产品、架构、技术方向、项目结构、质量或交付边界。
3. **关键问题**：形成了会改变后续路径或可避免重大重复损失的根因判断与解决方案。

关键决策在结论确定时记录，关键进展和问题解决在结果明确后记录。同一事项只保留一条记录，不因同时属于多个类型而拆分；只有结论或影响发生实质变化时，才新增关联记录。尚未解决但已经阻断后续工作的关键问题可以提前记录一次。例行操作、普通故障、局部实现、格式调整、重复验证及可由代码或文档直接还原的内容不记录。

## 不可变规则

1. 记录只能追加到当前分卷末尾，不得修改、删除、覆盖、重排或重新编号。
2. 错误、推翻、补充和替代均新增记录并引用原编号，原记录永久保留。
3. 编号采用全局连续的 `R-NNNNNN`，跨分卷递增且不得复用。
4. 实质性规则变化先新增决策记录，再更新本文件；不得借规则更新改写历史。

## 内容要求

1. 内容必须凝练、简洁、清晰；单条正文不超过 300 个汉字，标题和证据路径不计入。
2. 留痕只写结论及其不可缺少的依据和影响，不复制需求、设计、代码、日志或验证报告；详细内容只引用权威来源。
3. 没有信息增量的字段直接省略，不为格式完整填充废话；不得写入密钥、凭证和个人敏感信息。

## 分卷规则

1. 每卷记录 50 条，按 `work-log-0001.md`、`work-log-0002.md` 递增；当前卷写满后，仅在下一条记录产生时创建新卷。
2. 新卷从上卷的下一全局编号开始，并在本文件末尾追加一行索引；既有分卷和索引不再修改。
3. 处理当前任务时只读取索引、当前分卷及被引用的历史记录，不无差别载入全部历史。

## 记录格式

```markdown
## R-NNNNNN｜关键进展/关键决策/关键问题｜标题

- **时间**：YYYY-MM-DD HH:mm（Asia/Shanghai）
- **结论**：必须保留的结果、决策或问题解决方案。
- **依据**：仅在结论无法自行说明时填写。
- **影响**：仅在会约束后续工作时填写。
- **证据**：相关记录编号或权威文档、代码和验证位置。
```
