# 关键工作留痕 0001

> 本卷自 R-000001 起，只能在末尾追加记录，不得修改、删除、覆盖、重排或重新编号既有内容。

## R-000001｜关键决策｜第一版技术骨架

- **时间**：2026-08-18 10:25（Asia/Shanghai）
- **结论**：第一版采用 Go 构建轻量单二进制核心；长期信息资产使用可独立理解的追加式 JSONL 事件流，组织关系、索引与向量均为可重建派生状态；统一核心与 MCP 接入分离，模型能力通过可替换接口提供。
- **依据**：资产与内核独立、统一契约、语义关系图、前沿检索和轻量运行必须同时成立。
- **影响**：任何索引、模型、接入协议和数据库都不得成为信息资产的唯一载体。
- **证据**：`docs/architecture/overview.md`、`docs/delivery/first-version-delivery-definition.md`

## R-000002｜关键问题｜验收输入泄漏组织答案

- **时间**：2026-08-18 11:05（Asia/Shanghai）
- **结论**：固定基线 v1 把信息类型作为产品输入，违背“组织复杂度内化”并会造成假通过；保留 v1，新建 v2 将类型移入独立金标，产品仅接收内容与明确场景。
- **影响**：第一版完成判定只使用 `benchmarks/acceptance/v2/`；后续基线错误同样以新版本纠正，不改写历史。
- **证据**：`benchmarks/acceptance/README.md`、`benchmarks/acceptance/v2/`

## R-000003｜关键问题｜类型金标缺少完成阈值

- **时间**：2026-08-18 11:15（Asia/Shanghai）
- **结论**：v2 已将信息类型改为独立金标，却未规定通过阈值，无法作出完成判定；保留 v2，新建 v3，在查看产品结果前固定类型准确率为 90%，其余验收输入和标准不变。
- **影响**：第一版完成判定改用 `benchmarks/acceptance/v3/`。
- **证据**：`benchmarks/acceptance/v3/`

## R-000004｜关键问题｜固定基线未覆盖更新一致性

- **时间**：2026-08-18 15:05（Asia/Shanghai）
- **结论**：v3 只验证信息首次进入体系，无法证明更新后身份、明确语义和既有关系仍然一致；保留 v3，新建 v4，在查看模型结果前固定一项跨关系更新，其余输入、金标和阈值不变。
- **影响**：第一版完成判定改用 `benchmarks/acceptance/v4/`。
- **证据**：`benchmarks/acceptance/v4/`

## R-000005｜关键问题｜外部智能体检索证据绕过核心

- **时间**：2026-08-18 14:33（Asia/Shanghai）
- **结论**：仅检查答案会把智能体直接读取数据文件误判为 Ownward 主动检索；正式主动检索适配改为必须从运行事件证明成功调用 Ownward MCP，且不得出现旁路命令读取。
- **影响**：外部智能体接入验收必须以核心工具调用证据为准，答案正确不能替代路径真实性。
- **证据**：`benchmarks/longmemeval_v2/ownward_memory.py`、`internal/adapter/mcpserver/server.go`

## R-000006｜关键问题｜资源验收测错进程

- **时间**：2026-08-18 14:34（Asia/Shanghai）
- **结论**：原性能门槛测量验收器自身，掩盖了发布进程十万条数据下 1078 MiB 的真实 RSS；改为发布二进制加载生产格式数据后采样，并在常驻服务启动后释放重放临时内存，实测降至 645.6 MiB。
- **影响**：资源完成判定必须绑定发布二进制、固定数据、阈值摘要和候选版本，测试进程近似值不得替代。
- **证据**：`internal/performance/run.go`、`.tmp/performance-100k.json`

## R-000007｜关键问题｜完成报告未闭合底层证据

- **时间**：2026-08-18 15:24（Asia/Shanghai）
- **结论**：仅信任验收摘要会允许报告与候选、固定数据或原始运行材料脱节；完成判定改为绑定发布二进制、完整固定基线、外部智能体工具轨迹，并用固定版本官方代码重验 LongMemEval 完整材料及最终归档。
- **影响**：摘要通过不再构成完成证据，底层材料缺失、变化或无法复核均不通过。
- **证据**：`benchmarks/agent_integration/`、`benchmarks/final_acceptance/`、`internal/candidate/`

## R-000008｜关键问题｜公开前沿的外部智能体条件不等价

- **时间**：2026-08-18 16:16（Asia/Shanghai）
- **结论**：主动检索原配置使用 `gpt-5.4` 且未固定 Codex CLI，会使 LongMemEval-V2 前沿比较失真；改为官方条件的 Codex CLI 0.117.0、`gpt-5.4-mini` 与 `xhigh`，并将版本、模型、二进制和运行证据绑定到正式报告。
- **影响**：任何其他 Codex 版本、模型或推理强度生成的主动检索结果均不能用于第一版完成判定。
- **证据**：`benchmarks/longmemeval_v2/`、`benchmarks/final_acceptance/verify.py`

## R-000009｜关键进展｜资源前沿形成可复现闭环

- **时间**：2026-08-18 18:44（Asia/Shanghai）
- **结论**：资源验收固定以公开同类系统 total-agent-memory 12.4.0 的官方源码同机复现为基线；Ownward 在十万条、384 维等价负载下已同时领先程序体积、CPU、内存、存储、持久写入、基础可检索和语义检索内核时延。
- **影响**：后续正式候选必须重新生成并绑定同一口径的双方原始报告，任一指标落后均不通过。
- **证据**：`benchmarks/resource_frontier/`、`internal/performance/run.go`、`internal/derived/store.go`

## R-000013｜关键问题｜外部智能体验收动作存在语法歧义

## R-000014｜关键问题｜固定关系增益阈值不可达

- **时间**：2026-08-19 12:09（Asia/Shanghai）
- **结论**：v4 的全部关系查询在关闭关系扩展时前十名召回率已为 100%，正召回增益的数学上限为 0，却要求至少 0.05；保留 v4，以 v5 仅撤销该无效阈值，其余输入、金标、查询和阈值不变。实际检索增益继续由 LongMemEval-V2 主动与直接检索对照验证。
- **影响**：第一版固定产品验收和最终汇总改用 `benchmarks/acceptance/v5/`，不得通过降低无图检索质量制造增益。
- **证据**：`.tmp/final-a7863d1/product-report.json`、`benchmarks/acceptance/v5/`

## R-000015｜关键决策｜关系增益改按正确证据覆盖验证

- **时间**：2026-08-19 12:18（Asia/Shanghai）
- **结论**：R-000014 中把不可达阈值直接撤销仍会遗漏“组织关系必须改善检索”的要求；v5 最终改为计算关系图相对无图检索新增的正确关系证据覆盖，继续保持 0.05 的增益门槛，不以降低标准解决基线错误。
- **影响**：固定产品验收必须同时通过关系精确率、召回率、关系检索证据质量和图证据增益；LongMemEval-V2 继续验证完整主动检索前沿。
- **证据**：R-000014、`benchmarks/acceptance/v5/`、`internal/acceptance/run.go`

## R-000016｜关键决策｜分离回归验证与未见验收

- **时间**：2026-08-19 13:46（Asia/Shanghai）
- **结论**：v5 已参与实现诊断与调优，继续作为固定回归基线，但失去最终未见验收资格。第一版完成由固定回归、候选冻结后生成的动态未见数据和公开前沿基准共同证明；依据动态数据修复后必须形成新候选并重新生成未见数据。
- **影响**：产品目标与需求不变；架构明确分离通用语义判断和确定性结构保障，最终验收不得再以已参与调优的固定数据证明通用性。
- **证据**：`benchmarks/acceptance/v5/`、`.tmp/final-50238d0/product-report.json`

## R-000018｜关键问题｜语义模型凭证阻塞属于误判

- **时间**：2026-08-20 12:19（Asia/Shanghai）
- **结论**：R-000017 记录的凭证不可用事实成立，但将其推导为主线阻塞不成立；OpenAI 兼容端点只是当时验收实现的具体依赖，不是 Ownward 的产品前提。外部智能个体可通过稳定边界参与语义工作，无需用户为继续开发另行提供 API Key。
- **影响**：不得再以缺少特定模型服务或凭证阻断主线；后续实现与验收必须保持语义能力可替换，不把 Ownward 绑定到具体智能体、模型服务或协议。
- **证据**：R-000017、`docs/product/requirements.md`、`docs/architecture/overview.md`

## R-000019｜关键决策｜第一版本地向量模型确定

- **时间**：2026-08-20 12:19（Asia/Shanghai）
- **结论**：第一版采用 Google EmbeddingGemma 300M 的 Q8 GGUF，配合 llama.cpp `b10488`、2 线程和 512 维输出，作为本地语义表示与向量召回能力；它不独立决定最终组织与检索质量，内核仍负责融合全部证据并形成结果。
- **影响**：主线按该方案逐步完成模型接入、集成验证和最终交付；不得以其他候选或旧测试模型替代而不重新形成决策与证据。
- **证据**：`docs/research/vector-model-selection.md`、`docs/research/vector-model-selection-research.md`、`benchmarks/vector-model-evaluation/`

## R-000020｜关键问题｜最终验收存在未核算的规模放大

- **时间**：2026-08-20 14:33（Asia/Shanghai）
- **结论**：LongMemEval-V2 Small 的 451 个问题各自引用 100 条轨迹，当前适配器逐题重建时至少触发 1,170,518 次 `create`，该执行路径不可行且不是公开前沿证明本身的要求；正式验收保留唯一必要的 `active` operating point，复用不接触答案的查询无关语义结果，并在全量前完成成本预检。
- **影响**：高成本批量任务必须先证明规模必要并实测推算完整成本；十万条内核容量验收不得转化为十万次模型推理，检索编排只在具体替代方案可能改变结论时增加定向对照，未变化的对标系统报告可以复用。Ownward 不读取的 5.51 GiB 轨迹截图不再属于验收准备。
- **证据**：`benchmarks/longmemeval_v2/README.md`、`benchmarks/resource_frontier/README.md`、`docs/delivery/first-version-delivery-definition.md`

## R-000021｜关键决策｜动态未见验收改为最小有界正式路径

- **时间**：2026-08-20 15:18（Asia/Shanghai）
- **结论**：动态未见验收是防止固定样本过拟合、证明开放信息组织能力的必要证据，保留统计规则要求的最小 24 个有效场景；旧执行器绑定过时模型服务并累计多个无依据长超时，不构成有效完成路径。正式验收改为发布默认运行方式，组织与智能体时效分别绑定既定产品阈值和公开前沿，完整/无关系条件复用同一冻结状态并成对并行。
- **影响**：动态验收不得要求用户提供 OpenAI 兼容端点或使用测试向量空间；异常运行必须失败并从有效检查点恢复，不能靠延长等待完成，也不能以控制成本为由删除动态证据。
- **证据**：`benchmarks/acceptance/dynamic/`、`benchmarks/final_acceptance/`、`docs/delivery/first-version-delivery-definition.md`
