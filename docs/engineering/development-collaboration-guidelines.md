# 开发规范

## 代码设计

以满足当前需求的最简单完整方案实现。保持职责内聚、边界清晰、依赖单向和权威唯一；隔离可替换实现，不为未来可能预建抽象。涉及信息内容含义的能力，应通过可替换的通用语义机制实现；不得为特定领域、表述方式或验收样本堆叠语义判断规则。

## 代码质量

代码应当直接、清晰并符合所选语言的官方惯例。错误必须明确处理，状态变化必须保持一致；注释使用中文，只解释代码无法表达的原因和约束。

## 代码验证

任何行为变化都必须由有效测试证明。开发与修复过程中只运行能够完整覆盖当前变更的最小验证，复用未失效的结果；失败先定向归因，只重跑受影响范围。交付物稳定且定向验证全部通过后，才在同一输入上执行一次完整验证。

任何尚无可靠成本数据的批量任务，必须先用最小代表性样本实测单位成本，推算完整耗时、调用量、存储和外部费用，并证明计划规模不能由更小的等价证据替代；总成本不可接受或实际进度明显偏离推算时立即停止并调整方案，不得先启动再被动等待。

必要验收必须完成，停止异常运行不能替代结果。执行边界应优先来自固定工作量、产品质量阈值和既有前沿；独立对照应复用未变化的状态并在安全时并行。不得用彼此独立的宽松超时累计出长任务，也不得以缩短时间为由删除必要证据。

完成前必须通过适用的格式化、静态检查、测试和构建；性能关键设计必须以真实测量为依据。
