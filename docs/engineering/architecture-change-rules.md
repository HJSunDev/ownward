# 架构变更约束

用于设计、实现和审查跨组件变更与能力替换，将[架构演进方向](../architecture/evolution-direction.md)落实为契约、状态和验证边界。本文规定变更应满足的条件，不代表这些替换机制已全部实现；当前能力与限制以[Ownward 架构概述](../architecture/overview.md)为准。

## 契约与依赖

- **按真实变化划边界。** 职责、状态和生命周期决定边界；主体、能力与适用条件等独立变化的关系分别表达，不按角色称呼或固定场景表绑死，也不为未明确的组合预建抽象。
- **跨可替换边界依赖稳定契约。** 契约表达产品语义，调用方不依赖另一实现的私有类型、存储布局或模型协议。显式装配选择能力组合和产品模式，先验证资产、能力、派生格式及版本是否兼容，不让构造默认值暗中改变产品语义。
- **状态归属先明确。** 新状态须说明它属于长期资产、权威控制、物主私有工作、派生数据还是运行／宿主工作状态，以及谁保存、如何恢复和失效；不能明确时先补齐职责设计。权威控制只承载不能从资产和装配清单安全推导的产品决定，个人信息和算法私有状态不因持久化就成为控制权威。
- **契约变化显式处理。** 兼容变化保持既有调用方可用；破坏性变化采用新版本并明确迁移，不让适配器猜测含义或通过静默降级维持表面兼容。
- **逻辑边界不强制物理拆分。** 默认采用进程内直接调用，跨进程或网络边界须有资源、故障隔离或部署依据；组件有独立身份不要求各自成为文件或进程，也不以无损替换为理由预建任意代码热插拔或通用插件体系。

## 能力替换

接入、外部语义、向量模型与空间、组织、检索、派生存储、长期资产存储及完整内核的替换，都按实际受影响的状态处理；同一变更涉及多类状态时分别满足相应条件。具体变更须先核实当前实现实际提供的切换与恢复能力；缺少必要能力时先补齐并验证，不能直接在活动资料上套用目标流程。

| 替换涉及的状态 | 必须满足的条件 |
| --- | --- |
| 无持久状态的能力，如未改变持久状态的接入适配或检索算法 | 不改变资产、控制及未受影响的派生状态；候选通过契约、权限和端到端集成验证后，在安全边界切换。观察成立前保留旧实现，不为无状态调用制造数据迁移。 |
| 可重建的派生状态，如语义组织、向量空间、索引或派生存储的变化 | 从明确的资产基线建立隔离候选，核实来源、结构、向量空间及格式的组合一致性，验证增量、恢复、质量、时效和资源影响；候选不改权威资产与控制，不污染当前有效结果，完整验证后再切换。 |
| 权威持久状态，如长期资产与控制存储的替换 | 复制并验证资产及全部不可重建的控制、工作状态，保持身份、内容、明确语义、权限与删除边界及恢复能力；原子转移唯一写入权，旧源仅作只读回退源，不能用长期双写维持两个权威。 |

涉及持久状态时，切换前须追平已接受的变更，并通过短暂写入屏障或等价机制关闭最后的版本间隙，在同一有效状态上原子切换；做不到就不得切换。回退目标也须先追平当前有效状态并通过健康与一致性验证，不能丢失已接受的信息、撤销或遗忘决定。权威基座可升级，但不作为任意插件装卸。

可替换性须以候选独立准备、验证、受控切换、观察、回退及失败恢复的完整生命周期证明，不能仅凭存在接口宣称成立。准备失败不影响当前能力；切换可以包含明确的受控暂停，不要求零停机。具体要求按受影响模块核验；涉及内核候选晋升时遵循[内核持续演进体系](kernel-evolution-system.md)，验证层级与触发条件遵循[验收体系](../delivery/acceptance-system.md)，不把每次组件替换都扩大为整轮内核评测。

## 外部智能适配

等价更换外部智能实现只调整适配器、显式装配、配置及资格证据，不修改生成、语义组织、回答、裁判、评分或恢复编排来迁就某个实现。无法保持合同的变更应按能力或业务变更重新设计、验证，不能冒称等价替换。

请求与证据须能对应到调用契约、供应商、模型、推理档位、执行制品、工具清单、超时／重试策略和并发隔离条件。密钥、凭据等认证秘密不得写入组件身份或证据；适配器差异不能掩盖实际调用条件。具体角色资格与等价性核验遵循[验收体系](../delivery/acceptance-system.md#验收证据)。

## 制品身份与验证边界

组件身份由自身内容及真实直接依赖决定，组合身份记录所选组件及其兼容关系，Git 提交仅作开发来源。同一发布包可包含多个组件身份；打包或无关组件变化，不能冒充未变组件自身的变化。

证据分别绑定被测候选、输入、执行环境和观察者。评测工具也是独立制品：只改变评测工具或评测环境，不改变被测产物身份，但影响相应证据的适用性；若同时改变了产物内容或运行所需的真实依赖，则按实际影响处理。

证据失效沿真实依赖传播，只重验受到影响的部分。以下用于判断跨组件影响，不是按目录名称豁免验证的清单：

| 变更边界 | 需要重新判断的证据 |
| --- | --- |
| 接入、协议或宿主适配 | 对应接入、身份权限、安全与端到端集成；未受影响的内核证据复用。 |
| 内核能力 | 该能力及依赖它的内核、产品结果；独立且未变的能力不跟随失效。 |
| 语义能力、模型或向量空间 | 受其影响的组织、派生世代、检索与使用结果；未受影响的原始资产证据不重做。 |
| 资产契约、权威控制或持久化 | 资产身份与内容、授权与遗忘、迁移恢复及受影响的完整产品不变量。 |
| 无关文档、工作台或评测工具 | 不因仓库变化使产品或内核证据失效；观察方式发生变化时，重新判断依赖该观察的证据。 |

其他组件变更若实际触及资产、权限或恢复保证，同样核验相应不变量；不能以“不属于权威基座改动”为由跳过。组件证据仍有效，不等于新组合已经通过集成或兼容验证。具体执行阶段、门槛与复验规则以[验收体系](../delivery/acceptance-system.md#验收证据)为准，不另建一套验收流程。
