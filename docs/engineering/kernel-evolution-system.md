# 内核持续演进体系

本文档负责维护Ownward 内核长期产生、验证和晋升更优实现，是内核持续优化的统一工作方法。

## 决定信息内核效果的核心因素

Ownward 要优化的对象是**信息组织与检索内核**。它的效果来自从信息进入体系到证据交给外部智能体的完整技术链路，不由某一种索引、模型、编程语言或搜索算法单独决定。检索质量要求相关信息能够被完整召回、正确排序、按当前时间与场景适用并作为充分证据交付；检索效率同时包括可检索时延、查询时延、组织与索引维护成本、重建成本及资源占用。

| 技术方向                     | 优化方向                                                                                                                                                 | 影响                                                                                                                           | 优化优先级                   |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ | ---------------------------- |
| **信息表示与组织结构** | 优化信息单元颗粒度、稳定身份、来源、时间、版本、冲突、场景及关系模型，使跨时间、跨会话和多跳事实既不割裂也不错误合并。                                   | 直接决定内核实际拥有怎样的可检索知识，能够同时提高召回、关系推理、更新正确性并减少索引噪音，是质量上限的基础。                 | **最高：核心优化层**   |
| **检索架构与算法**     | 优化查询约束表达、多路候选召回、路径选择、过滤、关系扩展、分数校准、融合、重排、去重、多样性及证据交付，使正确证据既能进入候选集又能稳定排到前面。       | 直接决定“能否找全、选对并交付”，通常对端到端质量影响最大；更好的路径选择还能减少无效召回和读取，同时提高效率。               | **最高：核心优化层**   |
| **语义能力与表示模型** | 优化开放语义工作的输入与结果契约、向量与其他语义表示、查询—信息对齐、跨语言表达、关系与时间语义，使不同表述能够形成可靠且可替换的语义证据。             | 能显著抬高语义召回和组织质量上限，但模型调用、表示维度和推理复杂度也会影响沉淀成本、索引规模和响应速度。                       | **高：核心优化层**     |
| **数据结构与存储架构** | 优化倒排、向量、关系、时间和场景索引，数据布局、增量更新、缓存及冷热分层，使更多有效检索能力能够在真实长期资产规模下成立。                               | 主要抬高延迟、吞吐和规模上限，也会通过允许更广召回、更及时更新和更复杂融合间接提高质量。                                       | **中高：规模与效率层** |
| **执行架构与状态维护** | 优化在线与离线边界、并发、批处理、增量计算、数据复制、序列化、派生世代构建、原子切换及故障恢复，消除链路中的重复工作和等待。                             | 主要提升端到端效率、资源和新鲜度；只有测量证明执行链已经限制检索策略或组织质量时，才上升为核心优先级。                         | **中：证据驱动层**     |
| **实现技术与计算基础** | 在现有实现中优化热点路径、内存布局、分配与回收、编译、系统调用、本地推理和硬件利用；只有不可消除的运行时瓶颈得到证明时，才评估编程语言或基础运行时替换。 | 编程语言和硬件能够抬高性能下限，但很少单独改变检索质量上限。当前 Go 已提供高效、可维护的基础，第一版不以语言迁移作为优化方向。 | **低：基础保障层**     |

## 目标

每个大版本必须使信息组织质量、检索质量和端到端效率相对当前基线形成整体跃升，且每个方向都在自己的主要作用指标上取得大幅改善。上升型核心指标优先争取至少翻倍，下降型错误、时延或资源优先争取至少减半；处于高基线时使剩余错误超大幅收敛。改善没有上限，小幅变化不构成方向迭代或大版本完成。

## 基线与边界

体系始终只维护一个当前有效内核基线。新方案先作为候选与它使用相同资产、输入、环境和评价边界竞争；未经验证不得覆盖基线或成为后续工作的隐含前提。

- 长期信息资产、稳定身份、明确语义和统一能力契约不因内核迭代而改变。
- 组织状态、关系、索引和检索表示属于可重建的派生状态；候选失败不得损坏资产或当前有效世代。
- 外部智能体继续负责主动检索方向、累计证据判断和结果组织；内核负责提供可组合的高质量检索能力，不内置替代外部智能体的检索智能。
- 不针对验收题目、答案、题型或表面形式增加规则，不以降低质量、缩小信息范围、隐藏成本或改变评分口径制造提升。
- 质量、时效和资源分别评价，不能相互补偿；架构复杂度必须由可验证收益证明。
- 当前大版本不更换 Go 或基础运行时；只有证据证明基础设施阻断上层优化时，才单独立项处理。

## 大版本迭代

一个大版本必须完成以下五个方向的一次有效迭代：

1. 信息表示与组织结构。
2. 检索架构与算法。
3. 语义能力与表示模型。
4. 数据结构与存储架构。
5. 执行架构与状态维护。

实际顺序按依赖、优先级和证据调整，但任何方向都不能省略。跨层失败只归入首个可证根因所在方向；同一方案可以改善多个方向，但必须分别通过各方向证据，不得重复实现同一根因。开始前依据实测成本形成最短关键路径；正常路径仍会把一个大版本拖成多日工作时，必须先重构迭代与调度方式。

每个方向只有在专属快速优化视图证明主要指标大幅改善且受保护能力没有退化后才能关闭；五个方向全部关闭，才形成大版本候选。

## 方向专属快速优化集

体系维护一份版本化的内部优化语料库、执行入口和证据链；每个方向从中冻结符合自身验证需求的专属快速优化视图，不建立五套平行体系：

| 方向 | 快速证据入口 |
| --- | --- |
| 信息表示与组织结构 | 身份、关系、合并拆分、增量一致性与组织阶段。 |
| 检索架构与算法 | 词法、向量、关系、场景与融合阶段。 |
| 语义能力与表示模型 | 固定语义工作、模型与结果契约，评价输出质量和成本；输出冻结后再验证下游组织与检索。 |
| 数据结构与存储架构 | 重建不变量，以及组织、索引阶段的时延与资源。 |
| 执行架构与状态维护 | 状态、恢复和故障夹具，以及受影响阶段的端到端时延与资源。 |

- 每轮以当前基线最近一次完整正式测试的全部错误为问题池，按首个可证根因聚类并分配到负责方向，保留“正式失败—通用机制—优化方向—内部样本”的可追溯关系；每类只选覆盖主要失败机制的最小代表集，不挑选容易改善的有利样本，跨方向共用的保护样本只保存一份。
- 社区基准样本只用于定位通用缺陷；代表失败必须转化为事实、答案和表面形式均不重合的内部等价样本及反例，不复制公开题目或形成测试特判。
- 每个视图复用 Acceptance Suite 已有阶段和证据权威；语义方向在冻结输出前单独评价外部语义能力，不改变内核前沿基准冻结语义输入的边界。开发前冻结输入、真值、评分器、当前基线、主要指标、跃升门槛和受保护能力，候选与基线运行完全相同的内容。
- 单个确定性定向视图不得超过三分钟；一个方向包含语义调用、全部必要视图和保护检查的快速验证以五至七分钟为目标、最多十分钟。只重跑受影响部分，保留有效检查点和分阶段证据。

## 单方向闭环

1. **归因**：聚合失败并沿完整链路定位首个可证根因，区分现象、根因和下游损失，只把问题交给真正负责的方向。
2. **定标**：建立或校准专属快速优化视图，冻结基线结果、主要指标、受保护能力、跃升目标和淘汰条件；没有真实基线与成本证据时不得进入实现。
3. **设计**：从第一性原理选择能够消除根因的最优架构，不以最小改动、旧实现兼容或已投入成本限制方案。
4. **实现**：建立可独立验证的候选，保持长期资产和当前有效基线安全。
5. **快速迭代**：反复运行专属快速优化视图，只根据分阶段证据修复真实瓶颈；一次快速验证不是工作包边界，执行者持续工作到方向门槛或真实交接点；失败候选直接淘汰，不向主架构叠加补丁。
6. **关闭方向**：候选达到跃升目标、受保护能力无实质退化且结构无已知债务后，冻结该方向结果；结论同时绑定候选与视图，后续变更影响其依赖时自动重新打开。

## 持续调度接口

协调者负责大版本整体进度、方向选择、候选裁决和工作包连续性，执行者负责完成工作包内的设计、实现和验证。协调者每次派发前必须读取当前基线、大版本状态、快速优化证据和上一工作包结果，只选择当前方向中价值最高的一条完整问题链。

每轮开始时建立唯一大版本任务文档，只维护上一基线、当前最佳候选、五个方向的视图、门槛、状态与证据，以及当前根因和下一验证点；机器证据仍由 Acceptance Suite 唯一保存，任务文档只引用，不复制。

每个工作包必须写清当前方向与基线、要消除的根因、使用的快速优化视图、跃升目标、受保护边界、完成证据和明确排除项，并允许在边界内连续完成多轮快速验证。工作包结束后，协调者独立复核证据；未达到方向门槛就继续同一方向，达到后才切换方向。执行过程暴露的有效经验进入后续工作包，不把过程日志写入本体系。

## 大版本与最终验证

五个方向的关闭证据必须同时对同一最终候选有效；后续变更只重新打开受依赖影响的方向。全部有效后，使用同一基线和候选运行内核前沿基准完整模式及固定资格验证。只有证据证明信息组织质量、检索质量和端到端效率形成整体跃升、所有受保护能力无实质退化，才能结束大版本；否则重新打开造成差距最大的方向，继续快速迭代。

大版本通过后冻结唯一最终候选，按[验收体系](../delivery/acceptance-system.md)完成内部验收；达到可运行最终社区基准的条件时，持续调度停止并向用户报告。最终验证启动后只对该候选运行一次完整 LongMemEval-S。大版本未通过时不得消耗数小时社区基准；最终验证发现的缺陷必须抽象为通用能力问题并进入内部优化语料库，不以反复运行全量基准代替定位和修复。

验收体系中的基线身份和证据是晋升事实的唯一权威。每轮大版本状态由任务文档承载，关键决策进入[关键工作留痕](../records/README.md)，已晋升实现进入[检索体系演进](../modules/retrieval/README.md)；本文不记录实验过程和临时进度。
