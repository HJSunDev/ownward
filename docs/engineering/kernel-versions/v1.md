## 实现

| 方向 | V1 实现 |
| --- | --- |
| 信息表示与组织结构 | 长资产按需生成带来源身份的细粒度证据，避免整段会话直接占满上下文。 |
| 检索架构与算法 | 按来源排名和证据深度进行有界公平装载；短资产完整读取，长资产检索并读取源绑定区间。 |
| 语义能力与表示模型 | 为长资产建立语义表示，使其能够进入向量召回；继续校验语义工作身份、版本和原序提交。 |
| 数据结构与存储架构 | 派生状态升级为紧凑格式，权威日志保留当前资产快照并原子压实，重复维护只保留每资产一个当前派生记录。 |
| 执行架构与状态维护 | 批量创建和候选世代构建按事务边界合并耐久写入，校验完成后统一持久化并原子发布。 |

## 内部测试

| 范围 | 结果 |
| --- | --- |
| 核心不变量 | 资产保存、更新、备份恢复、派生重建、稳定身份、派生可销毁、模型可替换：`7/7` 通过。 |
| 内核质量（固定集） | 身份、增量一致性、合并拆分、关系精确率/召回率、图召回率、融合召回率和上下文精确率均为 `100%`；词法召回率 `97.30%`，向量召回率 `98.37%`，融合 NDCG `99.24%`。 |
| 内核效率（固定集） | 组织 P95 `0.54 ms`，索引构建 `0.81 ms`，融合查询 P95 `0.54 ms`；派生数据 `14,380 B`，索引 `529,080 B`。 |
| 产品专项 | 24 个场景全部通过，跨时间、多跳、场景适用和信息更新的召回率、精确率、NDCG 均为 `100%`；查询最长 `283.05 ms`，峰值内存 `256.00 MiB`，场景端到端最长 `15 分 28.75 秒`。 |

这些结果证明固定内部合同成立，但其开发集与晋升证据职责混淆、复杂分布和真实回归覆盖不足，不能证明端到端泛化。

## LongMemEval-S

正式测试采用官方清洗 500 题；语义与 Reader 使用 `gpt-5.6-luna`，裁判使用 `gpt-5.6-terra`。

| 指标 | 结果 |
| --- | --- |
| 总分 | `285/500`，准确率 `57.00%` |
| 单会话用户记忆 | `60/70`，`85.71%` |
| 单会话助手记忆 | `43/56`，`76.79%` |
| 多会话 | `51/133`，`38.35%` |
| 偏好 | `10/30`，`33.33%` |
| 时间推理 | `75/133`，`56.39%` |
| 知识更新 | `46/78`，`58.97%` |
| 检索时延 | 平均 `347.77 ms`，P95 `594.00 ms`，最大 `2,281.00 ms` |
| 返回上下文 | 平均 `3,042.9` 字符，P95 `3,059` 字符 |
| 正式报告墙钟 | `4 小时 55 分 30 秒` |

相对 V0，V1 有 101 道错题转为正确、58 道正确题退化，净增 43 题；多会话净增 23 题、时间推理净增 38 题，但单会话用户、单会话助手和偏好分别减少 5、13、3 题。两次正式运行的评测工具与阶段身份不同，因此这些差异只能描述结果，不能全部严格归因于内核变化。

## 判断

**长板**：搜索未返回目标证据的问题由 116 个降至 6 个，长资产语义召回、细粒度证据、批量耐久写入和存储收敛均产生真实改善；创建阶段累计耗时由 `2,750.0 秒` 降至 `705.3 秒`，Ownward 数据由 `8.65 GB` 降至 `399,536,519 B`。

**短板**：读取目标资产后仍答错由 9 个增至 140 个，说明证据片段完整性、时间与冲突裁决以及最终回答充分性严重不足；58 道既有正确题退化，检索平均时延约为 V0 的 8.4 倍。固定内部测试对局部机制代理形成满分，却没有提前发现这些端到端问题。

V1 不晋升，不替代 V0。其实现和正式结果保留为后续诊断证据；具体失败原因与方法修正见[《V1 最终测试质量偏差分析》](../../incidents/kernel-v1-final-benchmark-quality-gap.md)。
