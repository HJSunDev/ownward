# 提交规范

## 提交审视

下次提交审视时间统一保存于仓库本地 Git 配置 `workflow.next-commit-review-at`，采用 ISO 8601 格式；状态不存在时，以持续开发开始四小时后初始化。时间只在任务首次开始、暂停后恢复、上下文压缩后及主要工作阶段结束时检查，单次操作、普通步骤和工具调用不构成检查点。到达审视时间后，在当前阶段结束的第一个安全点审视现有变更；没有符合提交标准的内容时不提交。审视完成后将下次审视时间更新为四小时后。

## 提交拆分

先识别当前变更维护的架构不变量，提交边界不得切开任何不变量。每个提交必须形成可独立理解、构建、测试和回滚的终态子集，可以暂不包含后续能力，但不得处于半升级状态或依赖后续提交修复。

在上述约束内按功能边界拆分，并取能够独立成立的最大范围。属于同一不变量，或在同一类型、函数、迁移与测试中交织的变更必须一并提交；代码与契约或行为说明共同构成真实终态时一并提交。未完成或无法形成终态子集的变更保留在工作区。

## 提交确认

提交前核对实际暂存内容与目标提交边界完全一致，排除无关、临时、运行态和敏感文件。构建与测试必须针对实际提交内容，不得依靠未提交变更通过。

## 提交信息

提交信息的格式、类型与写法参考 [Git Commit 生成器的“生成规则”](../../.agents/skills/git-commit-generator/SKILL.md#生成规则)。
