# 提交规范

## 提交审视

下次提交审视时间统一保存于仓库本地 Git 配置 `workflow.next-commit-review-at`，采用 ISO 8601 格式；状态不存在时，以持续开发开始四小时后初始化。时间只在任务首次开始、暂停后恢复、上下文压缩后及主要工作阶段结束时检查，单次操作、普通步骤和工具调用不构成检查点。

除用户明确要求、到达审视时间，或实现稳定且必须冻结正式验收候选外，不得提交；普通阶段结束、局部修复或单项验证通过均不是提交时机。触发审视后，等待当前问题链闭合，在第一个安全点统一审视全部已有变更并形成一个提交批次；批次可以包含多个提交，没有符合提交标准的内容时不提交。一次审视完成后统一将下次审视时间更新为四小时后。本批未推送提交若随即暴露同一不变量的后续修复，说明终态判断失败，应重新整理该批历史，不得追加补丁式提交。

## 提交拆分

先识别当前变更维护的架构不变量，提交边界不得切开任何不变量。终态判断必须基于完整问题链和全部相关验证，不得以一次局部通过为依据。每个提交必须形成可独立理解、构建、测试和回滚的终态子集，可以暂不包含后续能力，但不得处于半升级状态或依赖后续提交修复。

在上述约束内按功能边界拆分，并取能够独立成立的最大范围。属于同一不变量，或在同一类型、函数、迁移与测试中交织的变更必须一并提交；代码与契约或行为说明共同构成真实终态时一并提交。未完成或无法形成终态子集的变更保留在工作区。

## 提交确认

提交前核对实际暂存内容与目标提交边界完全一致，排除无关、临时、运行态和敏感文件。构建与测试必须针对实际提交内容，不得依靠未提交变更通过。

冻结正式验收候选前，必须闭合当前问题链，完成最小充分验证及高成本环节的代表性预检，按终态边界完成本批提交并确认工作区干净；随后才构建绑定最终提交 SHA 的候选发布包。候选冻结后重整提交历史，将使候选及其正式证据全部失效。
