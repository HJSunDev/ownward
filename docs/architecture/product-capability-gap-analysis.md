# 产品能力差距分析

本文分析产品定位与跨设备使用能力之间的差距，保留产品目标、关键判断和源码依据；产品要求以[产品需求](../product/requirements.md)为准，完成标准以[第一版交付定义](../delivery/first-version-delivery-definition.md)为准，执行状态由[工作包待办](../tasks/information-control-and-change.md)维护。

## 产品目标与核心体验

**用户只维护一份属于自己的活动信息体系，自主选择部署位置；不同地点、不同形态的智能体经授权共同使用和补充同一份信息。** 价值在于让个人信息持续属于用户、供智能体共同使用，而不依赖某个设备或智能体持有另一份私有真相。

目标体验是：**“让这个智能体连接我的 Ownward。”** 接入准备由 Ownward 与宿主协作完成，用户只决定它是谁、允许做什么；已明确的同一决定不重复确认，不要求用户理解协议、交付凭据或管理副本。

## 长期判断

以下判断作为分析差距的依据，具体行为由对应产品与架构文档定义。

| 判断 | 必须保住的产品价值与依据 |
| --- | --- |
| 唯一体系、共同使用一致 | 各智能体在授权范围内使用同一权威及有效版本；并发修改不能丢失已经接受的更新，不要求用户维护多份信息或做多端同步。见[跨地点访问](../product/cross-location-access.md)。 |
| 部署位置自由 | 产品定义不绑定桌面、云端或某类设备；迁移后延续信息身份、控制权与使用关系，用户不必重新介绍或导入个人信息。可达性是部署条件，具体位置不是产品身份。见[跨地点访问与迁移](../product/requirements.md#跨地点访问与迁移)。 |
| 任意形态共享同一产品 | 软件智能体、机器人、车辆、无人机及未来形态遵循同一产品关系；当前发布平台和接入协议只是实现选择，新增适配不应要求改造资产或内核语义。见[接入架构边界](overview.md#十跨地点接入与迁移)。 |
| 用户参与最少、权限清楚可控 | 技术准备与后续连接由系统承担；接入者身份和权限分别明确，用户可查看、调整和撤销，普通使用不自动获得管理权。见[用户掌控信息](../product/information-control.md)。 |

共同访问不等于外部缓存自动更新：已交付材料在交接、恢复或再次使用时如何核对变化，仍由[信息随用户变化](../tasks/information-control-and-change.md#工作包三信息随用户变化)负责；接入畅通不能代替信息持续有效。

## 审查范围与结论

以下源码审查于2026-09-10基于工作包一交付提交 `57b2842` 进行，说明该基线已有能力和面向跨地点使用的缺口；后续实现状态见[工作包二](../tasks/information-control-and-change.md#工作包二跨地点访问与便捷迁移)，设计决定见[接入与迁移架构](../modules/access/README.md)。

**该基线已有独立信息资产、统一信息能力、本机多智能体共享，以及独立授权、撤销和遗忘；缺口是异地连接、管理接续及唯一活动权威迁移。** 原有能力须在新增用途下审查后复用；本机验证不能代替跨地点能力验证，设计完成也不等于能力已交付。

## 专项审查

| 使用场景与实际结果 | 源码依据 | 保留或修改的决定 |
| --- | --- | --- |
| 异地智能体连接服务时，监听和连接描述都拒绝非回环地址。 | [HTTP入口](../../cmd/ownward/main.go) `runHTTPMCP`；[共享连接](../../cmd/ownward/shared_mcp.go) `readSharedMCPDescriptor`。 | 保留本机保护；单独装配受保护远程入口，不能直接放开监听并暴露本机管理端点。 |
| 新设备建立连接前会检查本机向量资源；本机客户端还会按二进制、目录与组合身份判断是否重启服务。直接复用会让远端携带无关资源或干预现有服务。 | [命令入口](../../cmd/ownward/main.go)；[装配](../../internal/assembly/assembly.go) `PreflightSharedConnector`；[共享连接](../../cmd/ownward/shared_mcp.go) `ensureSharedMCPService`。 | 本机接入行为保留；远程连接只协商受支持协议与目标体系，不加载内核、不替换远端服务、不因失联创建私有库。 |
| 同一客户端名称在本机选择同一份保护区凭据；异地同名智能体若沿用名称分配身份，会混淆接入者。 | [宿主连接器](../../cmd/ownward/host_connector.go) `initialize`；[凭据存储](../../internal/adapter/localowner/vault.go)。 | 复用凭据保护与跨会话接续；远程连接独立登记，名称只显示，连接配置与主体显式绑定。 |
| 本机宿主通过当前 OS 账户取得所有者恢复证明；异地请求既无法读取该证明，也不能因自己弹出了确认表单就取得所有者资格。 | [本机管理](../../cmd/ownward/information_control.go) `prepareRecovery`、`recover`；[宿主恢复](../../cmd/ownward/host_connector.go) `restoreOwner`。 | 保留独立恢复通道；异地申请由已有可信管理入口批准，新主机建立自己的恢复入口，不传出源机器恢复秘密。 |
| 本机共享描述给出地址与启动令牌，没有远端证书信任、目标绑定或安全的位置更新机制。 | [共享描述及传输](../../cmd/ownward/shared_mcp.go)；[产品认证](../../internal/informationcontrol/control.go)。 | 地址与体系身份分离；可信初始化建立服务信任，验证目标后才发送主体凭据；内部认证头不能由远端声明。 |
| 请求已写入但响应丢失时，新建信息没有调用方可复用的操作标识；盲目重试会再创建一项。管理操作已经具备按操作标识接续。 | [产品输入](../../internal/contract/product.go) `CreateInput`；[新建提交](../../internal/core/service.go)；[管理操作](../../internal/informationcontrol/management.go)。 | 为可重试变更补最小耐久回执与同次提交保护，复用管理和语义工作既有身份；不能另存一份会与资产事实分歧的成功记录。 |
| 普通备份仅保存权威资产和控制，恢复会清空凭据摘要并增加主体修订；直接用于搬迁会使原连接失效，并丢掉可直接复用的组织结果。 | [权威备份恢复](../../internal/authoritysubstrate/backup.go) `Backup`、`Restore`。 | 保留历史恢复规则；迁移单独交接当前授权与兼容有效派生，不通过修改 `restore` 削弱旧备份安全性。 |
| 目录锁只约束同一存储位置；复制到另一台主机后，现有状态没有源退役与目标接管条件。 | [资产锁](../../internal/assetlog/store.go)；[控制契约](../../internal/contract/control.go)。 | 在唯一权威中补充受控交接状态，覆盖本机和远程全部入口；源退役后目标才可激活，禁止自动回退旧源。 |
| 迁移期间发生撤销、遗忘或派生提交，必须与搬迁快照保持同一有效状态；仅校验原文数量无法证明迁移完整。 | [用户控制](../../internal/informationcontrol/control.go)、[遗忘](../../internal/core/forget.go)、[派生世代](../../internal/derived/generation.go)。 | 校验资产、授权、删除与有效派生，不等待新的模型推理；普通写入暂停，用户收回控制的决定按[迁移并发规则](../modules/access/README.md#用户控制与迁移的先后)优先生效，不能一并冻结撤销与遗忘。 |

## 已有证据的复用边界

工作包一的245项测试与真实 Codex 验收见[已保存结论](../tasks/information-control-and-change.md#工作包一验收状态)。源码中已有回环拒绝、并发共享连接、授权恢复、流式备份、目标目录拒绝和安装失败保护的回归，分别位于[接入测试](../../cmd/ownward/main_test.go)、[宿主测试](../../cmd/ownward/host_connector_test.go)、[权威测试](../../internal/authoritysubstrate/substrate_test.go)。这些证据继续支持其原有职责，不外推为远程安全或迁移通过。

本审查未运行跨设备实验；后续在本机验证新增真实实现，受条件限制的场景按既定规则完成功能审查。实现范围集中于接入、用户控制扩展及权威交接，不重新设计检索、语义组织或信息使用流程。
