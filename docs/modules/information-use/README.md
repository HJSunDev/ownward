# 信息使用协作

产品定位以[产品需求](../../product/requirements.md#信息使用能力)为准，运行边界以[架构总纲](../../architecture/overview.md#信息使用层的运行边界)为准。

背景、核心思路及已验证方案的效果与取舍，统一见[信息使用能力探索记录](../../research/information-use-exploration.md)。

持续提出新机制、对照验证与取舍，遵循[信息使用探索方法](../../engineering/information-use-exploration.md)；方法服务于找到有效实现，不预设固定流程。

## 职责

外部智能体始终主导用户任务，并以自身智能执行各轮理解、推理、核验和取舍。Ownward 提供帮助它组织上下文、分配材料、衔接工作和交换依据的协作能力；不内置模型，不另设代行用户任务的智能体，也不以确定性代码判断开放语义。

信息已经取得后的处理流程是独立设计对象：可以隔离检索过程与任务执行上下文、分配不同工作、围绕实际分歧开展定向交流。应选择真实任务中质量与成本更好的安排，不强制简单任务进入多轮流程，不预定某种工作区、判断图或固定步骤。

## 接入实现与边界

[信息使用组件](../../../integrations/python/ownward_information_use.py)是一份零依赖 Python 接入实现，由外部智能体的运行环境执行。它完整保留“忠实理解与初稿 → 有原文支持的竞争方案 → 依据原任务比较并必要修订”，随后找回比较过程中遗漏的有用结果；只有确有补充时，才在独立上下文中依据原文核验，通过后附加，既有结果不再重写。所有理解、生成和判断都由调用方的智能完成；代码只传递材料、应用明确修订及已获认可的补充，不保存长期资产，也不调用任何供应商。

标准入口为 `respond(observations, invoke)`：第一次响应同时提供协作能力说明 `OFFER`，由智能体返回当前工作与 `use_information_use` 布尔选择。简单任务直接返回，不增加判断调用；选择协作才复用当前工作进入处理流程。判断依据是任务与材料中的综合、冲突和解释取舍，不只看自报信心；代码不判断语义，也不按题号选择。

已有工具检索循环的接入方，将同一 `OFFER` 和 `RESPONSE` 契约加入原响应，再调用 `finish(observations, response, invoke)`，无需另起一次选择调用。`observations` 含原始 `task` 和带 `id`、`origin`、`content` 的全部已获 `sources`；不得用模型重述替换原文。返回 `used_information_use` 记录是否实际启动。旧的显式 `complete(observations, invoke, draft=None)` 与 `reconsider(observations, draft, reading, invoke)` 保持可用，适合由调用方明确要求协作或接续已有工作。

返回的 `answer` 为最终结果，`base_answer` 保留原有纠偏后的结果，`addition` 只含获准补充；有补充提案时，`addition_review` 留下独立判断。无缺失结果就不追加解释；补充核验只接收原始任务、原文与提案，不接收旧答案的判断，以免继承同一偏差。完整流程调用五次，有补充提案时为六次；已有初稿可省去一次。

`invoke(stage, instruction, payload, schema)` 由接入方实现，为各阶段提供独立上下文、自己的模型和既定档位、正式协作规则、结构化结果校验及过程留痕；无现成初稿时需要支持两路并发。组件不接受标答或判分，不根据结果重试，不按题号或模型选择处理路径；服务失败和无法应用的修订明确抛出，恢复由接入方沿用已有机制处理。

产品采用[能力默认接入、流程按需启动](../../product/requirements.md#信息使用能力)的使用方式，已在标准 Python 入口及[模拟接入转接](../../../benchmarks/support/information_use_flow.py)实现。关卡与最终测试共用的 Reader 在现有响应中默认提供选择，获取信息后按同一 `finish` 契约分派；仅传入实际成功返回的工具材料，不再检索，不传入标答。各处理阶段沿用 Reader 的模型、档位、正式规则和现有检查点，用量累计，最终结果另行留存。第三方智能体需要装配此 Python 接入，单独连接信息内核的 MCP 不会自动执行客户端流程；产品不内置模型。

处理实现可独立演进，调用方只依赖入口与结果契约，无须依赖内部阶段数量。当前按需路径直接完成为一次响应，选择协作为五次，有补充为六次；并非所有任务固定多轮。

## 当前效果

当前增量版在 Qwen3.8 Flash／Reader xhigh、原始材料、正式规则与判分不变的条件下，补回 112 遗漏的 $3,750 筹款归属，并明确其与关联活动总额、直接个人金额的区别；89 通过，97 尚未通过。82、114、116 保底为 3／3，最终文本与原有通过结果逐字一致；82 的无依据事件合并补充被独立核验拒绝。

本轮固定复用未改动的原版四步，新增步骤使用首次有效调用，不算独立全流程重复。十项边界测试通过，六个现场经实际模拟入口回放，与实测逐项一致；合计判分 5／6，不能据此宣称整批问题已解决或获得 500 题成绩。实现身份及逐题证据见[验收记录](../../../.tmp/information-use-product/admitted-release-verification.json)，探索取舍统一见[探索记录](../../research/information-use-exploration.md)。

## 验证依据

按需接入的工程验证：组件 13 项、公共运行器 66 项、关卡接入 14 项测试全部通过，覆盖直接返回、智能体选择协作、原工作复用、原始材料交接、规则与档位保持、用量及结果留痕。此验证证明接入行为，不把模拟测试代替真实模型的触发质量或全套题目成绩；此前六题效果仍属于显式启动的处理流程。

2026-09-07 默认入口实测：固定原始已获材料、Qwen3.8 Flash／xhigh 和正式规则，全新运行 `respond`，不强制开启。82、116 自主选择协作，114 选择直接完成，官方判分 **3／3**；116 主结果从初稿 $220 纠正为 $720。三题并行总耗时 743 秒，分别为 743、144、672 秒；未重跑检索，不外推为全场景触发可靠性。原始选择、各阶段与判分见[本轮现场](../../../.tmp/information-use-product/adaptive-core3-20260907-171544/summary.json)。

使用智能体实际取得的原始材料及原始任务，同模型、同档位比较任务完成质量与成本；推理阶段不提供参考答案、答案来源标签或判分反馈。保留首次有效结果与过程证据，结合事实复核，避免把判分波动当作能力提升。

组件迭代以已解决的 82、114、116 为[固定保底集](../../engineering/information-use-exploration.md#组件迭代基线与固定保底集)：新增收益与保底通过后可交付增量版，未关闭问题继续登记。未修改的上游可依照探索方法固定复用，不能冒充独立重复；固定 24 题属于整批问题处理完、续跑最终测试前的内核验收，当前问题与下一步见[迭代任务](../../tasks/kernel-v2-final-test-failure-analysis.md)。
