# 信息使用协作

产品定位以[产品需求](../../product/requirements.md#信息使用能力)为准，运行边界以[架构总纲](../../architecture/overview.md#信息使用层的运行边界)为准。

背景、核心思路及已验证方案的效果与取舍，统一见[信息使用能力探索记录](../../research/information-use-exploration.md)。

持续提出新机制、对照验证与取舍，遵循[信息使用探索方法](../../engineering/information-use-exploration.md)；方法服务于找到有效实现，不预设固定流程。

## 职责

外部智能体始终主导用户任务，并以自身智能执行各轮理解、推理、核验和取舍。Ownward 提供帮助它组织上下文、分配材料、衔接工作和交换依据的协作能力；不内置模型，不另设代行用户任务的智能体，也不以确定性代码判断开放语义。

信息已经取得后的处理流程是独立设计对象：可以隔离检索过程与任务执行上下文、分配不同工作、围绕实际分歧开展定向交流。应选择真实任务中质量与成本更好的安排，不强制简单任务进入多轮流程，不预定某种工作区、判断图或固定步骤。

## 接入实现与边界

[信息使用组件](../../../integrations/python/ownward_information_use.py)是一份零依赖 Python 接入实现，由外部智能体的运行环境执行。它将工作拆为“忠实理解与初稿 → 有原文支持的竞争方案 → 依据原任务比较并必要修订”，所有理解、生成和选择都由调用方的智能完成；代码只传递材料、标识候选并应用确定的文本修改，不保存长期资产，也不调用任何供应商。

调用 `complete(observations, invoke, draft=None)`，其中 `observations` 含原始 `task` 和带 `id`、`origin`、`content` 的 `sources`；每个阶段均保留全部材料。已有工作结果可通过 `draft` 复用；若已有忠实理解和初稿，可用 `reconsider(observations, draft, reading, invoke)` 衔接后续工作，不重复生成上游。

`invoke(stage, instruction, payload, schema)` 由接入方实现，为各阶段提供独立上下文、自己的模型和既定档位、正式协作规则、结构化结果校验及过程留痕；无现成初稿时需要支持两路并发。组件不接受标答或判分，不根据结果重试，不按题号或模型选择处理路径；服务失败和无法应用的修订明确抛出，恢复由接入方沿用已有机制处理。

产品采用[能力默认接入、流程按需启动](../../product/requirements.md#信息使用能力)的使用方式，调用方依据任务与材料选择处理过程。当前已实现可调用组件；标准接入中的自动装配、能力发现与启动策略尚未完成验证，不能把这项产品决策写成已实现的默认行为。[模拟接入转接](../../../benchmarks/support/information_use_flow.py)直接使用同一文件；此前未证明收益的检查与准入实验已退出该转接，原始证据保留。当前没有改动内核、正式规则、关卡与最终测试的默认 Reader。

## 当前效果

固定 Qwen3.8 Flash、Reader xhigh、原始任务与全部已获材料，新流程首次三题 3／3，同批初稿 2／3；116 从主报 $220 改为 $720，未通过臆测年份排除事实，82、114 保持正确。再用历史三个错误结果直接检验同一后续流程，三题均纠正（复用已完成的理解，非独立全流程重复）。七项边界测试通过，六个现场通过模拟入口回放，与实测输入和输出一致；本轮三题修复验证完成，但不代表 500 题分数或所有场景都已改善，完整结果统一见[探索记录](../../research/information-use-exploration.md)。

## 验证依据

使用智能体实际取得的原始材料及原始任务，同模型、同档位比较任务完成质量与成本；推理阶段不提供参考答案、答案来源标签或判分反馈。保留首次有效结果与过程证据，结合事实复核，避免把判分波动当作能力提升。

当前任务只通过 82、114、116 及必要机制对照验证信息使用改进；固定 24 题属于整批问题处理完、续跑最终测试前的验收，不属于本轮探索任务。当前结果与下一步见[迭代任务](../../tasks/kernel-v2-final-test-failure-analysis.md)，不以接口完成、调用次数或中间产物数量代替效果。
