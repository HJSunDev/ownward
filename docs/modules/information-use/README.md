# 信息使用协作

产品定位见[产品需求](../../product/requirements.md#信息使用能力)，运行职责及宿主适配见[架构总纲](../../architecture/overview.md#信息使用层的运行边界)。

正式输入及中文对照见[正式流程提示词](prompts.md)。

## 处理方式

外部智能始终主导用户任务。组件帮助它把用户目标、原文依据、未决关系和必要的条件结果组织到同一次交付中，代码准备材料、按状态衔接并原样组合结果；不内置模型，不判断开放语义。

先由外部智能只看原始需求，按日常含义明确最小取证计划；历史事实不能因问题中的预设而视为已知。取得信息后逐项回应，保留用户指定的对象、事件及操作，不把找不到的所问对象替换为相似对象。计划不充当事实，也不能替代用户需求。主动取用时，以原始需求检索，尝试读取前三条来源的首个证据片段，再由外部智能继续按需取证；所有调用经过宿主原有权限与预算，初始线索不代表资料完整。

外部智能在取证过程中识别依据与未决关系，判断任务已解决、部分解决或无法确定，再交付主结果及必要条件；代码原样呈现结果，不判断语义。检索摘要优先展示相关完整原句，证据片段可附同源、同版本且不重叠的首部原文；原证据不变，新增文本计入原阅读预算。

## 宿主接入

### 可选快速取用与接续

明确来源或局部事实可在宿主已有任务中直接读取、按需检索，省去独立需求准备和固定前三条初始读取；综合、消歧、冲突及依据范围不明时直接采用原深度流程，不先试快速路径。外部智能选择路径并判断是否足够，向量、图、权限、阅读预算和结果契约不变。

`UseSession(task, host, invoke, context=...)`提供可携带的任务状态，`run('quick')`直接进入原交付契约，`run('deep')`仅补尚未完成的需求准备；已有取证不重新种入初始材料。`checkpoint()`与`restore()`携带原始需求、需求解释、实际工具结果及`basis`、必要说明、独立笔记和累计用量。恢复前逐项核对单读及批读取得的原文；变化、撤销或无法核对的材料及依赖笔记不进入新的模型输入。原始检查点仅存于宿主私有任务空间，最多8MiB，不写入长期记忆。

宿主的`call/report/restore`必须实际执行权限、阅读与工具预算，并保留已发生的模型用量；`invoke`绑定本会话的`call`，不能在切换或恢复时重置用量。检查点只接受宿主自身保存的状态，不接受模型或其他主体提供的记录；短引用包装应继续使用原会话映射。调用方负责检查点的授权、过期清理及遗忘回收。

正式Codex连接器通过`OWNWARD_INFORMATION_USE_PATHS=v1`向已有智能体任务提供同一套路径、取证与交付契约，原生任务沿用当前对话、实际工具记录和累计成本，材料核对由既有Hook与显式检查承担：状态进入下一次任务输入，失效依据及其结论停止沿用，受控材料集移除不可用项；插件不能擦除Codex历史对话。不会额外启动一个分流模型。Python的`UseSession`供自有工具循环接入，不是Codex对话的替代运行器。新路径默认关闭；取消该变量并重连恢复原入口，已保存资料与有效组织不变。

若当前任务确实依赖未完成组织，已配置且获准的正式组织执行器提供`ownward_organize(id)`，优先接续同一待办。此工具不等待模型、不增加执行名额、不返回虚假的完成状态；尚可恢复的依赖在前台活跃时继续接续，直至真实完成、终态或原恢复预算耗尽；已经接受的语义不重做。随后用`ownward_status`核对，等待和失败计入原任务。未配置执行器时不提供该工具。

[零依赖Python组件](../../../integrations/python/ownward_information_use.py)运行在智能体宿主一侧，由宿主提供实际智能与信息内核调用。

| 入口 | 用途 |
| --- | --- |
| `FRAME`、`FRAME_SCHEMA`、`task_contract(frame)` | 独立准备最小取证计划，将计划和固定结果结构交给外部智能。 |
| `PATH_INSTRUCTIONS`、`UseSession` | 可选的快慢取证契约及可信宿主任务交接；原深度入口保持不变。 |
| `EvidenceToolSession(host, read_limit)` | 将宿主的受控取证会话呈现为短引用和批读接口；底层保留逐条权限、已观察引用及预算校验。 |
| `initial_context(query, call)` | 以原始需求准备初始线索，返回可直接交给智能体的材料；`call`沿用宿主的权限、预算及工具记录。 |
| `check_materials(materials, call)`、`reuse_context(materials, call)` | 接续前用原连接批量核对材料的来源 `basis`，返回状态或可附入下一次正常任务调用的上下文；不调用模型、不改写原文，失败和缺项保持未核实。 |
| `OFFER`、`RESPONSE` | 在宿主已有取证循环中说明交付工作及结构，保持正式规则、模型和档位。 |
| `finish(response)` | 原样组合主结果与条件结果，无须提供原文或模型调用回调。 |
| `respond(observations, invoke)` | 处理已获材料：准备任务、形成有据结果，共两次宿主调用。 |
| `complete`、`reconsider` | 保留显式使用与接续已有工作的入口；此前草稿、理解独立于原始材料，不能成为事实依据。 |

`EvidenceToolSession`的宿主提供`call`、`reset_attempt`、`report`、`restore`、`validate`、`dynamic_tools`、`instructions`及`retrieval_capacity()`；最后一项返回是否还能调用、是否还能读取。短引用在同一会话恢复时保持映射，不能绕过重新观察和权限检查；批读逐条执行，单条失败保留其他结果。

`observations`包含原始`task`及带`id`、`origin`、`content`的`sources`，不得用模型重述替代原文。`invoke(stage, instruction, payload, schema)`由宿主实现，负责自身模型调用、结构校验、用量与恢复；原任务的日期等必要上下文及连接端正式规则须贯穿各独立阶段。组件不接受标答、答案来源标签或判分反馈。

任务准备返回`purpose`与`needs`，分别明确原任务目标与最小取证需求；它们是可纠错的任务解释，不要求重复输出依据清单。

完整流程的结果结构为`resolution`、`answer`和`conditional_results`；完成状态与结论均由外部智能判断，代码不按状态或文字筛选答案。返回`answer`为原样组合后的可用结果，`scoped_results`保留交付结构，兼容字段`basis`为空对象，原文依据保留在取证轨迹中；`used_information_use=true`表示采用本协作契约。

宿主采用任务准备、`task_contract`与自主取证形成结构化结果，再由`finish`原样呈现；`OFFER`、`RESPONSE`保留无任务分解的基础入口。已有运行与证据保持各自实现身份，不混用检查点。

## 执行与恢复

初始线索在每次尝试重置预算后准备，并与后续自主工具调用共用追踪与限制；其耗时计入本次完整等待。完成检查点恢复时不重复准备，异常尝试的已获材料与失败成本保留。轻量宿主仅在确定请求尚未发送时，于同一活跃作用域中消费原下一次尝试，续接相同请求与已获材料；不重置预算、不重复初始读取。已发送或发送状态不明的失败沿用原恢复规则。

模型将声明为数组或对象的工具参数编码成JSON字符串时，适配可以无损还原；字符串字段不作改写。已完成工作伴随无效空工具标记时，在同一上下文中纠正一次交付格式，不执行该工具，也不重取信息。真正的权限、工具或语义错误不能借此跳过。

`stage_prompt`可将同一步骤中断前的工作笔记与原需求、原文一起交回宿主；笔记可纠错，不充当事实。恢复沿用已有有效进展，不以截断思考、降低档位或反复重做整题处理失败。

[公共模拟转接](../../../benchmarks/support/information_use_flow.py)供关卡和最终测试共用；初始材料通过与供应商无关的执行生命周期传递，轻量客户端、Codex和OpenCode分别适配自身输入形式。仅连接内核MCP不会自动执行宿主侧接入。

## 旧材料的接续契约

宿主接续或重新使用已有材料时，按[信息变化架构](../information-change/README.md#宿主如何沿用材料)保留并核对原文的来源依据；变化、不可用和未核实的状态进入原任务，由外部智能体继续判断，不增加串行模型复核阶段。没有来源依据的笔记只能作为可纠错工作，不能当作已经核对的事实；来源未变也不替代对当前需求、时间条件及新增信息的判断。新增接续能力的实现和验收状态见[工作包三](../../tasks/information-control-and-change.md#工作包三信息随用户变化)。

第一版自动接续由正式 Codex 接入包承载，安装与事件衔接见[宿主接入契约](../information-change/README.md#不同宿主的接入)；通用核对逻辑与宿主事件适配分离，不将模拟 Reader 或 App Server 实验脚本作为用户入口。

宿主把实际读取返回的 `basis` 与原文一同保留，在恢复或再次使用前调用 `reuse_context`，将结果并入下一次已有的任务输入；它不会替宿主识别生命周期。这里的来源 `basis` 是不透明字符串，不是模型填写的判断依据。Codex 插件通过原生 Hook 自动完成这一衔接。

自动跟踪使用[有界材料工作集](../information-change/README.md#自动核对的材料工作集)，不累积检查整个对话历史；退出集合的材料再次使用前重新核对。明确说明无论位于同一资产或另一资产，均随相关片段提供定位，已取得最新来源引用不能代替阅读必要说明。
