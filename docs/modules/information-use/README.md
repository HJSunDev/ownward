# 信息使用协作

产品定位见[产品需求](../../product/requirements.md#信息使用能力)，运行职责及宿主适配见[架构总纲](../../architecture/overview.md#信息使用层的运行边界)。

## 处理方式

外部智能始终主导用户任务。组件帮助它把用户目标、原文依据、未决关系和必要的条件结果组织到同一次交付中，代码准备材料、按状态衔接并原样组合结果；不内置模型，不判断开放语义。

先由外部智能只看原始需求，按日常含义明确最小取证计划；历史事实不能因问题中的预设而视为已知。取得信息后逐项回应，保留用户指定的对象、事件及操作，不把找不到的所问对象替换为相似对象。计划不充当事实，也不能替代用户需求。主动取用时，以原始需求检索，尝试读取前三条来源的首个证据片段，再由外部智能继续按需取证；所有调用经过宿主原有权限与预算，初始线索不代表资料完整。

外部智能在取证过程中逐项建立依据、识别未决关系，形成主结果及必要条件；代码保留完整依据，原样组合主结果与条件结果，不判断语义。证据片段附带有界相邻原文和来源首部，帮助理解语境；原证据及来源版本不变，新增文本计入原阅读预算。

## 宿主接入

[零依赖Python组件](../../../integrations/python/ownward_information_use.py)运行在智能体宿主一侧，由宿主提供实际智能与信息内核调用。

| 入口 | 用途 |
| --- | --- |
| `FRAME`、`FRAME_SCHEMA`、`task_contract(frame)` | 独立准备最小依据计划，交付时逐项记录事实、关系及其依据。 |
| `initial_context(query, call)` | 以原始需求准备初始线索，返回可直接交给智能体的材料；`call`沿用宿主的权限、预算及工具记录。 |
| `check_materials(materials, call)`、`reuse_context(materials, call)` | 接续前用原连接批量核对材料的来源 `basis`，返回状态或可附入下一次正常任务调用的上下文；不调用模型、不改写原文，失败和缺项保持未核实。 |
| `OFFER`、`RESPONSE` | 在宿主已有取证循环中说明交付工作及结构，保持正式规则、模型和档位。 |
| `finish(response)` | 原样组合主结果与条件结果，无须提供原文或模型调用回调。 |
| `respond(observations, invoke)` | 处理已获材料：准备任务、形成有据结果，共两次宿主调用。 |
| `complete`、`reconsider` | 保留显式使用与接续已有工作的入口；此前草稿、理解独立于原始材料，不能成为事实依据。 |

`observations`包含原始`task`及带`id`、`origin`、`content`的`sources`，不得用模型重述替代原文。`invoke(stage, instruction, payload, schema)`由宿主实现，负责自身模型调用、结构校验、用量与恢复；原任务的日期等必要上下文及连接端正式规则须贯穿各独立阶段。组件不接受标答、答案来源标签或判分反馈。

任务准备返回`purpose`与`needs`，分别明确原任务目标与最小取证需求；各需求生成对应的依据字段。

完整流程的结果结构为`intended_outcome`、`basis`、`answer`和`conditional_results`；`basis`按计划序号绑定每项需求，每项含`supported`与`unresolved`。语义由外部智能判断，代码不分析文字。返回`answer`为组合后的可用结果，`scoped_results`保留交付结构，`used_information_use=true`表示使用了本信息使用契约，不能再解释为启动旧多阶段组件。

宿主采用任务准备、`task_contract`与自主取证形成结构化结果，再由`finish`原样呈现；`OFFER`、`RESPONSE`保留无任务分解的基础入口。已有运行与证据保持各自实现身份，不混用检查点。

## 执行与恢复

初始线索在每次尝试重置预算后准备，并与后续自主工具调用共用追踪与限制；其耗时计入本次完整等待。完成检查点恢复时不重复准备，异常尝试的已获材料与失败成本保留。

模型将声明为数组或对象的工具参数编码成JSON字符串时，适配可以无损还原；字符串字段不作改写。已完成工作伴随无效空工具标记时，在同一上下文中纠正一次交付格式，不执行该工具，也不重取信息。真正的权限、工具或语义错误不能借此跳过。

`stage_prompt`可将同一步骤中断前的工作笔记与原需求、原文一起交回宿主；笔记可纠错，不充当事实。恢复沿用已有有效进展，不以截断思考、降低档位或反复重做整题处理失败。

[公共模拟转接](../../../benchmarks/support/information_use_flow.py)供关卡和最终测试共用；初始材料通过与供应商无关的执行生命周期传递，轻量客户端、Codex和OpenCode分别适配自身输入形式。仅连接内核MCP不会自动执行宿主侧接入。

## 旧材料的接续契约

宿主接续或重新使用已有材料时，按[信息变化架构](../information-change/README.md#宿主如何沿用材料)保留并核对原文的来源依据；变化、不可用和未核实的状态进入原任务，由外部智能体继续判断，不增加串行模型复核阶段。没有来源依据的笔记只能作为可纠错工作，不能当作已经核对的事实；来源未变也不替代对当前需求、时间条件及新增信息的判断。新增接续能力的实现和验收状态见[工作包三](../../tasks/information-control-and-change.md#工作包三信息随用户变化)。

第一版自动接续由正式 Codex 接入包承载，安装与事件衔接见[宿主接入契约](../information-change/README.md#不同宿主的接入)；通用核对逻辑与宿主事件适配分离，不将模拟 Reader 或 App Server 实验脚本作为用户入口。

宿主把实际读取返回的 `basis` 与原文一同保留，在恢复或再次使用前调用 `reuse_context`，将结果并入下一次已有的任务输入；它不会替宿主识别生命周期。这里的来源 `basis` 是不透明字符串，区别于交付结构中由智能体填写的判断依据对象。Codex 插件通过原生 Hook 自动完成这一衔接。

自动跟踪使用[有界材料工作集](../information-change/README.md#自动核对的材料工作集)，不累积检查整个对话历史；退出集合的材料再次使用前重新核对。明确说明无论位于同一资产或另一资产，均随相关片段提供定位，已取得最新来源引用不能代替阅读必要说明。
