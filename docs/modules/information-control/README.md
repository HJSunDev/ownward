# 用户控制架构

实现[用户掌控信息](../../product/information-control.md)规定的授权、撤销与遗忘。本文确定设计；实现和验证状态由[工作待办](../../tasks/information-control-and-change.md)维护。

## 结构与共享边界

**认证在接入层，授权与资产生效状态在唯一权威基座，信息处理在现有内核。** 权限检查不依赖模型判断，也不在每种接入协议中各写一套。

| 部分 | 职责 |
| --- | --- |
| 接入适配 | 证明连接身份、注入可信调用上下文、呈现用户需要决定的内容；对接宿主自己的交互和凭据存放能力。 |
| 用户控制能力 | 提供接入管理、遗忘提交与状态查询，编排既有权威与清理能力；不持有另一份资产或权限真相。 |
| 权威基座 | 保存授权决定及修订、资产生效状态和未完成清理记录，统一决定调用、提交及结果交付是否仍被允许。 |
| 内核与派生存储 | 在有效资产上检索、组织；按权威变更移除或失效相关派生材料，不自行决定用户授权。 |
| 宿主编排 | 使用结构化状态接续操作、提示必要决定；理解和行动始终由外部智能体完成。 |

信息变化能力复用主体身份、资产身份与版本、停止使用状态、变更范围及结果有效性检查；现实变化的具体语义与宿主何时复查属于该能力自己的职责。两个能力不建立各自的版本系统或删除状态。

## 身份、凭据与管理入口

信息体系以独立生成、耐久保存的身份标识归属范围，接入者以稳定主体身份和独立凭据绑定；设备、目录路径、网络地址、模型和进程不决定这些身份。每项授权分别表达所属体系、主体、操作集合、作用范围及修订；授权采用整库和手动撤销，不预建通用策略引擎。

所有者入口是由用户控制、能够证明管理决定来源的可信通道，其验证由部署适配承担；本机部署可使用受操作系统保护的安装与恢复入口，业务契约不要求用户和服务处于同机。来自回环地址、知道数据目录或在请求中声明所有者身份均不构成所有者证明。

初次建立管理关系只发生在经验证的初始化操作中，已有所有者状态不得被再次初始化覆盖。后续管理通过已获管理能力的可信入口完成；普通智能体只能申请接入，不能用工具参数中的“用户已同意”升级自己。批准绑定具体体系、接入者和权限，由系统将新凭据直接交付目标连接器；原始凭据不进入模型上下文或返回内容。

管理凭据、普通连接凭据与内部服务启动凭据分离。可使用的秘密保存在相应部署适配保护的凭据区，权威侧保存验证所需摘要及授权记录；体系身份、所有者关系和管理记录进入完整恢复范围，活动凭据不随用户资产备份分发。安装和所有者恢复不能因请求最先到达而自动认领用户身份。

地址只用于定位连接目标；接入适配确认目标体系的可信绑定后才交付凭据，地址字符串或服务自报的体系标识不能代替验证。权威检查使用已认证的体系和主体上下文，不以连接地址、目录哈希或进程身份授予权限；更换地址或轮换凭据不新建主体、不扩大授权。

能直接读取数据目录、修改服务或取得管理凭据的程序处于部署信任边界内，接口权限无法隔离其系统级访问；宿主管理员不因此在业务契约中自动成为信息所有者。受限智能体仅经受控连接器访问。跨设备连接与传输保护由接入能力实现，本机共享令牌不承担产品授权。

### 初始化与恢复契约

| 情况 | 身份与授权处理 |
| --- | --- |
| 首次初始化 | 可信所有者入口确认后创建体系身份和所有者关系；重复请求不得覆盖已有关系。 |
| 正常重启、重连或地址变化 | 恢复当前权威状态，核对有效凭据并继续执行原授权；不走首次认领或旧备份恢复流程。 |
| 管理凭据失效 | 经独立于失效凭据的所有者通道验证后恢复管理连接，使被替换的凭据失效；不重建资产、主体或整套授权。 |
| 恢复旧备份 | 保留备份中的体系与主体身份，按旧快照恢复规则重新确认管理与连接；旧凭据不得自动激活。 |

部署迁移与恢复历史快照分别表达；位置改变本身不要求重新授权，迁移时权威交接及连接恢复由接入能力设计，不能通过复制目录制造多个活动权威。

## 宿主内的管理闭环

首个交付采用现有本机 MCP 路径加宿主侧管理适配：MCP 承载操作请求与回执，可信所有者入口负责批准与恢复，宿主适配接续原任务。模型提出要做的事，批准来自已认证的管理主体或宿主的可信用户确认通道；自然语言回复不能自行产生管理权限。

| 步骤 | 执行与交接 |
| --- | --- |
| 准备 | 接入适配识别调用主体与所需能力；允许普通连接提交管理提案，但未批准前不执行，也不向其泄露越权资料。已获管理授权的调用直接进入执行。 |
| 必要确认 | 宿主将确定的操作送到已配置的可信入口，携带原任务关联。批准绑定体系、请求者、操作与目标参数；批准单次操作不授予提案方长期管理权。首次建立或丢失管理连接时，先通过所有者验证再接续原请求。 |
| 执行 | 权威层在提交时复核批准者的管理权限、该次批准范围及目标版本，以同一操作标识耐久提交；重复提交返回已有状态，同标识不同参数拒绝。目标或重要后果变化时重新核对意图，不静默替换批准内容。 |
| 接回 | 凭据直接送至目标连接器，回执交回关联的原任务；拒绝和未完成同样有明确结果，不要求用户切换管理智能体或重复输入。 |

未提交的提案与原任务关联由宿主适配维护；批准及执行状态由权威层持有，避免两处各自判断是否完成。操作标识只用于追溯，不能当作权限凭据；查询回执仍校验当前主体，越权输出留在可信管理入口，普通连接只接收获准的结果。

宿主适配必须实际具备确认交接、私密凭据交付和任务恢复能力；不具备时不宣称完整支持管理功能。实现验收使用真实宿主验证该路径，不能用测试裁决或模型生成的同意替代，也不建设独立管理界面、智能调度器或通用审批框架。

## 授权执行

| 操作面 | 所需能力 |
| --- | --- |
| 搜索、导航、原文和证据读取、信息状态 | 读取 |
| 创建、更新、领取与提交语义工作 | 读取及维护；语义输入同样受信息访问边界约束 |
| 接入者列表、授予、调整、撤销、遗忘 | 用户管理；普通连接可提交提案、查询自身权限与获准的申请状态，不能自行批准或执行 |
| 备份、恢复及能够重建或导出完整资产的维护入口 | 经验证的所有者入口或明确的管理能力 |

统一产品入口取得认证上下文后读取当前授权；JSON 参数、`Source.Actor`、工具名称和进程标签不能成为认证依据。MCP、命令行与管理入口必须进入同一权威边界，未认证的公开调用失败关闭；模型白名单或隐藏工具仅改善使用体验，不能代替服务侧检查。

授权变更使用耐久修订提交。请求进入、资产提交、语义结果接受与结果交付前均核对仍有效的许可和资产状态；撤销后旧连接和旧工具目录不能绕过新状态，查询途中发生遗忘也不能交付未经重新核验的旧结果。已经通过最终交付校验的在途响应无法追回，已提交的操作也不倒退；其余工作按新状态拒绝，返回可理解的原因。

授权核对与提交以短临界区确定先后；不持锁等待模型或网络，不靠等待所有长期任务结束才允许撤销。查询结果沿用原排序和预算，权限检查只限制可访问内容与可执行操作。

## 遗忘与清理

采用一个由权威基座持有的可恢复操作，包含两个明确阶段：

1. **停止使用。** 管理入口提交操作标识、已确认资产集合及其版本；权威基座校验授权与版本后，耐久记录删除意图并将目标置为不可用。返回清理中状态前，此屏障已对读取、变更、语义工作和世代切换生效。
2. **完成清理。** 清除目标资产正文和旧日志副本、相关派生内容、旧工作材料及受控世代中的副本；核对清理范围后保存完成结果。途中失败保持屏障，重启接续同一操作，不重新请求用户确认或把已删除内容回滚回来。

状态仅需表示清理中、清理失败可重试、已完成；记录保留操作身份、目标身份、进度与必要失败原因，不复制被遗忘正文。无关资产不回滚，删除中的旧标识不能被创建操作重新占用。删除目标由外部智能从用户需求定位，代码仅处理获准的资产集合和版本；局部内容删除不通过改写原文或先复制再删除伪装支持。

### 清理、重建与回执分别完成

- 删除屏障耐久成立后即结束前台等待；清理由服务维护执行，与外部模型调用和宿主会话生命周期解耦。**遗忘完成只取决于受控副本清理通过，不取决于受影响资料的语义重建。**
- 原文未被删除的资产保持可读；受污染的派生结果先移除，按现有语义工作机制恢复。状态与证据覆盖如实交付，不用旧材料维持表面质量，也不为补回派生结果阻塞无关任务。
- 服务对可恢复的失败接续同一清理操作，采用退避而非紧密重试；需要外部处理的故障保存具体原因和进度。宿主适配保存操作关联，在线通过已有连接取得回执，断线后在接续或下一次 Ownward 调用中合并查询待完成操作；不另起模型轮询或定时智能体任务。
- 完成回执幂等交付，宿主按操作标识避免重复提醒；权限已撤销时只返回允许表达的状态，不因接续旧任务绕过权限。确认材料、缓存与错误记录中的受控正文同样纳入清理，完成记录只保留必要元数据。

### 清理覆盖与防复活

- 权威资产端口增加按预期版本删除及当前有效性表达；删除事件不能被现有非空正文校验误当作普通更新。压实后只保留必要的无正文删除身份，保留成本受资产身份数量约束。
- 失效范围沿资产版本及派生工作的实际输入依赖传递，包含候选上下文和此前分析，不能只沿最终关系边查找。某派生记录失效不意味着它的其他输入原文也被删除；仅实际依赖失效输出的下游继续失效，不沿主题相似性或共同出现关系扩散。需要重新组织的其他资产保留原文，但旧摘要、向量、工作上下文及旧提交结果不能继续泄露目标信息。
- 搜索结果、图边、证据引用、组织工作、日志和错误材料均按该边界处理。无法证明来源有效的派生材料先停止交付，再修复对应部分；不能以回退世代重新启用已遗忘内容。
- 运行中的生成任务提交时重新校验目标与输入版本。活动和候选世代切换前检查删除屏障，清理完成前禁止相关旧副本重新挂载或导出；未受影响的处理继续服务。
- 删除屏障与进度均属于不可安全重建的权威状态；普通崩溃恢复必须先恢复屏障，再开放接口。后台清理是服务维护职责，不需要定时调用外部智能体，也不依赖模型重新理解才能阻止访问。

清理按一批目标合并受影响记录与文件，复用依赖元数据并接续已完成进度；同一日志只做必要的合并清理，避免逐条遗忘反复重写全库。真实依赖造成的大范围失效须保留依据并计入成本，不能漏清理换取速度；语义恢复只覆盖实际受影响部分。验证分别记录前台接受、后台清理和语义恢复的工作量与耗时，确认规模增长不会变成用户等待或无关能力退化。

备份依据当前有效资产和控制状态生成，删除中的目标也不得进入新备份。恢复旧备份是显式回到旧快照：保留其资产和控制记录，但无论原地恢复还是恢复到新环境，恢复实例均须拒绝原有连接凭据，由经过验证的所有者重新建立管理入口、重新签发经用户允许的连接凭据。旧副本中的信息可能恢复，不能把这种操作冒充继续执行原实例的遗忘。

## 对现有实现的处理

| 实现 | 设计决定 |
| --- | --- |
| `authoritysubstrate`、`authorityport`、`assetlog` | 保留经审查的唯一权威、修订提交、恢复与关闭保护；扩展授权和删除契约、日志回放及恢复规则，不复制成第二套存储。 |
| `ProductCapability` 与装配入口 | 增加用户控制能力与不可绕过的认证上下文检查；模型可调用面与可信所有者维护面分别授权。 |
| MCP共享连接 | 保留经过验证的协议转发及本机实例定位；目录哈希、进程和地址仅用于该定位。替换共享凭据代表所有智能体的授权方式，将独立体系与主体身份传到权威层。 |
| `derived` 与语义工作 | 保留输入版本、紧凑工作引用、失效与压实基础；增加删除、完整输入依赖清理和过期提交拒绝，不能把现有更新刷新当作完整遗忘。 |
| 备份与恢复入口 | 保留流式归档和完整性检查；覆盖新增控制状态与删除屏障，排除活动凭据，封堵旁路导出及恢复旧权限。 |
| 协作规则与宿主适配 | 增加简明能力说明和结果状态处理；复用调用方自身智能，权限与删除决策不交给提示词执行。 |

## 实现必须保住的结果

普通调用不增加模型轮次；权限与版本核对使用确定性元数据，受控清理可接续且不阻塞无关任务。验证覆盖真实宿主的确认与任务接回、拒绝与重复请求、确认后目标变化、清理中断及重复回执，以及伪造身份、普通权限越权、重复初始化、正常重启与所有者恢复、地址变化时身份和授权不变、撤销与提交并发、删除期间的读取与旧语义提交、世代回退和旧备份恢复。外部语义能力不可用时仍须完成遗忘，清理后未受影响的任务质量保持不变；已有证据按真实依赖变化决定是否失效。
