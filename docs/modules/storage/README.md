# 信息存储与增长控制

本文说明 Ownward 当前如何保存一条信息、各类派生数据与长期信息资产的关系、实际存储成本，以及第一版完成前必须解决的增长问题。

长期方向与第一版架构边界见[《存储架构》](architecture.md)。

## 存储原则

> 信息资产随用户内容线性增长；派生数据具有明确、受控的单条成本，不因更新和失效状态无限堆积，并且任何派生数据都可以安全清理和重建。

长期信息资产是唯一权威。向量、关系、语义分析和索引只为组织与检索服务，不得替代资产，也不得成为恢复资产的必要条件。

## 一条信息的存储结构

| 内容 | 磁盘持久化 | 与初始文本的关系 |
|---|---|---|
| 长期信息资产 | 是 | 保存文本、稳定 ID、明确场景和明确关系，是唯一权威。当前实现会去除文本首尾空白，因此尚不是严格的逐字节原样保存。 |
| 语义派生状态 | 是 | 保存摘要、主题、线索、推导场景、推导关系、向量，以及不复制权威正文的紧凑工作引用和提交回执；可由长期信息资产重新生成。 |
| 词法索引 | 否 | 启动时根据资产在内存中构建词项和倒排表，不形成额外磁盘文本副本。 |
| 向量索引 | 否 | 启动时读取已持久化的向量，在内存中建立检索结构。 |
| 关系图索引 | 否 | 根据派生状态中的关系，在内存中建立正向和反向导航结构；关系边不复制完整文本。 |
| 向量模型 | 是，固定一份 | 整个产品共享，不随信息数量增长。 |

磁盘上主要保存两部分，而不是为词法、向量、关系和场景分别复制一份完整文本：

```text
长期信息资产
└─ 原始内容与不可丢失的明确语义

派生状态
├─ 向量
├─ 摘要、主题和线索
├─ 推导场景
├─ 推导关系
└─ 紧凑语义工作引用与提交回执
```

词法索引、向量检索结构和关系图导航结构主要存在于运行内存中，并分别从长期信息资产和派生状态构建。

## 历史体积基线与当前候选证据

以下数据是历史候选 `78a5198` 在同机十万条、384 维、短合成文本条件下的旧基线，不代表当前 V1 候选的存储格式或体积：

| 项目 | 体积 |
|---|---:|
| 长期信息资产 | 26.77 MiB |
| 派生状态 | 176.77 MiB |
| 完整存储占用 | 210.03 MiB |

最终选定的 EmbeddingGemma 使用 512 维 `float32` 向量，每条固定占用 2048 字节，十万条向量约为 195.3 MiB，比旧 384 维基线增加约 48.8 MiB。曾按旧格式估算的十万条完整存储 `253～259 MiB` 已因存储格式演进失效，不能描述当前实现，也不能作为完成证据。

当前 V1 存储候选已在版本化内部存储视图中，以同一组代表资产对比 v3 等价写入：产品总存储为旧格式的 `7.09%`，派生存储为 `1.43%`，反复更新后的权威恢复日志为压实前的 `41.80%`。这证明紧凑引用、回执和日志收敛机制成立，但该定向视图不是最终 512 维十万条资源验收，不能替代同一最终候选上的完整证据。

对于很短的信息，固定长度向量和派生元数据可能使完整存储达到原始文本的数倍；文本越长，向量的固定成本占比越低，整体放大比例也越低。EmbeddingGemma 模型与运行时约 358.5 MiB，是一次性固定成本，不随信息条数增加。

## 当前增长风险

- 信息资产和派生状态仍先通过追加恢复日志安全写入；资产维护会原子压实为每项当前资产一个快照，派生日志超过回收阈值后由维护只保留每项资产的当前记录。因此日志不会再把全部旧正文、旧向量和旧关系当作永久状态，但两次维护之间仍会暂时保留尚未回收的追加记录。
- 当前派生格式为 `ownward.derived/v4`：语义工作只持久化资产/候选身份和版本，提交只保留紧凑回执；松散 v3 日志首次打开时会迁移压实，已封存旧世代通过完整重建、校验和原子切换升级。迁移失败与大规模中断场景仍须在最终候选验收中持续保护。
- Q8 压缩的是模型权重，当前向量仍按 `float32` 保存；不能把模型量化误认为索引已经量化。
- 十万条正式资源证据仍来自旧 384 维格式；当前定向存储视图证明了新架构的相对收敛，但不能证明最终 512 维配置下的绝对磁盘、内存和更新成本满足存储前沿。

## 第一版完成前

1. 明确信息资产的保真边界；若要求原始输入逐字节不变，必须消除当前首尾空白归一化造成的变化。
2. 接入最终 512 维向量方案后，按实际产品格式重新测量不同信息规模和更新频率下的磁盘与内存占用。
3. 在同一最终候选上验证大规模反复更新、v3 迁移、派生失败、世代重建中断、备份与空白恢复，证明日志收敛不会损害当前权威资产、原子切换和精确恢复。
4. 只有在检索质量没有不可接受损失且最终资源证据确有需要时，才采用 `float16`、整数向量或其他额外压缩表示；不得把可选压缩冒充当前缺失能力。
5. 使用最终模型、维度、关系和更新负载重新通过同类存储前沿验收，不能沿用旧 384 维基线或定向内部视图代替最终结论。
