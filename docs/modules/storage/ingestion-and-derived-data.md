# 原文存入、组织与派生数据

## 维护规则

1. 本文必须与正式代码的实际行为一致；实验候选和设计设想不得写成已实现能力。
2. 项目功能变更涉及存入、组织、派生数据或检索取用时，必须即时核对并在同次变更中同步更新本文相关内容；受影响的历史测量不得继续代表新实现。
3. 仅保留流程、职责、产物、成本及必要依据，删除过程记录、重复说明和无关信息。

**核心定位：信息组织与存储策略。** 在完整保留已接收原文的前提下，统筹持久化的信息类型与派生表示、生成与更新时间、组织结构与存储粒度，以及派生数据的体积增长。这些决策共同影响信息覆盖、检索准确性、依据完整性及查询时的计算与推理工作量，是系统质量、响应效率和长期维护成本的核心决定因素之一。

本文说明原文如何成为可检索、可关联的信息，以及这些数据在正式检索中的使用顺序；外部智能的完整取证作答契约见[信息使用协作](../information-use/README.md)。长期约束见[存储架构](architecture.md)，语义职责见[语义理解架构](../semantics/README.md)。正式入口已接入SQLite有界存储；迁移及整体验收状态见[改造任务](../../tasks/bounded-storage-implementation.md)。

## 处理流程

**原文是权威资产；组织结果是可重新生成的派生信息。保存成功与组织完成是两个状态，组织失败不撤销原文。**

| 环节 | 执行方 | 实际工作与产出 |
| --- | --- | --- |
| 保存原文 | 内核代码 | 流式保存完整正文、身份、修订、来源与明确关系；按64 KiB分块落盘，原子发布资产及词法入口。 |
| 准备组织材料 | 内核与宿主代码 | 默认写入仍在返回前准备向量与关联候选；显式采用延后协议时先返回原文，宿主领取待办后按同一机制准备，不减少组织材料或预算。 |
| 语义组织 | 外部AI | 读取资料，生成检索信息、证据单元、对象和有据关系；允许没有可靠关系。 |
| 校验与发布 | 内核代码、本地向量模型 | 校验身份、版本、引用及结构；生成向量，将组织、依赖与检索投影持久化，事务切换可见版本。新向量立即可查，后台归块不改变分数和顺序。 |
| 失败恢复 | 宿主、外部AI、内核 | 复用已接受部分，只修正实际失败来源及其依赖；显式重建逐项复用有效语义、恢复缺失或不兼容的本地向量并重建检索投影，完整验证后切换世代，失败保留原世代；不重新派发已接受的AI工作。 |
| 长期维护 | 内核代码 | 按持久队列分批失效、回收旧版本、整理向量块及归还超额空闲页；与前台轮转，控制操作优先。遗忘立即阻断使用，完成回执覆盖正文、派生、日志及尚未交付的内核／RPC副本；临时文件由操作系统在进程退出时回收，启动持有独占锁后清理可确认的旧暂存残留。 |

语义判断仍由外部AI完成。存储迁移不新增AI阶段，不改变组织材料、模型、取证预算或答案形成方式。

### 延后组织接口

正式存储入口支持可选协议 `deferred-v1`，默认调用不变；宿主核对服务声明的 `ownward.deferred-organization` 能力后，才可在创建、更新或批量创建的每项中指定 `organization_mode`。原文、基础索引、明确关系、组织待办与写入回执同事务成立，保存后可立即读取和基础检索；此时不执行向量及候选准备，不表示智能组织已经运行。正式Codex连接器在系统显式启用（`OWNWARD_DEFERRED_WRITE=1`）时对创建、更新与批量创建采用延后写入；启用与是否存在组织执行者无关——执行者就绪只影响是否有人提前组织，不影响保存速度。可选组织执行器（[宿主策略](../information-change/README.md#可选组织执行器)）显式配置后接续同一待办。

| 操作 | 执行约定 |
| --- | --- |
| `ownward_semantic_jobs` | `claim` 按唯一 `request_id` 领取一项待办，结果不明时沿用该ID重试；返回资产、修订、世代、执行凭据及期限。后台设置 `background=true`，同一内核最多一个有效后台持有者；`after_asset_id` 按资产ID遍历，让失败资料之后的待办继续。`renew` 续期，`release` 释放；期限默认300秒、最多600秒。 |
| `wait` | 最多等待30秒，只报告是否有可领取工作，不占用数据库快照或前台执行锁；持久待办是事实来源，通知遗漏和凭据到期均可恢复。 |
| `ownward_semantic_work` | 延后任务携带 `lease` 和唯一 `asset_ids` 获取原有组织材料；旧调用继续取得原协议待办，不混领延后任务。 |
| `ownward_semantic_submit`／`_batch` | 宿主将凭据填入每项 `submission.execution_lease`；读取工作、续期和发布复核主体、权限、资产修订与世代。更正、撤权、遗忘、过期或重新领取后，旧执行者不能发布。 |
| `ownward_status` | `execution_identity` 标识当前资产修订、组织世代和工作，不是授权凭据。宿主按体系与主体修订关联恢复预算；预算耗尽时报告 `restore_organization_execution` 及原因，原文仍可读，新版本或其他工作不继承旧失败。 |

完整组织发布与结束执行占用在同一事务完成；完成凭据只用于核对同一已接受结果，不可续期或重新执行。语义已接受但向量失败时保留待办：有效凭据下可重放同一提交；中断或到期后重新领取，获取组织工作时只补向量，不再派发AI。关联来源更正产生新待办后即可重新领取，不等待旧占用到期。

执行元数据与待办同库保存，按资产保留一条，不复制正文或另建业务队列；重复写入仍沿用原耐久回执。SQLite格式5在格式4基础上增加后台占用标记，自动兼容升级既有库，保留原文、有效组织与旧待办，不重建资料；旧二进制拒绝新格式，停用延后路径不等于降级数据库文件。

`ownward_organize(id)`按需领取指定资料的组织待办并把组织材料交回调用者：返回租约、工作材料与期望提交结构；已有持有者时返回持有状态与接续信息，不唤醒后台。调用者完成组织后用`ownward_semantic_submit`提交（凭据填入`execution_lease`）；互斥、权限与资源上限沿用原领取约束。原文读取不要求先请求组织。


## 生成的信息及用途

处理单位是一次写入的一份资产，不是固定的一轮对话。五轮对话合并写入时，共用一份原文资产及其摘要、主题、线索和组织结果；分成五份写入时，则分别生成。批量调用可以同时处理多份资产，但输出仍逐份对应。

原文、控制状态、组织记录及可检索索引统一持久化于 `stores/<存储ID>/ownward.sqlite`。`storage.json` 指向唯一活动库；资产ID、修订、组织身份和输入依赖建立关联，不将多个来源改写或合并成一份原文。

```text
数据目录
├─ storage.json：活动数据库指针
├─ stores/<存储ID>/ownward.sqlite
│  ├─ 权威资产：身份、修订、完整正文分块、来源与明确关系
│  ├─ 控制状态：体系、主体、授权、交接与删除账本
│  ├─ 派生组织：摘要、主题、线索、图节点／边／条件、输入依赖与处理凭据
│  └─ 持久索引：词法倒排、原向量与筛选块、图导航、维护队列
├─ assets/.ownward.lock 与 manifest.json：新旧程序共同互斥及旧程序拒绝标记
├─ scratch/：请求和结果的临时流式工作文件，使用后回收
└─ 独立边界：模型制品、受保护的连接凭据、备份及测试日志

运行内存
├─ 固定数据库连接与页缓存
└─ 有界请求、检索及维护工作区；按需读取，不加载全库正文、向量或图
```

**关机不会丢失已提交的信息与索引。** 重启打开活动数据库并接续未完成维护，不重新读取全部原文建立索引，也不调用AI重做有效组织。工作区不足时排队或按批读取，不缩小可检索资料范围。全文结果经流式接口传输，避免请求与响应整包驻内存。

| 信息 | 内容与用途 | 生成方式及保存位置 |
| --- | --- | --- |
| 摘要、主题、检索线索 | 当前正式测试所用轻量宿主由AI为每份资产选择一个代表性原文片段作为摘要，生成最多4个主题标签，并选择最多8个原文片段作为检索线索；摘要和线索正文由代码按AI选择摘取，不自由改写。 | 保存为 `analysis.summary/topics/cues`，保存在组织记录中，通过资产ID、修订与组织身份绑定原文。内核接口本身也支持其他宿主提交文本形式的语义结果。 |
| 推导场景（接口支持，当前测试路径未生成） | 可记录影响含义或适用性的场景键、值、置信度及原文依据。当前轻量宿主的输出格式不包含此字段；100题4,734份资料中均未生成，不能计作已有实际产物。 | 内核接收后可保存为 `analysis.inferred_contexts`，保存在组织记录中并绑定资产及版本；不同于写入方明确提供的 `contexts`，也不同于关系中的适用条件。 |
| 证据单元、对象及定位 | 标出独立事项、对象及角色，保留对应原文和必要上下文，支持精确取证，并为图中的节点提供原文依据。 | 外部AI选择，代码转换并校验定位；保存在 `organizations`、`organization_chunks` 及其图投影表。 |
| 图关系及适用条件（图的边） | 连接资料、证据单元或对象，表达同一对象、包含、支持、冲突、推导等关系；保存方向、具体含义及适用条件的原文依据。例如“支付模块 → 属于 → 星河项目”。 | 外部AI生成的有据关系保存为 `analysis.organization.links`；内核也支持资产级 `analysis.relations`，并接收写入方明确提供的 `explicit_relations`。这些关系投影到SQLite图表供导航；适用条件及端点定位由有据关系保存。 |
| 向量 | 支持语义相似检索。 | 本地向量模型生成，保存在 `vectors` 表并绑定组织版本；每份资产的当前有效组织使用一个512维 `float32` 向量，原始向量占2,048字节，不含数据库及检索结构开销。尚未生成或生成失败的组织不保证已有向量。 |
| 词法索引 | 类似书后的关键词索引：记录哪些文字出现在哪些资料中、出现几次，查询时按文字直接找到资料。覆盖正文、资产ID、显式场景的键值及显式关系的类型和目标ID。 | 内核生成，不调用AI。保存在 `postings`、`lexical_documents` 及上下文投影中，通过 `lexical_payload_ids` 关联原文。 |
| 向量检索结构 | 组织各资产的向量，供查询向量比较并召回语义相近的资料。 | 原向量、增量区、成员关系及保守筛选页持久化；查询按需读取、精确计分，筛选不可用时回退精确扫描。 |
| 图导航索引 | 按图的节点组织正向、反向连接，支持沿关系查找其他节点及其原文依据。 | 内核将关系投影到 `graph_units`、`graph_links`、`graph_names` 等SQLite表及索引；重启直接读取，不再次调用AI生成关系。 |
| 版本、依赖及处理凭据 | 识别组织输入版本、执行持有者和有效期限，支持失效检查、恢复及重复提交处理。 | 代码生成，保存在组织记录、`dependencies`、操作回执及 `semantic_jobs`／`organization_execution` 中；执行凭据不授予额外访问权。 |

**词法索引与词法检索：** 存入时提前建立“词项 → 资料”的查找表，例如“星河 → 资料A、资料C”，“项目 → 资料A、资料B”。当前中文按单字和相邻双字拆分，英文、数字按连续片段处理，英文统一小写。查询时按相同规则拆分查询文字，查表找到候选，再结合词项区分度、出现次数和资料长度评分排序；不要求整句连续出现，也不要求所有词项都命中。索引记录资料身份和词频，不记录每个词的精确位置，具体证据片段由后续取证定位。它识别文字重合，不负责理解同义表达或判断事实；语义相似由向量检索补充。

**图数据与图导航索引均持久保存。** 资料、证据单元及对象构成节点，关系连接节点；关系可由写入方明确提供，也可由AI提出后经内核校验保存。导航索引用于按节点、方向和类型定向查找，不替代原文事实。

当前正文不超过320个UTF-8字节时可直接生成向量；更长的正文保留完整内容，待语义结果返回后，将摘要、主题、线索等检索表示分块向量化，再聚合为一个资产向量。中间分块向量不逐份长期保存。

## 检索时如何使用这些数据

以下为正式代码的普通搜索流程；索引用于筛选和定位，原文用于取证，派生记录不会全部交给外部智能。

| 顺序 | 执行方 | 实际行为 |
| --- | --- | --- |
| 1. 召回资料 | 内核、本地向量模型 | 词法检索与向量检索分别召回，融合排名；对象名称检索补充未命中的候选。 |
| 2. 扩展关系 | 内核 | 以融合排名前4份资料为起点，沿已保存的图关系扩展一跳；普通搜索内部自动执行，不依赖AI另发图查询。 |
| 3. 筛选排序 | 内核 | 结合直接命中、关系权重和依据相关性排序，应用场景筛选，仅保留请求数量的结果。 |
| 4. 交付取证入口 | 内核 | 返回摘要、命中信号、相关证据定位及选中的关系依据；不返回原始向量或整套索引。 |
| 5. 按需读取 | 宿主与外部智能 | 当前信息使用层以原始需求搜索，尝试读取前三条结果的首个证据片段；外部智能再按实际缺口继续搜索、读原文或图导航，受原有权限与预算约束。 |

按资产ID精确命中时直接返回；无有效派生世代时可仅走词法检索。图扩展只使用已有有效关系，不在查询时调用AI临时生成关系。前4份、一跳是当前固定规则，不代表针对所有任务自适应选择了最优路径。

**待组织信号**：搜索响应附带 `pending_organization`——查询相关的未组织资产，逐资产给出 ID、修订、确定性首段与 `pending` 状态及 `required_action`；有界分页（`organization_offset`，每页五条）、当前主体范围、按确定性相关性（词法评分）排序，复用既有状态词汇；`total` 为该查询词法候选窗口内（随 `limit` 放大、至多四百条）的待组织数量，窗口外不枚举。未搜到或组织待完成不代表信息不存在；存在未组织资料时，深度路径必须触发组织或显式返回部分覆盖。

实现依据：[组合检索](../../../internal/core/streaming_search.go)、[证据与关系交付](../../../internal/core/streaming_graph.go)、[宿主初始取证](../../../integrations/python/ownward_information_use.py)。

### 累计容量与启动成本评估

2026-09-17正式SQLite装配的已测边界如下；完整原文、组织和向量保持不变，无新增外部AI调用。

| 项目 | 实际结果 | 含义 |
| --- | --- | --- |
| 完整进程树峰值 | 210.52 MiB | 含服务、本地模型与连接器；非模型49.58 MiB，分别低于270 MiB总上限及56 MiB分项预算。 |
| 短资料热查询 | 20次，p95约547毫秒 | 与冻结资源负载相同的20份资料及查询；低于600毫秒边界，不代表任意GB规模查询。 |
| 批量存入 | 模型预热后约312毫秒／份 | 20份冻结资料，包含正式工具调用及存储；模型冷启动的另一轮首次批量约698毫秒／份，两种条件不能混用。 |
| 冷启动 | 三次2.02～2.86秒 | 启动服务、连接器并完成首次查询；低于3.5秒边界，不含旧资料首次迁移。 |
| 48份真实资料迁移后体积 | 正文0.504 MB；SQLite 6.210 MB | 组织编码0.511 MB、原向量0.098 MB；其余为索引、控制元数据及页面开销，清理后空闲页为0。相同资料改造前为8.749 MB，减少29.0%。 |

上述真实样本共22,359条词法倒排。改用整数文档版本编号后，正反倒排及编号映射合计约2.064 MB；完整原文、组织、向量、词项和频次的校验值不变。80／160条冻结合成内容的数据库分别由2.261／3.375 MB降至1.868／2.605 MB。编码口径的派生体积比例仍约1.03，低于原1.35边界；它不包含完整SQLite文件开销，不能用来声称数据库只有原文的1.35倍。

**当前判断：内存和启动不再依赖全库物化，已测负载的资源与查询成本满足既定边界。** 持久索引增加磁盘占用，已通过紧凑标识减少重复存储；不能将小样成本或旧编码比例外推为任意资料密度的保证。检索用的小型临时数据仅在共享预算内缓冲，超过8 KiB即落盘，原文和已提交索引仍耐久保存。[版本身份、测量条件及原始证据](../../../benchmarks/acceptance/suite/adapters/product_resource/bounded-unit-four-20260917.json)。

### 历史耗时

2026-09-15，版本 `a3df3f3`，千问3.8 Flash／medium，各测一次；不是稳定均值，不含PDF解析或OCR。完整体验与保存确认口径见[信息沉淀实测](../../delivery/first-version-delivery-definition.md#信息沉淀)。多来源批量导入的分钟级等待不能全部归为有效推理，也不能直接代表单文档体验。

### 历史容量问题与改造依据

评估对象是长期累计资料总量，不是单次写入量。2026-09-16使用本文基线的正式内核代码测量本地加载与索引重建，不调用外部AI；较大容量根据已有测量推算。

| 累计原文体积 | 重启加载与重建时间 | 启动后内核进程内存 | 依据 |
| --- | ---: | ---: | --- |
| 约10 MB | 1.2—1.6秒 | 103—108 MiB | 实测 |
| 约50 MB | 6.2—7.4秒 | 439 MiB | 实测 |
| 约105 MB | 12.9—14.0秒 | 907—934 MiB | 扩展样本实测 |
| 约210 MB | 36—39秒 | 约1.8 GiB | 扩展样本实测 |
| 约500 MB | 约1—1.5分钟 | 约4—4.5 GiB | 同等资料结构推算 |
| 约1 GB | 约2—3分钟 | 约8—9 GiB | 同等资料结构推算 |
| 约10 GB | 普通电脑可能先遇到内存不足，无法保证启动时间 | 数十GiB量级 | 同等资料结构推算 |

实测使用i7-10710U、16 GB内存，每档两个新进程依次测量，限制两个CPU执行线程，未清空系统文件缓存。材料来自已完成组织的100题资料，平均每份原文约10 kB；超过4,734份的扩展样本复用原文和关系结构，不代表同等数量的独立真实文档。推算假设平均文档长度、词汇及关系密度相近，实际成本还受这些因素影响；内存不足时可能显著偏离推算。

内存列包含原文、组织记录、索引及运行时开销，不包含本地向量模型进程；是启动后的进程物理内存快照，不是索引净体积或长期稳定占用的承诺。原文MB、GB采用十进制，内存MiB、GiB采用二进制。

**旧实现判断：这是基础性架构设计缺陷，违反长期信息存储产品必须控制运行资源的基本要求，应作为核心可用性的阻塞问题处理。** 旧实现要求原文和组织记录全量驻留、索引全量重建，缺少有效约束全库内存占用的机制，使用户正常积累资料就会持续推高内存需求与启动成本，最终可能挤占其他应用资源或无法正常启动。约50 MB原文已带来约439 MiB启动内存占用，500 MB原文按现有结构推算即需数GiB，尚未计入本地模型；这已暴露基础设计问题，不能作为一般性能优化后置。产品必须能在明确、可控的运行资源预算内使用长期累积的GB级资料，不能要求用户随资料增长持续扩充内存，也不能靠限制正常资料积累掩盖这一缺陷。

## 迁移、备份与恢复

旧日志首次打开时，在原锁下隔离旧入口，流式迁移有效原文、控制状态和组织材料，校验后耐久切换指针；中断按检查点接续。旧程序拒绝标记永久保留，不能与新库双写。只有切换激活之前允许明确取消，激活后向前恢复。

旧向量仅在空间身份相同或具有逐字节等价证据的兼容映射下复用；未知空间拒绝转换，不冒充兼容。旧资料与目标库会短暂共存，迁移前检查空间，成功后清理被替代日志。不能删除唯一原文给迁移腾空间。

默认资产备份保留原文与必要控制信息，排除派生结果和可直接使用的旧连接凭据；部署交接快照保留有效派生及授权连续性。交接源退役后清理原文及派生副本，保留身份、接续信息和旧程序拒绝标记。原目录恢复旧快照时应用删除账本并使旧凭据失效，不能复活已遗忘信息。
