# 关系组织架构

产品行为以[关联信息的可靠取用](../../product/related-information.md)为准；本文规定图的表示与运行机制，设计与实现状态由[图能力工作包](../../research/graph-value-and-cost.md#工作包图能力设计实现与验收)维护。语义协作的权威与权限边界沿用[本模块契约](README.md)，不建立第二套语义服务。

## 架构选择

**采用以证据单元为中心、结合对象线索与有据关系的混合组织：用关系找到原文，用原文支持判断。** 一项短信息可直接作为一个单元；长资料中互不相同的事项分别定位，事件的参与者、时间和条件保留在同一语义边界内。跨资料关系连接这些单元，避免整篇关联过粗，也避免把所有内容压成丢失条件的实体三元组。

对象名称和别名用于找候选，同一对象的判断保存为可撤销的关联，不建立会吞并原文身份的全局唯一实体。事件以来源内的完整陈述表达，不另设领域事件模型、时态推理引擎或本体编辑系统。

| 结构 | 保存的最小内容与边界 |
| --- | --- |
| 权威资产 | 原文、稳定身份及不可丢失的明确语义；继续使用现有资产，不为图复制正文或改变资产身份。明确更正等关系仍属于资产。 |
| 证据单元 | 派生身份、所属资产版本与组织快照、简洁忠实的陈述、原文定位及必要上下文定位。一个事件或带条件的判断不能拆到含义改变；陈述是检索线索，不能替代原文。 |
| 对象线索 | 单元内有独立定位的对象提及，包含名称、角色或别名及其原文位置；名称倒排查找只表示可能相关。同名、共现和向量相近均不证明同一对象，更不证明业务关系。 |
| 有据关系 | 两端引用、方向、关系含义、必要条件与双方依据；端点明确区分资产、证据单元和对象提及。同一对端点可有不同条件下的多种关系；通用类别用于导航，具体含义保留简洁说明，不靠增加领域枚举表示世界。 |
| 生成依赖 | 实际送入该语义工作的完整输入身份与版本、实际使用的派生内容标识（单元快照或关系记录）、外部能力身份和派生世代。它回答“哪些材料参与生成”，与回答“内容之间如何关联”的语义边分开，不能仅凭最终关系边执行遗忘。 |

每项资产在一个派生世代内持有当前组织快照，标识该资产产出的证据单元与对象提及集合。关系记录独立引用端点快照，不能仅凭资产版本未变继续使用；局部重整可改变快照而不改变资产身份、修订或其他资产的组织快照。仅增删或重新绑定关系不替换未变的端点快照，避免引用恢复本身引发连锁重整。该标识属于派生元数据，不建立第二份资产版本权威。

重建后不承诺派生身份不变；对外长期引用仍落到资产与原文。时间和条件有依据才保留，发生时间、表达时间与入库时间不能互相替代。

“同一对象”连接对象提及，“含义等价”连接陈述，两者不能混用；即使对象相同，也不合并两次事件。关系去重同时考虑端点、含义、方向、条件及依据，不按“同一目标”只留一条。

## 构建：整理一次，后续复用

1. 资产按现有耐久写入路径成立，基础读取与检索立即可用；生成关系不进入写入的同步模型等待。
2. 内核通过既有语义工作提供当前资料、必要上下文及有界候选。候选来自词法、向量、已有对象线索和明确引用的联合召回，避免只寻找语义相近的整篇资料；未被召回的关联不能宣称不存在。
3. 接入方自己的智能在原有语义整理中提出证据单元、对象线索及有依据的关系。一次工作材料足够就同时完成；只有新线索确实带来需核对的候选时才补充局部工作，不为每个名字、每条边固定追加模型调用。
4. 内核核对当前权限、全部输入的资产版本与实际使用的派生内容，以及领取工作时的目标组织快照和工作标识；通过定位与结构校验后，按下方[局部替换规则](#局部替换与引用接续)原子发布。原文定位使用可唯一匹配的引用和必要邻文，由内核生成范围；不让智能体计算偏移，也不截断改变语义的证据。
5. 不确定的身份与关系保持未定，缺少依据允许无关系；语义工作完成只表示已处理本次给定材料，不代表全库关联已经穷尽。结构校验不冒充语义真伪校验，自报置信度不作为正确性的证明。

由正式宿主适配在其可用的工作时机领取并提交语义工作；Ownward 不自行调用模型，不要求第二个智能体或额外密钥。不支持后台执行的宿主保留待整理状态，在接续使用时继续，不能让用户必须等待整理结束才能做其他工作，也不能宣称任何宿主都已具备自动后台处理。

批量输入按有界材料合并整理，跨批关系由共享派生索引和必要的局部补充发现；不全库两两比较、不为每次查询重建图。只需保存的临时或单一信息不承担无依据的重度拆分。

## 检索：关联必须进入可用材料

```mermaid
flowchart LR
    Q[原始需求与既有任务要点] --> S[词法、向量和对象线索召回]
    S --> G[有界关联扩展]
    S --> R[统一候选排序]
    G --> R
    R --> E[原文入口、必要条件与关联依据]
    E --> A[接入智能体取证并完成任务]
    A -->|需要补充| S
```

- 保留稳定身份直接读取及原有混合召回。对象线索提供跨资料入口，有据关系补足间接材料；词法或名称已取得种子时，向量暂不可用不能连带禁用有效图。不新增固定的查询模型、关系裁判或结果复核链。
- 普通搜索从有限种子展开局部关系。直接命中、关系目标和连接所需的依据按同一阅读预算组合；依据相关性、来源有效性、重复程度和路径长度排序，不按连接数量累加声望。关系目标可由与需求相关的连接依据入选，不能仅因目标缺少相似词便永远排在结果之外。
- 一个关系候选须交付可核对的连接理由及双方原文入口，条件不被拆掉。跨多步路径只证明存在这些有据连接，不自动推导传递、因果或最终结论；省下的是寻找材料的工作。
- 原文与片段继续走现有读取、权限和 `basis` 核对契约；[明确更正随来源交付](../information-change/README.md#明确更正随来源交付)独立于相关度排序。图中缺边、关系整理未完成或来源状态未变，均不能证明资料完整或结论仍适用。
- 检索结果保持资产身份、原文入口及已有字段可用，补充关系依据和证据单元定位；复杂关联通过现有导航能力继续获取。用户不选择图类型或工作深度，工具和接入适配承担参数与材料交接。

遍历同时限制实际访问的节点、边和返回材料量，按需读取邻接项，不先复制或排序高连接节点的全部邻居。达到单次预算时返回已核实部分及未穷尽状态；下一次导航可接续，但来源或所用组织快照变化后不能沿用失效路径。不能以结果条数有限冒充工作量有限，也不能把截断当作没有更多证据。普通检索无需等整条长路径探索完毕。

没有可用关系时继续原有词法、向量与原文取证；原始内容不因图缺失退出候选。适用条件的含义由外部智能判断，内核不凭缺字段或不完整时间把可能有效的资料排除。

## 更新、纠错与安全

| 变化 | 必须发生的处理 |
| --- | --- |
| 新信息进入 | 组织新来源并查找相关候选，允许为已有单元补充带新依据的连接；不要求重做未受影响的旧语义，也不按入库顺序漏掉反向关系。 |
| 原文修改、明确更正 | 提交与失效可见性一致：受影响旧定位、关系和实际依赖结果先不可用于交付，再合并安排必要重整。纯生成时间较新不代表事实更可信；明确更正不等待图重新理解。 |
| 身份误合并或关系错误 | 撤回有误的派生连接并重整实际受影响结果；原文、不同事件及其他独立依据保持可读。名称相同不做不可逆合并，相同对象也不推导其所有经历相同。用户明确纠正的含义保存在资产中，重建后不会遗失。 |
| 授权调整或撤销 | 按当前授权限制该主体的访问与提交，使其过期访问许可和未经最终校验的在途操作失效；不删除共有资产、关系或回滚已接受结果。来源仍有效的组织结果继续供其他获授权主体使用；交付时校验全部相关来源，不泄露受限端点、桥接理由或派生片段。 |
| 遗忘指定信息 | 按获准的遗忘范围停止内容使用，沿完整生成依赖清理受控陈述、名称索引、边、缓存及工作材料，拒绝带被遗忘输入的旧提交。保留其他独立资产；不依赖模型重算才阻止泄露，清理完成不等待语义恢复。 |
| 中断、恢复与迁移 | 接续尚未完成的工作，复用仍有效结果；提交再次核验输入。恢复先恢复控制屏障，再开放图和索引；迁移携带兼容派生结果，不因地址变化重新判断信息，也不形成第二活动权威。 |

失效按真实生成依赖传播，不能沿“相似”“同一对象”等语义关系无限扩大；同一模型工作读过的候选也算输入，不能为了少重算而漏记。无关原文始终保留，可独立使用的组织结果继续提供服务。

### 局部替换与引用接续

1. **先准备，再切换。** 新组织快照准备期间，来源仍有效的旧快照继续服务；已失效的旧结果不继续使用。沿端点引用和真实生成依赖收集受影响项，在同次提交中发布新快照、停用旧快照及依赖它的旧引用和生成结果。持久化与索引恢复遵从同一决定，不能出现新单元搭配旧边；原文和无关组织保持可用，不在提交中等待模型。
2. **引用恢复有据。** 仅当单元陈述、对象角色、原文定位与条件等语义字段完整一致且匹配唯一时，确定性地重新绑定引用；否则保留原文入口，将受影响关系交给既有语义工作重新判断，不凭相似名称或位置猜测新旧对应。实际使用了被替换派生内容的生成结果须重新判断，不能只改引用使其恢复有效；恢复以当前原文与明确语义为依据，避免相互依赖旧派生结果而反复重算。
3. **旧工作不能覆盖新结果。** 提交必须仍是当前有效工作，匹配领取时的目标快照及全部实际输入状态；工作被替代、输入已失效、组织快照已替换或权限已收回时，拒绝迟到结果并接续受影响的工作。同一已接受提交沿用原回执，不重复替换快照；回执读取与任务接续仍须校验当前主体权限。
4. **读取同样核验。** 关系、缓存和导航接续在交付前核验关系记录、端点快照及生成依赖的有效性；失效引用返回可重新取证的状态，不能作为有效关联或伪装成已查明没有关联。局部重整本身不使未变原文的长期依据失效，用户无需重新保存或手工修复连接。

## 存储与职责落点

采用同一派生世代内的记录和可重建索引：证据单元按资产归属；名称使用倒排引用；关系使用正反邻接；生成依赖使用反向索引。原文通过引用读取，不给每条关系复制全文、生成向量或另存多层摘要。共现通过名称索引找候选，不物化所有共现资料两两之间的边。

存储与更新量随实际单元、提及、关系和生成依赖增长，不以全库组合数增长；失效记录与日志沿现有回收机制收敛。沿用单进程与现有派生持久化端口，补足当前图记录和局部索引操作即可，不增加专门图数据库、独立服务或双写权威。

| 模块 | 承担的变化 |
| --- | --- |
| `semantics` | 统一语义工作与提交结构、来源定位校验；扩展证据单元和关系表达，旧字段不被静默解释成新能力已完成。 |
| `derived` | 保存与索引组织记录、生成依赖和有效状态；局部更新、可重建、受控回收。 |
| `core`／检索 | 组合直接证据与关系证据、原文读取及导航，统一执行权限、版本、遗忘和预算。 |
| 接入与测试适配 | 使用同一正式语义契约与产品路径，不写入验收答案或标签，不丢弃智能体返回的有效关系，也不为关卡和最终测试维护两套语义行为。 |

需升级语义或派生格式时显式区分能力版本。旧资产无损沿用；可兼容的粗粒度关系仍只表示其真实能力，不能伪装成已取得精细证据。新旧组织格式通过一致候选世代验证与切换，回退须遵守当前权限和删除屏障，不让旧读写器静默清空新关系。

## 验证设计是否成立

先用[已有关系、场景与更新材料](../../../benchmarks/acceptance/suite/README.md)覆盖下列边界，仅补现有材料确实缺失的场景：同一长资料中的独立事项；跨资料对象与两步关联；同名和别名；条件与冲突；新增更正及身份纠错；遗忘、恢复和高连接节点。预期固定为必要原文与合理关系，允许不同但忠实的表达。

定向验收须覆盖：撤销一个主体后其他获授权主体仍可使用共有信息；原文未变但单元重新划分时，旧边、缓存与迟到提交均不能误用旧快照；中断恢复不混合新旧组织，无关信息可继续取用。

验证分清两种证据：同一份语义产物下启用或屏蔽关系扩展，观察图如何改变证据覆盖与读取工作；完整产品再与未引入该组织方案的有效基线比较，计入新增语义处理、表示与维护成本。前者不能替代后者，最终答对只是其中一项结果。

优先验证会改变方案成立与否的三点：单元能否保留条件且减少无关阅读，名称与关系能否找到新增必要依据，局部维护能否避免陈旧信息与成本扩散。取得实际增益后再运行受影响的质量回归与规模检查；复用现有运行器和记录，不新建通用评测平台。验收依据与停止条件以产品文档和工作包为准。
