# 用户掌控信息

本文定义用户控制能力的产品行为，遵循[产品需求](requirements.md)与[项目哲学](../philosophy.md)；实现职责见[用户控制架构](../modules/information-control/README.md)。

## 用户得到什么

**通过自己信任的智能体，决定谁可以怎样使用 Ownward，随时收回访问，并让指定信息退出体系。** 用户关注对象、允许的行为和结果；接入身份、凭据、版本与清理流程由系统处理。

## 使用过程

| 用户需要 | 产品行为 |
| --- | --- |
| 让一个智能体使用 Ownward | 在正在使用的智能体中提出需求；系统准备连接并带到可信确认入口，呈现接入者和拟允许的行为。用户决定后自动接回原任务，凭据由系统交付。 |
| 知道谁在使用 | 在当前会话提出请求，经管理授权取得接入者、允许的行为及是否已停用；名称相同时能够区分具体连接，名称本身不构成身份凭证。 |
| 调整或停止使用 | 对指定接入者调整权限或收回访问；生效后该连接不能继续取得新的许可，重新连接也不能恢复旧权限。 |
| 忘掉指定信息 | 智能体找到对应信息并明确删除对象；范围明确且用户意图充分时直接执行，有歧义或会连带删除其他内容时才澄清。提交后停止使用，受控副本清理完成后报告已完成。 |

已明确的决定不反复确认；用户不需要复制密钥、理解协议或管理内部状态。权限改变、无法执行或需要用户作出新决定时才打断用户，普通调用不增加确认步骤。

### 管理请求如何完成

已有管理授权的可信入口直接执行用户明确要求的范围。普通连接只提出请求，由宿主带到可信入口批准该次操作；这不等于把长期管理权交给提出请求的智能体。批准、拒绝或中断都回到原任务，用户不需要寻找另一个管理智能体或重新描述需求；不支持的能力直接说明，不进入无效确认流程。

首次使用或管理连接失效时，宿主引导完成所有者验证，自动建立所需连接后接续待办请求。必要的身份验证和重要后果由用户确认，定位入口、携带请求、交付凭据和接回结果由系统负责；缺少所有者验证条件时说明缺失条件并保留请求，不冒充已经恢复。

这些行为须在至少一种真实宿主中完整交付，不能仅靠模型转述“用户已经同意”或把操作说明交给用户手动完成。

## 使用与管理的边界

| 用户可理解的能力 | 允许的行为 |
| --- | --- |
| 查看资料 | 检索、阅读原文与证据、查看相关信息状态；不改变信息和组织结果。 |
| 使用并维护资料 | 包含查看，以及创建、更新和参与语义组织；不包含管理接入者或执行遗忘。 |
| 代我管理 Ownward | 由用户单独交付给可信管理入口，可管理连接、执行遗忘及备份恢复；不因智能体名称、长期使用或普通读写权限自动获得。 |

这些是可授予的能力，不是固定的主从智能体等级。管理入口可以替换，所有权始终属于用户；安装时通过用户控制的可信入口建立初始管理关系，失去智能体连接后仍可由经过验证的所有者恢复控制。用户无需与服务位于同一设备；入口的具体形式由部署适配提供。

用户、接入者及信息体系的身份独立于设备、目录和网络地址；更换连接地址本身不改变信息归属或已有授权，也不能让另一个服务冒领该身份。

支持整库访问，正常授权持续到用户收回。只接受局部访问或自动到期条件时，系统不能偷偷改成整库、无限期授权；明确说明支持边界，由用户决定是否改用当前能力，未明确同意则不授予。细粒度授权见[未来能力登记](future-capabilities.md)。

## 遗忘的准确含义

- 用户按内容表达要忘掉什么，智能体负责定位。确认材料只呈现可识别的内容、来源及删除影响，不展示资产编号、版本或派生结构。当前删除能力以整项资产为单位；若用户只想去掉其中一部分，明确说明尚不支持该粒度，不执行删除，也不把整项删除包装成普通确认。只有用户另行明确要求删除整项时才执行。
- 遗忘包括选定资产，以及 Ownward 控制的相关摘要、向量、关系、缓存和恢复材料；不能只隐藏搜索结果。其他独立资产是否也应删除，由用户意图确定，不能通过无依据的联想扩大删除范围。
- “已停止使用，正在清理”与“已完成遗忘”是不同结果。清理失败保留停止使用状态并能接续；中断、重启、旧工作提交和世代回退不能让信息自行复活。
- 其他系统已经取得的副本、用户独立保存的旧备份不属于可远程擦除范围，也不承诺物理介质取证级擦除。正常使用不展示技术细节，但在相关操作中必须说明会影响用户决定的边界。

撤销访问同样不能收回已交付的信息或撤销已完成的外部行动；尚未提交的修改和尚未通过最终交付校验的结果必须按最新权限处理。

### 用户何时可以继续工作

遗忘请求被可靠接受并停止使用目标后，即返回“已停止使用，正在清理”，用户可继续其他工作，不等待后台清理或语义重建。系统接续可恢复的清理失败；只在确需用户处理时说明原因和必要动作，不让用户判断内部重试。

完成结果保留在原操作中。在线宿主接回结果；会话中断时由宿主保留关联，下次接续或再次使用 Ownward 时带回最新结果，用户无需重新发起或反复查询。完成清理即可报告“已完成遗忘”，不等待其他资料重新组织；受影响资料尚未恢复完整检索能力时如实表达状态，不降低证据质量冒充正常。

## 恢复与完成标准

普通重启、断线重连或地址变化沿用当前有效授权，不重新认领所有权；管理凭据失效时，由经过验证的所有者恢复控制，不改变信息归属。

恢复旧备份可能带回备份时点的信息，必须让用户知道这一后果。备份保留信息与管理记录，不携带可直接使用的连接凭据；恢复后由经过验证的所有者重新建立可信管理入口和需要恢复的连接，不能自动激活旧凭据。这与沿用当前权威状态的正常接续不同。

能力完成须同时满足：

1. 普通接入者无法自授管理权；权限变更与撤销在重启后仍有效，所有信息入口遵循同一边界。
2. 至少一种真实宿主完成“原任务发起—必要确认—自动接回”，覆盖首次接入、普通连接提出管理请求及管理入口恢复；用户不处理凭据、技术配置或重复描述。
3. 遗忘覆盖受控副本，失败可接续且不复活；用户不等待清理，不管理重试。无关资产、稳定身份和原有可用能力不受损，局部内容删除的范围限制准确表达。
4. 权限与有效性检查不调用模型，不在普通任务中增加模型复核链、重复确认或全量重读。

权限保护以 Ownward 服务入口为边界；持有数据目录及宿主系统管理权的程序不能被包装成受该接口权限隔离的对象。
