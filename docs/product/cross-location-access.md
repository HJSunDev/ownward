# 跨地点访问与便捷迁移

本文定义跨地点使用与部署迁移的产品行为，遵循[产品需求](requirements.md)与[项目哲学](../philosophy.md)；实现职责见[接入与迁移架构](../modules/access/README.md)。

## 用户得到什么

**信息体系留在用户选择的位置，不同地点的智能体经授权使用同一份信息；更换存放位置后，信息、控制权和使用关系延续。** 智能体的身体、品牌和所在地不决定权限，接入方式不决定信息归属。

## 使用过程

| 用户需要 | 产品行为 |
| --- | --- |
| 让另一个地点的智能体接入 | 在自己已信任的管理宿主发起连接，将公开连接材料打开到目标宿主；核对接入者及拟允许行为后批准，系统私下建立连接并接回目标原任务。 |
| 换会话、换网络后继续使用 | 在服务仍可达且授权有效时自动重连，继续使用同一身份；无需重新授权、重新介绍个人信息或在每台设备导入资料。 |
| 多个智能体同时使用 | 共享当前有效信息；遇到并发修改，保留已提交的结果并明确返回冲突，不能静默覆盖或因重试重复存入。 |
| 更换存放位置 | 在目标主机通过正式安装入口选择“接收迁移”，再在现有管理宿主选择该目的地；系统检查条件并告知暂停，确认后自动交接、验证和接续，不要求用户复制目录、搬运密钥或判断哪个副本有效。 |
| 连接暂不可用 | 原任务保留进度，明确说明暂未取得信息或提交结果尚待确认；恢复后核对并接续，不把旧副本冒充当前信息，也不让用户无限等待。 |

接入者没有可信管理连接时，其自身的“同意”不能完成授权；确认由已经验证的所有者入口承接，原申请与结果自动关联。管理入口暂时不可用时保留申请，说明等待谁的决定，不制造反复确认。已明确的同一次决定不重复索取。

确认直接呈现在已授权管理宿主的原连接任务中；必要时用双方显示的简短标记核对是否为自己选择的设备，不能只凭名称批准。目标先发起时，申请送至已关联的管理连接；该宿主没有正在接续的调用时，在下次使用 Ownward 时带回，明确显示待批准。批准后在线任务继续，中断任务在重连或下次使用时接回；不承诺主动唤醒任意智能体。

用户只处理使用对象、允许的行为、目的地和重要后果；连接定位、证书验证、凭据交付、重试和交接状态属于系统职责。用户首次指定体系或目的地是必要选择，不等于要求用户理解部署协议。

## 支持边界与维护责任

- **一处服务，多处使用。** 支持用户控制的常在线电脑或服务器承载一个活动实例；智能体侧只需受支持的连接适配，不各自运行信息内核或保存可独立写入的资产库。
- **可达性是使用条件。** 部署位置须有持续存储、运行条件和允许访问的网络入口；安装适配检查并说明是否具备条件。休眠、断电或网络隔离期间不承诺远程可用，Ownward 不内置公网中继、云托管或多端同步服务。
- **运行责任清楚。** 部署方提供主机、网络与系统级服务启动条件；Ownward 提供可安装、可恢复的服务及连接适配，并在授权范围内完成自身配置，不能把内部凭据和恢复步骤转交普通用户处理。
- **沿用用户控制。** 整库读取、维护和独立管理授权遵循[用户掌控信息](information-control.md)；跨地点不新增默认权限。细粒度范围、临时期限以及新形态宿主的专用适配不因本能力自动获得支持。
- **迁移包含受控暂停。** 目的地先准备、校验，正式交接期间存在必要暂停；不承诺零停机。网络、数据规模和存储性能影响搬迁耗时，开始前给出依据当前条件的估计；不通过丢弃组织结果、重新调用外部模型来换取实现便利。

部署使用正式发布包的服务安装入口，完成系统托管启动、连接保护及本机恢复入口准备；部署方只补齐自己控制的主机与网络条件。目的地尚未准备完成时，源体系继续可用；系统明确哪项条件缺失，不让用户自行研究内部配置。

保留原有访问地址时，连接自动接续；地址改变时，在原位置停用前保存并向在线连接交付新入口，宿主在目标接管后自动更新。离线设备已取得新入口的自动接续；未取得且旧地址失联的，在该宿主打开管理入口保存的新连接材料即可，沿用原授权。系统不依赖旧主机永久在线，也不承诺凭空发现新地址。

## 迁移与旧备份恢复

**迁移是同一体系的受控交接；旧备份恢复是显式回到历史快照，两者不能混用。**

迁移须保留资产身份、内容、版本、所有者、当前授权、撤销与遗忘结果，以及兼容且有效的组织状态；已接入智能体继续使用原授权。新主机的管理恢复入口重新建立，旧主机不能因重启重新提供活动服务。

迁移期间要求收回或缩小权限、忘掉信息，仍在原任务中办理：源尚未退出时，系统中止搬迁并使旧候选失效，先让决定生效，不要求用户等待搬迁结束；遗忘清理继续在后台完成。若交接已成立，则自动接到新位置处理；尚未生效或暂不可达时明确告知并保留请求，不能将等待中的决定报告为已完成。

只有目的地接管并验证可用后才报告完成；交接前失败可取消并保留源服务，源位置退出活动服务后发生故障则接续交接，不自动启用旧副本。不能通过回滚丢掉迁移期间已经接受的信息或恢复旧权限。

源位置不可用时，独立备份仍可用于恢复，但须明确其时间范围与旧凭据失效规则，不把缺失最新状态的恢复称为无损迁移。

## 质量与完成标准

正常取用不增加模型轮次、重复语义组织或全库复制；传输开销与内核处理分别度量，复用连接并按需传递材料。相同输入、权限和能力版本下，接入与迁移不能改变检索结果、证据含义或信息使用流程。

完成须具备可信接入、授权隔离、断线接续、提交结果核对和唯一权威迁移，且原有本机使用保持有效；等待状态、拒绝和恢复结果均能接回原任务。实测与功能审查的验收边界遵循[第一版交付定义](../delivery/first-version-delivery-definition.md#跨地点访问与迁移)。
