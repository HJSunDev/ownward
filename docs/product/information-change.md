# 信息随用户变化

本文定义信息变化的产品行为，遵循[产品需求](requirements.md)与[项目哲学](../philosophy.md)；实现职责见[信息变化架构](../modules/information-change/README.md)。

## 用户得到什么

**用户说明一次更正或变化，后续智能体能够采用适用的信息；继续旧任务时，不让已经过时的材料悄悄沿用。** 用户只需表达变化内容和必要条件，不需要选择更新模式、管理版本或逐个通知智能体。

重新读取已更新的信息取得当前内容，是已有基础能力。产品需要进一步做好变化含义的保存，以及已经取得的材料在再次使用时的核对。

## 使用过程

以下例子说明行为，不限定信息类型。

| 用户的需要 | 产品应有的行为 |
| --- | --- |
| “之前地址记错了，我一直住北京。” | 更正错误，不把上海居住经历当作真实历史；保留必要来源和与更正无关的内容。 |
| “我刚从上海搬到北京。” | 当前安排采用北京，过去的上海经历仍可用于历史任务；变化时间只依据已有信息，不编造日期。 |
| “下月开始按新预算执行。” | 保存这句话原有的时间参照与生效条件；以后读取或编辑时，“下月”不随之顺延，记录得晚也不等于现在就生效。 |
| 智能体继续上午未完成的安排，相关信息已被别的智能体修改 | 在再次使用旧材料时核对；取得受影响的新内容后继续原任务，不要求用户重述需求或提醒另一方刷新。 |
| 原资料没改，但用户另存了对它的明确更正 | 保存时连同更正对象一起记住；以后核对或读取原资料，能发现这份更正，不要求用户重复关联。 |
| “忘掉这份资料。” | 沿用[用户控制](information-control.md)的确认、停止使用与清理过程；不把覆盖正文或保留历史包装成遗忘。 |

智能体依据用户意图定位信息、理解变化并提交；系统保证可靠保存、并发保护和关联更新。只有对象、生效条件或修改范围存在影响结果的实质歧义时才澄清，不能要求用户学习内部分类。

## 保存什么含义

- **纠错：** 保存纠正后的含义。错误若因来源追溯而保留，必须能看出它已被纠正，不能继续当作有效事实。
- **现实变化：** 保存当前状态、仍有用的过去事实及明确的适用条件；不抹掉真实经历，也不要求永久保留每一次编辑的全文。
- **来源与冲突：** 保留原始来源作为证据时，另存或明确附加更正，并保留已明确的对应关系，不能把历史发言改写成从未说过的话。没有充分依据的矛盾保持未确定，不能简单以最后写入者为准。
- **时间参照：** 依赖表达时点的含义，连同已知表达时间及必要时区保存；来源没有提供时保留未知，只在影响用户当前结果时澄清，不用入库、编辑或读取时间猜补。

更正写在原资料内部或另存，使用效果一致：智能体只读取相关片段时，也能发现影响它的明确更正；不能让用户为防止遗漏而选择保存形式、拆分资料或提醒读取全文。

更新成功后，新内容已可靠保存，后续读取可取得它；关联理解尚未完成时如实表示待组织，不能用旧理解冒充已经更新。并发冲突由智能体取得当前信息后重新处理，不能静默覆盖别人的变更。

## 旧材料如何继续使用

宿主随取得的原文保留来源依据，在任务交接、中断恢复或再次用于当前判断、行动时按需核对。未变的材料继续用；变化的材料重新获取相关部分；已遗忘、无权取得或无法核实的材料，不再被作为已确认的当前依据。

**“这份材料没有变化”只说明材料仍与来源一致，不等于它仍适用于当前需求，也不代表没有新增信息。** 需要当前状态、完整汇总或确认信息不存在时，智能体还须针对需求查找相关依据；时间经过也可能改变适用性，即使正文没有修改。

第一版通过正式 Codex 接入包交付自动接续：用户完成一次安装、接入授权及宿主要求的扩展信任后，正常继续原任务即可，不用手工刷新、编写接续脚本或逐次开启检查。其他宿主按同一契约适配；仅连接工具、尚未启用接续适配的接入，不宣称具备自动接续。

这些处理嵌入宿主原有任务过程，只自动跟踪有界的近期材料；已结束或持续未使用的材料退出检查，再次需要时重新核对。退出检查不等于遗忘资料，也不删除有效工作。新鲜材料不额外复查，每轮对话不全量重读，不新增串行模型复核链；用户无需整理检查清单或为累积的历史材料持续等待。

## 边界与完成标准

核对反映取得结果时的来源状态，不保证信息从此不再变化。需要依据信息执行外部操作时，由宿主在实际使用边界核对；Ownward 不锁住外部世界，也不能强制改写其他智能体已形成的结论。

当前范围包括变化含义的忠实保存、按需依据核对及至少一种宿主的接续闭环。主动订阅通知、完整历史版本回溯和任意外部系统副本联动见[未来能力登记](future-capabilities.md)，不作为当前实现前提。

完成必须同时证明：更正与现实变化被正确沿用；交接和恢复能识别旧材料；新增相关信息不被旧版本检查掩盖；授权、遗忘和迁移边界保持成立；没有变化时不重复读取正文或增加模型调用，发生变化时只补与任务有关的工作。具体交付范围见[第一版交付定义](../delivery/first-version-delivery-definition.md#信息随用户变化)。
