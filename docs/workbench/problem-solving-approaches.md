# 策略库

积累可按问题特征选用、组合和切换的解题策略。

## 目录与选用

完整策略提供从问题到验收的推进主线；环节方法完成某项具体工作，并将产物交回主线。以下按主要障碍选用，能够直接解决的任务沿最短可验证路径完成。

**完整策略**

- [策略一：分组归因与组合修复](#策略一-分组归因与组合修复)：多项问题需要共享修复、处理相互影响。
- [策略二：逐步逼近](#策略二-逐步逼近)：完整任务过难，可从能够承接的简化版本推进。
- [策略三：反例驱动求解](#策略三-反例驱动求解)：原因尚不清楚，但能可靠找出候选解的错误。
- [策略四：矛盾驱动设计](#策略四-矛盾驱动设计)：方案反复在必须同时满足的要求之间冲突。
- [策略五：案例迁移求解](#策略五-案例迁移求解)：存在成功经验，可围绕关键差异迁移解法。
- [策略六：约束聚焦改进](#策略六-约束聚焦改进)：局部改善难以转为整体收益，存在可观测的系统约束。

**环节方法**

- [方法一：问题重构](#方法一-问题重构)：转换阻碍求解的表示与结构。
- [方法二：获取关键证据](#方法二-获取关键证据)：消除会改变下一步行动的未知。
- [方法三：构建解题能力](#方法三-构建解题能力)：将反复耗时或易错的操作交给可复用工具。
- [方法四：失败条件最小化](#方法四-失败条件最小化)：将复杂失败缩减为便于分析的复现案例。
- [方法五：调配求解投入](#方法五-调配求解投入)：在继续、取证、验证和换路之间分配投入。

### 组合、切换与积累

- 以当前主要障碍确定主线，明确所调用方法的任务、返回产物及其如何影响下一步。另一完整策略也可承接一个边界清楚的子问题，完成后回到整体目标验收。
- 切换前核对新路线的成立条件，并说明它能改变当前哪个障碍。依据关键前提失效、失败机制重复或新证据调整路线；阶段成果对最终目标的贡献决定是否继续投入。
- 难以决定继续、取证、验证或换路时，调用[调配求解投入](#方法五-调配求解投入)，取得下一步行动及其判断依据后回到求解。
- 始终保存可恢复且附有验证依据的当前综合最优候选。比较时统一原始目标、验收条件与投入上限，新方案经验证整体更优后替换。
- 新增条目是参考公开方法后的通用化整理，项目实效随任务验证。使用后记录问题特征、关键成败证据与总投入，分别标明情境推演、实际结果和对照增益，用于改进适用条件与流程。

## 策略一 分组归因与组合修复

**适用场景：**多项问题同时存在，需要识别共性与差异，并形成整体修复。

> **核心价值**
>
> 横向对照使共同原因共享修复，减少逐题重复投入；充分探索并比较不同机制，提高找到有效路径的机会，将投入集中到最有希望的组合；整体验证揭示方案之间的相互影响，让局部收益经过验证后累积为整体提升。

### 已确认流程

使用时，将原文中的“四题”对应为当前需要共同解决的问题集合。

```text
1. 逐题诊断，横向对照
   梳理每题的预期结果、实际偏差、可能原因及证据。比较四题，识别共有原因和各自特有的原因。

2. 依据证据分组
   将共享原因的题归为一组，为每组明确需要解决的问题、归因依据和待确认之处。

3. 每组充分发散候选机制
   尽可能提出有合理依据、实质不同的解决机制。每个候选说明：改变哪个环节、为何可能有效、适用条件、预期结果及验证方法。

4. 比较选优，整合实施
   综合因果依据、成功可能性、覆盖范围和实施成本，对各组候选排序。选择最有希望的方案组合，评估相互影响，合并共同改动、处理冲突，形成并完成统一修复。

5. 四题整体验证，持续迭代
   用同一修复版本运行四题的完整流程，逐题核对正确性，并比较整体效果与投入。保留已验证的收益，根据剩余问题的证据，调整归因、候选排序或实现，再进行整体验证。
```

### 按需增强

以下调用补充到对应步骤，方法产物参与后续选择和整体验证。

- **[方法二：获取关键证据](#方法二-获取关键证据)**
  - 触发：第1、2步存在竞争归因，或第4步的方案选择取决于某个未知。
  - 返回：用区分结果更新分组、归因或候选排序。

- **[方法一：问题重构](#方法一-问题重构)**
  - 触发：第1步的表达混杂影响定位，或第3步的候选反复受同一结构限制。
  - 返回：以转换后的问题重新分析，或将新表示形成的解法纳入候选，按原始目标比较。

- **[方法三：构建解题能力](#方法三-构建解题能力)**
  - 触发：第3、4步发现反复耗时或出错、可由工具承接的操作。
  - 返回：将工具及建设成本纳入方案比较，选用后接入统一修复。

- **[方法四：失败条件最小化](#方法四-失败条件最小化)**
  - 触发：第1、2步被复杂输入或长流程淹没，难以确定各题共享什么条件。
  - 返回：用缩减后的复现案例辅助归因，并回到原题核对分组依据。

**互补路线：**归因长期停滞而错误可可靠检验时，可转入[反例驱动求解](#策略三-反例驱动求解)；候选组合反复互相损害时，可用[矛盾驱动设计](#策略四-矛盾驱动设计)解决冲突，再回到组合验证。

## 策略二 逐步逼近

**适用场景：**完整任务难以直接取得进展，复杂度可以逐步恢复，阶段成果能够支撑后续求解。

> **核心价值**
>
> 先取得可以承接的可靠成果，再逐步扩大可解决的范围。相邻阶段的差异帮助定位新增障碍，已有成果降低后续探索成本；每轮投入以缩小原始目标的剩余差距为依据。

### 执行流程

```text
1. 明确完整目标与难度来源
   写清原始目标、全部约束、验收条件和可承担的投入。识别规模、依赖、约束或环境中影响求解的主要难点。

2. 选择简化起点与恢复路径
   构造保留关键关系的简化版本，列明每项简化如何恢复、已有成果如何承接到下一阶段。优先检查最可能阻断扩展的条件，选择有望通向完整目标的起点和顺序。

3. 取得并验证起点成果
   完成简化任务，核对该阶段的结果与成立条件，保存可恢复的方案和验证依据。根据实际结果修正后续扩展路径。

4. 逐步恢复复杂度
   每轮明确新增条件、可复用成果和通过标准，扩展方案并验证新增能力及已有能力。出现失败时，对照阶段差异定位障碍，修正方法或调整扩展顺序；多项条件叠加时检查相互影响。依据距离原始目标的差距分配后续投入。

5. 完成原任务并整体验证
   恢复全部原始条件，在完整任务中核对正确性、覆盖范围与总投入。达到原始验收标准后完成交付；剩余差距可沿当前路径推进时继续扩展，路径持续失效时保留有效成果并重新选择起点或完整策略。
```

### 按需增强

- **[方法一：问题重构](#方法一-问题重构)**
  - 触发：第2步难以构造可承接的简化版本，或第4步暴露表示方式的限制。
  - 返回：更新简化起点、转换条件或扩展路径。

- **[方法二：获取关键证据](#方法二-获取关键证据)**
  - 触发：第4步出现失败，几种解释对应不同的修正方向。
  - 返回：根据证据选择修正方法、调整顺序或更换路径。

- **[方法三：构建解题能力](#方法三-构建解题能力)**
  - 触发：第3、4步的构造或验证操作反复成为瓶颈。
  - 返回：将经过验证的工具用于当前阶段，并核对向后续阶段迁移的条件。

**互补路线：**阶段成果难以扩展时，用[获取关键证据](#方法二-获取关键证据)查清失效条件；恢复约束后暴露目标冲突时转入[矛盾驱动设计](#策略四-矛盾驱动设计)，发现满足原始条件的成功案例时可转入[案例迁移求解](#策略五-案例迁移求解)。

## 策略三 反例驱动求解

**适用场景：**候选解可以生成，正确性有可靠检验手段；归因难以推进，或方案反复在不同条件下出错。

> **核心价值**
>
> 将每次失败变成后续解法必须满足的约束，一次反例排除具有同类错误的候选，使验证结果直接推动搜索范围收缩。

### 执行流程

```text
1. 确定判定依据
   明确原始目标、允许的解法范围及验收方式。区分可覆盖全部要求的证明与有限样例检验，列出已知约束和反例。

2. 构造满足当前约束的候选
   生成同时满足全部已确认约束的方案。若构造失败，检查约束的依据与相容性，或调整解法范围、表示及构造方式。

3. 独立寻找反例
   围绕尚未覆盖的要求、边界与相互作用检验候选，取得可复现的失败条件。核对失败来自方案还是判定依据，并记录检验覆盖范围。

4. 用反例约束下一轮求解
   保存有效反例，明确它排除了什么行为。将有依据的共同失败机制归纳成约束；后续候选须同时通过历次反例，防止修复来回摆动。

5. 按原始目标收敛
   持续构造与检验，达到原始验收条件后交付。反例持续增长而约束无法有效缩小搜索时，调整表示或转向其他路线；保留最佳方案、有效约束与未覆盖要求。
```

### 按需增强与转向

- 反例复杂时，用[失败条件最小化](#方法四-失败条件最小化)提取更清楚的约束。
- 构造反复失败时，用[问题重构](#方法一-问题重构)调整搜索空间；约束冲突时转入[矛盾驱动设计](#策略四-矛盾驱动设计)。
- 检验只能提供有限覆盖时，按覆盖范围报告结果，并补齐原始验收所需证据。

**来源：**[MIT：Counterexample Guided Inductive Synthesis](https://people.csail.mit.edu/asolar/SynthesisCourse/Lecture17.htm)。

## 策略四 矛盾驱动设计

**适用场景：**改进一个目标会损害另一个必须满足的目标，现有候选反复被同一冲突淘汰。

> **核心价值**
>
> 把搜索重点放到造成冲突的关系与条件上，改变目标相互牵制的结构，从而获得能够同时满足要求的新方案。

### 执行流程

```text
1. 描述冲突与完整目标
   写清必须同时满足的要求、当前取舍及证据，定位哪个变化通过什么关系造成另一项恶化，并区分目标要求与现有实现假设。

2. 定位冲突成立的条件
   明确冲突发生的对象、时间、范围和环境。检查要求是否真正作用于相同条件，列出可调整的结构、控制方式和现有资源。

3. 构造消解冲突的机制
   分别尝试按时间、空间、条件分离要求，改变组成与相互作用，或利用现有资源完成所需作用。候选须说明如何同时满足原要求、付出什么代价及如何验证。

4. 选择并完成方案
   优先检验最可能使候选失效的关键关系，比较证据与总成本，选定机制并完成实现；把局部消解放回整体流程检查新增影响。

5. 验证完整目标并迭代
   在冲突两端及其交界条件下共同验收。剩余冲突用于修正模型或机制；发现目标本身在给定条件下不可兼容时，带回依据并确认可调整条件。
```

### 按需增强与转向

- 冲突关系尚不确定时，用[获取关键证据](#方法二-获取关键证据)区分真实依赖与表面相关。
- 解法难以构造时，用[案例迁移求解](#策略五-案例迁移求解)寻找已解决同类冲突的结构；用于组合修复时，交回方案与成立条件。

**来源：**[TETRIS 教学材料：ARIZ 的问题建模、构造与验证流程](https://innovazionesistematica.it/wp-content/uploads/2020/10/EN_03.pdf)。

## 策略五 案例迁移求解

**适用场景：**存在具有成功依据、关键结构与当前问题相近的案例，能够围绕差异完成适配；也可在自主构造停滞时寻找新的起点。

> **核心价值**
>
> 以已有成功路径及其成立条件为起点，把求解投入集中在新旧问题的关键差异上；每次验证后的适配又成为后续可复用的经验。

### 执行流程

```text
1. 按关键结构检索案例
   描述当前目标、约束、依赖与失败点，据此寻找已解决案例，优先比较决定成败的关系和条件。

2. 核对成功依据与迁移边界
   查清案例做法、实际结果及依赖的资源和环境。逐项对应当前问题，标明可复用部分、必须适配的差异和未知条件。

3. 验证迁移成立的关键条件
   检验最可能阻断复用的差异，比较适配成本与预期收益。选择有依据的案例或相容部分，写清适配方案与验证标准。

4. 完成适配并在原任务验证
   复用有效结构，补齐差异，在完整目标与约束下检验结果；根据实际失败修正映射和方案。关键结构不匹配时重新检索或选择其他策略。

5. 保存可复用的新案例
   达标后交付，并保存问题特征、方案、成立条件、验证依据与投入；保留失败适配及其原因，帮助后续检索避开已知失配。
```

### 按需增强与转向

- 领域用语遮蔽共同结构时，用[问题重构](#方法一-问题重构)建立对应；关键差异尚不清楚时，用[获取关键证据](#方法二-获取关键证据)判定能否迁移。
- 已有解法只在简化条件下成立、且存在可承接的扩展路径时，接入[逐步逼近](#策略二-逐步逼近)。

**来源：**[西班牙国家科研委员会：CBR 的检索、复用、修正与保留](https://www.iiia.csic.es/en-us/engagement/industry/technology-1/)。

## 策略六 约束聚焦改进

**适用场景：**任务涉及相互依赖的流程，局部改进难以提高整体有效产出，能够观测限制系统表现的环节或规则。

> **核心价值**
>
> 让投入作用于真正限制整体成果的约束，并调整其他环节对它的支持；随着约束转移重新聚焦，使局部能力转化为系统收益。

### 执行流程

```text
1. 定义整体成果与限制因素
   明确在正确性、质量等要求下需要提高的有效产出或完成效率。沿完整流程观测损失与等待，用证据找出最有全局影响的限制因素。

2. 发挥约束环节的现有能力
   检查其输入、排队、返工、切换与资源使用，优先减少浪费，使现有能力作用于真正需要完成的工作。

3. 协调其余环节
   调整上下游的质量、节奏与优先级，确保约束环节得到合适输入、其成果能被后续利用。共同约束存在时，协调它们的依赖与资源分配。

4. 必要时提升或改变约束
   若整体仍未达标，比较扩充能力、调整规则与重构流程等机制，选择有依据且成本合适的方案，完成改进。

5. 以整体收益验收并重新聚焦
   在可比条件下验证完整流程的正确性与总效果。根据结果修正限制因素判断；约束转移时更新配合方式，达到整体目标后交付。
```

### 按需增强与转向

- 难以判定哪个因素限制整体时，用[获取关键证据](#方法二-获取关键证据)检验改变该因素能否影响最终产出。
- 约束来自反复操作时调用[构建解题能力](#方法三-构建解题能力)；观测显示主要是多项独立正确性问题时，转入[分组归因与组合修复](#策略一-分组归因与组合修复)。

**来源：**[Theory of Constraints Institute：Five Focusing Steps](https://www.tocinstitute.org/five-focusing-steps.html)。

## 方法一 问题重构

**使用时机：**概念混杂、复杂依赖或现有表示持续阻碍分析与求解。

> **核心价值**
>
> 改变问题的表示和结构，使已有能力更容易发挥作用，降低推理、实现或验证的难度。

### 操作步骤

```text
1. 找出当前表示造成的具体困难，保留原始目标、约束和验收条件。

2. 提出有实质差异的新表示，说明变量、关系或边界怎样对应原问题，以及预期降低的困难。

3. 核对转换前后的对应关系，用关键样例与边界情况检查遗漏、成立条件和解的还原方式。

4. 比较转换成本与求解收益，将最有希望的新表示、还原规则及检查依据交回主流程。求解结果仍按原始目标验收。
```

## 方法二 获取关键证据

**使用时机：**某个未知会改变归因、分组、候选选择或下一步行动。

> **核心价值**
>
> 用一次有区分力的观测或实验排除多条错误路线，提高后续行动的命中率。

### 操作步骤

```text
1. 明确待作出的决策，列出会改变该决策的未知与竞争解释。

2. 为各解释写出可观察的预期，并说明不同结果分别导向什么行动。

3. 比较观测或实验的区分能力与成本，执行最有决策价值的取证；尽量保持其他条件一致，记录实际结果。

4. 依据结果更新解释并交回证据、剩余未知和建议行动。结果仍含糊且追加取证值得投入时调整实验；已有证据足以支持行动时回到主流程推进。
```

## 方法三 构建解题能力

**使用时机：**已有运行证据显示同类操作反复成为瓶颈，复用收益有望覆盖建设与维护成本。

> **核心价值**
>
> 将反复耗时或易错的操作转化为可靠的可复用能力，用一次建设支撑后续多次求解。

### 操作步骤

```text
1. 定位瓶颈操作，记录它对正确性、耗时和后续求解的影响。

2. 比较现成工具、已有成果复用和新建能力，明确所需输入、输出、适用范围以及建设成本。

3. 完成所需能力，用已知结果和边界情况独立验证，保留可复现的使用方式与依据。

4. 将能力、成立条件和成本交回主流程，在原任务中检验整体收益，并据实际效果决定保留、改进或调整。
```

## 方法四 失败条件最小化

**使用时机：**复杂输入、配置或长流程造成可重复的失败，缩减后的复现案例有望降低分析难度，重复检验成本可承担。

> **核心价值**
>
> 保持同一失败，逐步剥离无关条件，压缩需要解释的范围；将精简案例交回诊断或反例分析，使下一步更容易定位和验证。

### 操作步骤

```text
1. 保存原始复现与判定依据
   固定必要环境，明确怎样识别同一失败，并区分正常结果、目标失败和输入无效等无法判定的情况。

2. 逐步缩减失败条件
   按有意义的单位删除或简化输入、配置、步骤或改动，每次检验是否仍触发同一失败。保留有效缩减，无法继续时改用更细粒度或其他简化方式。

3. 核对复现与缩减范围
   达到足以支持分析的规模或投入边界后，复核原始与缩减案例的失败对应关系，记录已尝试的缩减及剩余条件。

4. 交回定位依据
   返回精简案例、复现方式与判定证据，说明已检验的最小性范围。用它支持归因和干预验证；最终修复回到原始完整任务验收。
```

**来源：**[Andreas Zeller：Delta Debugging 教材与实现](https://www.debuggingbook.org/html/DeltaDebugger.html)。

## 方法五 调配求解投入

**使用时机：**多条可行路线争夺投入，当前进展不足以支持继续或切换的决定；可用于各完整策略的选择与推进节点。

> **核心价值**
>
> 把下一次思考、取证或实现视为有成本的行动，按它对最终结果的预期贡献分配投入，并用实际进展不断修正选择。

### 操作步骤

```text
1. 明确当前决策与剩余差距
   保留最佳成果及证据，写清距离原始目标的差距、关键未知和可用投入。

2. 列出值得比较的下一步
   包括继续当前路线、补充证据、验证候选、调用方法或切换策略。为每项写清预期产物、如何影响最终结果及其成立依据。

3. 比较收益与成本
   依据已有证据，对行动的预期收益、成功把握、成本和不确定性排序，将组织与评估自身的开销计入。长线探索结合关键未知的减少及可承接成果判断价值。

4. 执行并更新判断
   选择最值得投入的行动，约定本轮应取得的证据与投入边界。执行后对照预期更新路线价值；不同判断导向不同选择时，可先取有区分力的证据。

5. 将决定交回求解主线
   返回下一步、理由、预期产物及复核时机。达到原始验收条件时交付；可继续取得有价值进展时推进，投入边界已到时保存最佳成果并报告剩余差距。
```

**来源：**[Stuart Russell：理性元推理与有界最优性](https://aima.eecs.berkeley.edu/~russell/research-bo.html)；[Learning to Select Computations：近似选择计算行动](https://arxiv.org/abs/1711.06892)。此处将其整理为面向任务的定性决策方法。
