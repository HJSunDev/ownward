# 取证作答提速：双任务协作

## 共同目标与依据

第4环节“继续取证并形成结果”在固定14题上平均达到约60秒量级，质量至少13／14、争取全过；需求准备保持十来秒。完整等待计入排队、纠错与重试，不以转移阻塞、增加未披露成本或牺牲必要证据换取提速。不扩大到24题或500题。

正式基线为提示词修订后两轮均10／14的版本。以 `.tmp/evidence-answer-improvement-20260913/baseline/identity.json` 和封存源码核对身份；正式文件及当前暂存状态保持不动。候选完成验收后保存并报告，只有用户明确授权采用才进入正式代码。

[质量任务](../tasks/task-quality-improvement.md)维护当前正式版本问题；[历史正式版记录](../research/formal-prompt-quality-20260913.md)保存实验基线；[策略库](problem-solving-approaches.md)提供执行方法。本页只维护协作分工、资源与交接，不复制实验历史。

## 沟通与互相监督

- 使用 `mcp__codex_app__send_message_to_thread` 向上述线程ID发送消息；双方都可主动发送。消息包含“发送方、发现或请求、证据路径、需要对方采取的动作”，不改对方模型与档位。可用 `wait_threads` 的即时状态和共享产物核对进展。
- 在选路、候选就绪、实验结束、发现错误或停滞时通报；普通阅读与编辑无需逐条通报。对方忙时消息可能排队，资源交接必须等到明确确认，不能把已发送当作已接收。
- 候选交接以B确认的文件路径和校验值为准；确认前原作者保留交付文件，不重复实现或切换入口，确认后的迟到建议不改变已冻结实验。
- 实验前由另一方检查关键因果依据、是否重复已淘汰机制、候选是否真正接入、控制条件与成本。审查只处理会影响决策的缺陷，不增加形式性材料。
- 实验后交流完整结果、局部收益、反例及成本；不得仅报通过数或忽略失败尝试。分歧转成最小可验证问题，共识不代替证据。
- 每次上下文压缩后先读本页、本页当前交接和自己的实验记录，检查重复准备、逐题补丁、无依据试错、串行等待与过晚止损；发现低效先纠正再继续。
- 不追加子智能体或定时任务；不通过打断对方运行取得资源。

## 资源与实验隔离

1. **付费实验唯一启动方为B。** A并行进行证据分析、候选实现和离线检查，将就绪候选及明确的实验请求交给B；B可以运行自己的或A的方案。同一时刻只运行一组可计时实验。
2. 总上限为6个题目任务，共用标准8槽模型调度；两臂配对共计6个，不是各6个。原始资料和有效语义结果复用；确有语义直接依赖变化时才并行重建受影响资料，不能同时叠加另一组模型任务。
3. 有模型计时实验时，另一方避免全量构建、全套测试、大规模拷贝等资源竞争；先完成这些准备，再申请实验。运行前后核对实际进程、并发和文件身份。
4. 需要更换唯一启动方时，现启动方先停止派发、确认相关运行退出并明确移交；未完成移交则继续由B启动。
5. 每个候选使用独立源码或overlay、独立二进制及结果目录。共享基线只读，资料每次使用独立副本；禁止同时覆盖正式文件、公共实验脚本或对方产物。
6. 付费调用前离线证明候选入口确实生效、工具与结果协议可用；不能仅凭类名或配置名判断。执行异常按具体请求及时定位，保留已完成资料及答案，不无依据整批重跑。
7. 每组实验以启动前保存的版本、样本和条件为准。运行开始后不暗换样本或拼接成绩；不影响本轮有效性的后到建议用于结果解释或下一轮，发现执行错误则及时止损。

## 收敛与完成

按“约束聚焦改进”推进，必要时用“矛盾驱动设计”消除速度与质量冲突，以“获取关键证据”和“调配求解投入”控制试错。比较实质不同的机制后集中推进，不把协作本身变成任务。

B维护可恢复的综合最优记录，A独立复核其依据。局部收益与整体资格分开，候选之间的小样本对照不得代替相对正式基线的收益验证。只在机制互补且控制条件明确时组合，组合后单独验证。

固定模型、档位、原文、预算和判分；理解与判断仍由外部智能承担，不向产品路径提供标答或官方答案来源标签。最终以同一候选完整14题及完整成本验收，满足共同目标后双方停止并报告，正式版本不自动更新。
