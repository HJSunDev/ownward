```text

持续执行以下循环：

1. 先从目标与产品需求独立推导架构必须回答的问题，再审查现有架构总纲是否准确承载。
2. 以“首席产品官 + 乔布斯式产品直觉 + 顶级架构师”的标准判断：
   - 是否抓住产品不可替代的本质与边界；
   - 是否形成职责清晰、依赖稳定、逻辑闭合的整体架构；
   - 是否以最少的结构完整承载需求，没有多余能力、重复职责和低价值复杂度；
   - 当模型、存储、检索技术、协议和智能个体形态变化后，核心架构是否仍然成立；
   - 是否不存在阻碍检索时效、检索质量、信息组织质量以及轻量运行目标的结构性瓶颈。
3. 严格控制颗粒度。架构总纲只保留整体结构、核心职责、能力边界、依赖方向、关键不变量及质量目标的架构响应；不得进入模块拆分、接口定义、数据结构、算法流程、技术选型、参数指标、实施步骤和交付计划。
4. 每项架构判断必须能够直接反绑产品需求，或属于满足明确需求不可缺少的架构推论。不得以最佳实践、未来可能、技术先进性或“更加完整”为理由扩张范围。
5. 完整审查一轮后统一归并问题并集中修复根因，随后复审受影响范围。最优架构不是抽象最多或预建最远，而是锁定范围内最简单、完整、清晰、可演进且没有已知结构债务的方案。
6. 准备结束时，对同一份未修改的最新文档分别执行产品本质、整体架构、长期稳定性与性能支撑、需求反绑与范围控制四次独立冷启动审查，不得复用此前结论。任何一次发现问题，都应继续修复并重新执行全部审查。

只有产品依据本身存在冲突或缺失，且不同选择会改变产品定位或需求范围时才暂停询问；其余架构判断自主收敛。

完成条件：

- 所有必须由架构承载的需求均有准确落点；
- 产品边界、核心职责、依赖关系和关键不变量清晰一致；
- 架构能够支撑既定质量与性能预期，不存在已知结构性阻碍；
- 内容始终停留在架构总纲层级，没有设计细节和实现细节；
- 不依赖当前具体技术，也没有为未来预建产品能力；
- 不存在需求之外的复杂度和已知结构债务；
- 同一份未修改文档通过全部冷启动审查。

满足后回复“架构总纲收敛完成”，简要说明最终判断和实际修改，立即停止，不再追加视角、继续润色或扩大范围。
```
