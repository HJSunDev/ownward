### 审查问题与解决方案

```
以顶级架构师的身份，审查“解决问题工作台”中的问题与解决方案。

脱离现有结论，从产品需求出发、独立判断问题是否真实成立；站在最强反方立场检查它是否只是误解、局部现象或没有必要解决的问题。
问题成立后，再判断解决预期是否准确，解决方案是否能够完整覆盖根因及全部受影响链路、彻底消除问题且不留下同类隐患；是否保留了真正必要的产品能力、没有过度修复、范围扩张、额外复杂度或对其他架构与功能的影响；是否已经是当前范围内最简单、可靠、高效并能经受长期变化的最优方案。

直接回复，不要动手；
```

### 按解决方案修复问题

```text
以 `problem-resolution-workbench.md` 为任务依据，按照“问题解决预期”和“问题解决方案”逐项彻底修复问题。
每次开始、恢复或上下文压缩后，重新完整读取该文档并核对仓库当前事实。

只关注本问题的解决，不得改变其他架构、模块职责、正式能力契约和既有功能，不得扩大范围。
完成后以最小充分的测试、构建和隔离预检证明全部解决预期真实成立，并按文档要求处理旧状态、证据和残留。

全部方案完成、全部预期通过且不存在旧错误链路或无关影响后，简要回复；
```

以顶级架构师的身份，按 `problem-resolution-workbench.md` 中问题的预期和解决方案，审查问题是否得到真正的彻底解决且无负作用。
