# 验收体系

## 目标体系

建立一套长期稳定的 **Ownward Acceptance Suite v1**。它独立于内核实现，内核怎么迭代都使用同一把尺子。Ownward 自有的测试数据、真值、评分器、执行配置、版本清单和结果证据随项目公开；第三方基准固定官方版本和执行协议，不擅自复制受限制内容。独立第三方能够依照公开材料复现并审查结论。

> **最高级评测不变量：**评测适配器可以约束资源，但不得替代外部智能体承担主动检索、证据积累、方向调整、停止判断和结果组织。违反该边界的结果只能作为诊断，不能证明产品质量、内核根因或晋升资格。

体系由一个高频优化闭环和三层验收证据组成。

### 内核前沿优化环

内核前沿基准使用版本化的固定多规模资产快照、变更序列、查询与真值，并冻结向量和语义输入，不调用外部智能能力，不重新沉淀或审查数据。固定规则以固定种子生成不改变真值的身份、顺序、时间、场景和干扰信息变体；新候选与当前有效内核基线始终运行同一批变体，防止针对固定表面形式调优。基准在相同环境下呈现二者与同期公开可复现等价前沿的差距；外部前沿只在基准版本、对标对象或环境变化时重新校准，不在每轮优化中重复运行。没有等价外部基线时，当前最佳结果只能作为内部基线，不能据此宣称达到前沿。

基准提供不超过三分钟的定向模式和不超过十分钟的完整模式：定向模式只运行受当前修改影响的能力与阶段；完整模式覆盖全部受保护能力，并在候选进入资格验证前执行。结果必须分别呈现信息身份、关系质量、错误合并与拆分、增量一致性、组织和索引成本，以及各类检索中词法、向量、关系、场景、融合阶段的质量、时效与资源变化；保留逐项证据并定位损失发生的阶段，使组织错误、召回缺失、排序错误、关系污染、场景误判和性能瓶颈能够直接进入修复。该基准参与开发调优，只承担优化反馈，不能作为最终验收证据。

质量、时效和资源分别设防，不计算可以相互补偿的综合分。新候选只有在完整模式下所有受保护能力均未发生超过重复测量误差的退化，且至少一项指标达到随基准版本预先固定的有效改善时，才能进入资格验证；资格验证通过后才成为新的有效内核基线。

### 验收证据

1. **固定内核基线**以确定性、本地、低成本验证资产保存、更新、恢复、重建、身份稳定、派生状态可销毁、模型可替换等产品不变量，不调用外部智能能力。
2. **固定 Ownward 专项数据集**覆盖跨时间、多跳关联、场景适用、信息更新和关系组织增益。每个场景必须具有完整输入、可核对证据、容纳合理语义表达的真值边界和确定的评分方法；通过一次冷启动审查后随版本冻结，不在候选验收时重新审查。第一版完整集固定为四类能力各六个场景，共二十四个场景、一百二十条信息；资格集随版本固定选取每类两个代表场景。该规模只承担第一版产品能力覆盖与回归验证，不被包装成开放世界通用性的统计证明，也不得为追求表面完整而继续扩张。

   - 资格验证使用其中固定的代表性子集。
   - 最终验收使用同一数据集的完整集合。
   - 相关实现发生变化时复用同一数据重新运行，不重新生成或重新验证数据。
   - 发现新缺陷只能在新版本中追加回归场景，不能改写既有版本。
   - 任何测试数据、真值、评分规则或执行口径变化都必须产生新的不可变版本，旧版本和旧成绩永久保留；只有产品要求或验收语义发生实质变化时才升级主版本。
3. **LongMemEval‑S 官方清洗基准**
   作为第一版唯一的社区主基准，固定使用官方清洗数据、官方协议和完整 500 题。它直接验证长期用户—助手交互中的信息提取、跨会话推理、时间推理、知识更新和拒答，既覆盖 Ownward 长期个人信息的主体能力，也是 Zep、Mem0、Supermemory 等同类记忆基础设施公开采用的共同口径，因此能够形成专业、可复核的同行比较。[官方仓库](https://github.com/xiaowu0162/LongMemEval) [选择依据](../research/first-version-benchmark-basis.md)

   官方问答准确率与 Ownward 在固定等价条件下测得的检索时延、返回上下文量和资源成本分别报告，不得把项目自测指标冒充官方指标，也不得用不同 Reader、裁判、检索预算或数据版本的成绩直接比较。LongMemEval‑M 只是相同任务的扩大量级，LongMemEval‑V2 测量的是多模态 Web Agent 环境经验；二者均不属于第一版社区主基准，不得为追求测试数量而追加。Ownward 专项集只证明产品自身要求，不能替代官方成绩或由项目自行宣称行业领先。公开基准暴露的缺陷只能抽象为通用能力问题并进入新版内核前沿基准，不得复制题目、答案或为特定样本增加规则。

   社区层通过只表示官方 500 题按冻结协议完整执行、证据齐全且成本在界内；准确率保持独立报告，在没有等价生产口径基线时不虚构质量阈值，也不阻断三层证据汇总。

   产品评测固定为 `external-agent-progressive`：外部智能体直接接收问题，自主调用 Ownward 搜索、导航、证据检索与读取能力，并依据累计观察继续、调整或停止后组织答案；宿主只执行工具与预算约束，不预选证据或决定读取顺序。未暴露工具、禁止工具调用、启用宿主固定预取或不能保留多步主动检索时，盲测与正式入口必须失败关闭。

   性能必须按测量对象分别报告：单次 Ownward 工具调用时延评价内核；单题多轮主动检索累计时延评价内核与外部智能策略的组合；从问题开始到最终计分答案的整题时延评价产品体验。门槛必须与测量对象、工作负载和权威依据一致；不能追溯或借用自其他口径的数值不得参与候选裁决。评测进程耗时只约束评测效率，不得判为内核失败。

   失败统一按[最终测试失败归因](#最终测试失败归因)核实原因，再确定改进方向；证据不足时保持未决且不得据此修改内核。通过批次销毁逐题现场，失败批次完整保留至归因关闭，同一套件最多保留一个失败现场。

外部智能是验收执行依赖，不是业务流程实现。生成、语义组织、Reader 与 Judge 只依赖 `ownward.external-intelligence/v1` 的结构化 turn、动态工具、用量、失败与恢复合同；供应商进程、认证定位和传输事件只存在于具体适配器。每份证据仍显式封存供应商、模型、推理档位、适配器和执行制品身份。替换供应商必须先证明角色能力、工具闭环、输出 Schema、失败语义、成本和恢复等价，不能通过稳定端口静默降级。

Qwen3.8 Flash 已通过[相关推理能力核验（10／10）](../../.tmp/kernel-fast-iteration/qwen-phased-20260906-171906/capability-and-flow-summary.json)，当前作为测试环境中模拟外部智能体的可替换模型使用；实际任务效果由模型能力与信息交付、协作流程共同决定。

验收证据按组织准备、语义组织、索引、查询检索、证据读取、回答与裁判分段寻址；变化只失效自身及下游。执行入口必须复用直接依赖未变的分段结果，禁止因查询侧、评测流程、文档或全仓身份变化重做组织、语义、索引及其他无关证据。候选只提交通用组件清单与分段汇总，高层验收控制器不得枚举具体事故或修复证据。

执行层级与触发条件固定为：

- 普通开发：只运行覆盖当前变更的定向测试。
- 影响身份、资产、派生世代、备份或恢复不变量的变化：运行固定内核基线。
- 影响组织或检索行为的变化：运行内核前沿基准定向模式。
- 一轮内核优化形成明显整体改善：运行内核前沿基准完整模式、完整回归和低成本端到端保护，冻结候选身份后进入版本级 5、15、25、50 题盲测。
- 四级盲测全部通过且候选未变：复用全部有效分段证据，只补齐一次固定内核基线、固定资格集和完整 Ownward 专项集。
- 全部内部验证通过：对同一候选最后运行一次完整 LongMemEval‑S 官方清洗基准。
- 同一候选汇总三层证据，形成 Ownward Acceptance Suite v1 的最终结果。

在第一版固定规模和基准环境下，固定内核基线不得超过五分钟，内核前沿基准定向模式不得超过三分钟、完整模式不得超过十分钟，资格集不得超过三十分钟，完整内部验收不得超过九十分钟。LongMemEval‑S 只在最终候选上执行；全量前必须以最小代表样本实测单位成本并冻结总墙钟、调用量和费用上限，实际成本超出边界时立即停止并修复执行路径，不得用等待代替解决问题。

失败只使该项及依赖它的上层证据失效；修复后只重跑失效层级。不得重新生成验收数据、重复仍然有效的无关工作、对未修改候选重复执行同一验收，或把完整专项集和官方基准下沉到日常迭代。

版本级盲测只运行已冻结候选，用于在最终测试前尽早暴露未知数据上的真实缺陷；相对基线提升与既有能力保护由盲测前的同尺比较和完整回归承担。资格与完整专项入口必须机械拒绝尚未完成四级盲测的候选；盲测入口必须机械拒绝未完成完整回归、低成本端到端保护和身份冻结的候选。

用于 qualification/full 的外部智能制品绑定、成本预检和执行准备属于四级盲测后的最终内部验收准备，不得成为进入盲测的前置；盲测自身使用的外部智能仍由已封存版本套件、评价批次和共享条件独立绑定。

## 最终测试失败归因

**最终测试出现问题，必须基于原始题目、实际交付给智能体的信息、处理过程与判分证据，从以下四个方向分析，查清具体原因后再决定在哪里发力。** 先确认执行与判分正常，服务失败、未完成或判分执行错误单列处理，不能冒充任务能力缺陷。

| 方向 | 判断依据 | 发力位置 |
| --- | --- | --- |
| **1. 内核／信息获取没做好** | 完成任务所需的事实、来源、时间条件或澄清没有忠实交付；原文存在、来源被搜到，不等于智能体实际拿到了必要信息。 | 定位信息维护、组织、检索、证据交付或接入中的真实断点，修复对应通用机制。 |
| **2. 信息给到了，但没有用好** | 必要信息已交付，模型具备相关能力，却在关联、范围、冲突处理或形成结论时使用不当。 | 改善协作规则、上下文与外部智能体的工作流程；不能因信息已给到就免除信息使用工程的责任。 |
| **3. 模型能力不足** | 有能力核验或对照证据支持：排除信息交付与流程干扰后，模型仍缺少任务所需的理解、推理能力；不能仅凭一次答错或一种流程无效下结论。 | 明确外部模型能力限制，不扩展内核去代替模型智能。 |
| **4. 题目预期不合理** | 标答无法由现有信息通过合理解释、有依据的推断或必要限定得到支持，必须臆造事实或无依据地排除有效证据才能命中；数据有冲突本身不构成此类。 | 复核确认后登记原因，停止以命中该标答为优化目标；正式测试仍保留该题和原始计分。 |

同一题可以有多个原因，分别记录依据与对应改进项；证据不足的部分保持未决，不强行归类。职责内缺陷修复其背后的通用短板，不为题目表面或标答定制规则；职责外限制按[产品职责边界](../product/requirements.md#职责边界)登记处理。

## 用户提示词

### 审查验收体系

```text
顶级架构师的身份，以乔布斯的视角再次审查这个验收体系，静态区。是否专业，是否可行，是否能高效地把内核持续推向前沿。

有问题修复，没问题直接回复。
```

### 审查验收体系执行计划

```text
以顶级架构师的身份，以乔布斯的视角审查这个验收体系的执行计划。完整执行后是否必然以专业、可行、高效且不扩大范围的方式，将项目现状收敛为静态区已经定稿的验收体系；是否彻底清理旧错误路径、错误数据和无效产物；是否只建设并验证验收体系本身，在具备开始正式验收的全部条件后立即停止，不提前执行任何正式验收；是否不会改变产品架构、模块职责和既有功能。

有问题修复，没问题直接回复。
```

### 审查验收体系实现

```text
以顶级架构师的身份，以乔布斯的视角审查当前验收体系实现。静态区已经定稿，不得修改，也不得通过降低标准使现有实现通过审查。

检查代码、固定数据、真值、评分器、适配器、执行入口、证据生命周期、成本控制、公开说明和清理结果，判断它们是否完整、准确地实现静态区规定的验收体系；是否专业、公开、可复现；是否能够高效推动内核持续达到前沿，并以固定内核基线、固定 Ownward 专项数据集和官方清洗 LongMemEval‑S 形成可靠的三层验收证据；是否具备明确的候选与环境绑定、结果复用、局部失效、中断恢复、异常停止和基线晋升能力；是否不存在测试专用产品路径、重复入口、旧错误流程、无效数据、临时残留和无法真正执行的纸面设计。

审查与修复只能作用于验收体系实现及其直接说明，不得改变产品定位、整体架构、模块职责、正式能力契约和既有功能，不得扩大验收范围，也不得提前运行资格集、完整专项集或 LongMemEval‑S 等正式验收。使用最小夹具、单元测试、隔离自检和非正式预检证明体系自身真实可用；不得以文档描述代替可执行实现。

有问题修复并重新审查，没问题直接回复。
```
