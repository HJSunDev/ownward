# 第一版交付定义

第一版是产品本质成立的最小完整版本，不是存储、检索或智能体接入的单项原型。它必须在一个可实际运行的产品中完成“智能体使用—信息沉淀—自主组织—检索使用—经验回流—再次受益”的闭环，并证明个人信息资产能够脱离当前运行实例独立持有和完整恢复，全部派生状态能够仅凭资产重建。

以下交付边界与完成条件必须全部成立；任何一项未通过，第一版均未完成。

## 一、交付边界

### 智能体接入

完成至少一种现有主流软件智能体的真实接入。该智能体通过统一核心检索、读取、创建和更新同一份权威信息资产，并从体系本身获得使用、维护和主动补充信息所需的规则；用户通过该智能体使用体系。第一版由这个接入智能体兼任[《语义理解架构》](../modules/semantics/README.md)规定的外部语义能力，通过统一能力契约中独立的语义工作与权限边界为内核提供开放内容理解，不内置第二个智能体，也不要求额外模型服务或密钥。

### 信息沉淀

能够承载需求文档规定的广义个人信息，而非局限于项目知识或智能体记忆。依赖场景的信息与场景关联，不依赖场景的信息不被强制场景化。信息进入体系不要求接入的智能体设计目录、分类体系或关系结构。

### 自主组织

体系自主建立并持续维护信息之间的语义关系，能够处理不同时期产生的相关信息，并表达多重归属、层级、交叉、组合和场景关系，不因组织位置不同而复制同一信息或形成彼此割裂的真相。可替换的外部语义能力提供带来源、依据和不确定性的候选判断；第一版由接入的外部智能体兼任该角色。内核不独立判断开放内容真伪，而是负责身份、版本、来源、证据与结构不变量，管理冲突、不确定性和组织状态并对最终质量负责，不能把目录、分类和关系结构的设计责任转嫁给接入方。

### 检索使用

第一版覆盖明确对象检索、语义意图检索、关系约束检索和场景适用性检索。各类检索的质量与端到端时效必须同时达到验收时公开可验证的同类系统前沿，不得以牺牲其中一项、缩小信息范围或挑选有利场景换取另一项达标。

复杂检索由接入的智能体基于累计证据多轮调用内核完成；内核提供可组合、可迭代的检索能力，不内置检索智能，也不代替智能体选择检索方向、评估累计证据、判断结束或组织结果。

第一版最终采用的检索编排必须通过 Ownward Acceptance Suite v1 的内核前沿优化环、固定 Ownward 专项数据集与官方清洗 LongMemEval‑S 公开对标验证，并与[《检索体系演进》](../modules/retrieval/README.md)中的当前有效版本一致。只有可靠证据表明某个替代编排可能改变完成结论时，才增加对应的定向对照，不为证明“已经比较过”而另行制造候选和重复全量验收。

### 持续成长

智能体在真实任务中形成的错误教训、解决经验和可复用路径能够回到同一信息体系，经体系组织后被后续独立使用直接获取并正确应用，使同类任务不再重复已经沉淀的错误，并以更短路径完成。

### 资产独立与恢复

个人信息资产与当前内核及其派生组织、索引和检索状态相互独立。仅凭信息资产即可重建派生状态并恢复核心能力；备份副本能够由用户脱离原设备、第三方服务和原运行实例独立持有，并在空白环境中完整恢复为可用的信息资产。

第一版必须落实[《存储架构》](../modules/storage/architecture.md)规定的权威资产、当前派生世代和可销毁运行状态边界。派生状态更新或重建只有在完整生成并通过校验后才能原子切换；失败不得暴露半成品或破坏上一个有效世代，稳定切换后旧状态能够回收。

### 产品交付

正式发布包完整包含第一版所需的本地向量模型和运行时。用户安装 Ownward 后无需另行选择模型、申请服务、提供密钥、启动模型进程或完成产品额外设置即可使用完整向量能力；通用语义理解通过统一契约由可替换的外部语义能力提供，第一版由正在使用 Ownward 的外部智能体兼任，不依赖额外服务。Ownward 自有代码与第三方制品的许可边界清晰，模型条款、用途限制、`NOTICE`、修改说明和运行时许可证均随包交付，并在组包与发布时完成完整性和对应关系校验。

第一版按[《向量模型方案》](../research/vector-model-selection.md)集成经过验证的模型、运行配置和向量生成方式，并遵守[《向量能力架构》](../modules/embedding/README.md)规定的空间身份、能力世代和故障边界；选型阶段的独立结果不能替代最终交付形态的集成验收。

## 二、验收基线

第一版验收统一采用 [Ownward Acceptance Suite v1](../../benchmarks/acceptance/suite/README.md)。固定内核基线证明资产与派生状态不变量；固定 Ownward 专项数据集以四类各六个场景验证产品组织与检索能力，固定资格集承担候选晋升；固定版本的官方清洗 LongMemEval‑S 提供社区可比较的长期记忆质量、检索时效与成本证据。三层证据必须绑定同一候选、发布二进制、环境、输入和工具并分别通过，不能相互替代。

专项数据集的内容、真值、评分和资格子集在候选产生前已经完成冷审并随版本冻结。相关实现变化时复用同一版本，只重跑受影响层级；发现新缺陷只能形成新的不可变数据版本，不得改写既有材料、按候选结果筛选场景或在候选冻结后重新生成验收数据。内核前沿优化环使用冻结的向量与语义输入和确定性变体，为日常迭代提供可定位的质量、时延与资源反馈，但不能替代三层正式证据。

所有验收必须运行正式发布默认路径，不得通过验收专用模型服务、测试语义实现、替代向量空间或产品侧测试开关制造结果。Ownward 自身操作遵守冻结时延，外部语义协作遵守异常停止与成本边界并如实记录端到端耗时，检索遵守公开前沿；不得把来源不明的数值当作产品门槛，也不得用宽松超时累计等待。

最终候选版本开始验收前，必须重新确认对标对象仍代表当时公开可验证的同类前沿。验收标准不得因产品未通过而降低、替换或缩小；只有独立证据证明原定义本身错误时才可纠正，纠正原因、证据和全部变化必须完整记录并重新冻结。

1. 固定验收环境、资源条件、能够代表个人长期积累的信息规模与增长梯度、更新要求、并发负载，以及用于检索验收的外部智能体、模型版本、上下文和检索预算；不得以孤立的小规模样本代替实际产品规模。
2. 固定 Ownward 专项数据集必须覆盖跨时间、多步关联、场景适用和信息更新，每类六个场景、每个场景五条信息；关系真值容纳合理语义表达，内容、真值、评分、资格子集、版本和摘要全部公开且不可变。
3. 以固定版本的官方清洗 LongMemEval‑S 证明完整产品在长期用户—助手交互记忆上的社区可比质量，并在等价 Reader、裁判、检索预算和数据条件下独立比较检索时效与成本；四类产品能力由固定 Ownward 专项数据集判定。只有主基准无法覆盖明确需求时，才补充能够改变完成结论的最小外部证据。
4. 内核前沿优化环分别保护关系准确性、错误合并与拆分、增量一致性、组织与索引，以及词法、向量、图、场景和融合阶段；质量、时延与资源不得相互补偿。固定历史基线中的既有关系标签只保留诊断价值，不承担当前完成证明。
5. 固定信息持久写入、基础可检索等 Ownward 自身操作的时延上限，以及沉淀信息所需的最大交互次数。外部语义能力的推理时间与 Ownward 操作时延分别记录；在没有公开可比依据时不得人为设定绝对通过线，但必须受有界执行、异常停止和完整成本核算约束。
6. 在功能范围、信息规模、质量、更新要求和资源条件等价的前提下，分别为信息内核和完整交付产品确定程序体积、CPU、内存、存储占用及信息写入、持久化、组织和索引效率的同期前沿、复现方法与通过阈值。完整交付口径必须包含发布包全部文件和 Ownward 启动的完整进程树；模型与运行时只能从信息内核的等价对标中排除，不能从完整产品验收中排除。两条轨道独立判定、分别通过，不计算能够互相补偿的综合分。
7. 检索编排首先复用内核前沿优化环、固定专项数据和公开前沿证据完成判断；只有现有证据无法收敛、且具体替代方案可能改变第一版结论时，才在查看结果前固定该方案、任务类别、质量、时效、资源指标和选择规则，执行最小定向对照。

所有批量验收在全量执行前必须用最小代表性样本同时验证执行有效性与单位成本，推算完整耗时、模型与智能体调用量、存储和外部费用，并证明既定规模不能由更小的等价证据替代。通过预检的批量工作必须保留有效检查点，只补未完成或无效部分；发现系统性失败或实际进度明显偏离推算时立即停止，不得整批重做已经成立的工作。规模数据用于验证内核容量时，可以直接构造符合生产格式的派生数据，不得把十万条容量验证误做成十万次模型推理；模型生成质量、吞吐和资源另以最小充分样本验证。

未形成上述基线，或基线无法独立复现，第一版不得进入完成判定。

## 三、完成条件

| 编号 | 验收对象 | 通过条件 |
|---|---|---|
| 1 | 智能体接入 | 接入的智能体能够通过统一核心检索、读取、创建和更新信息，并在第一版兼任外部语义能力，通过统一能力契约中彼此隔离的能力边界获取语义工作、提交带来源、依据与不确定性的候选判断；体系提供的协作规则足以使其正确使用、维护和主动补充信息，验收不得依赖适配层或智能体私有提示中预置同一规则。不同独立会话看到相同的信息身份、内容和变更结果；所有持久信息及其变更均以统一核心为权威，验收结果不依赖接入方私有副本或旁路状态。 |
| 2 | 信息范围 | 固定内核基线与固定 Ownward 专项数据集共同覆盖需求规定的信息范围和关键组织形态；相关信息全部能够进入体系，内容及明确语义无丢失。依赖场景的信息保持正确场景关联，非场景信息不产生强制场景归属，仅属于外部智能体的短期工作状态不会被当作个人信息资产。 |
| 3 | 信息沉淀 | 接入的智能体提交信息后无需另行设计或维护目录、分类和关系。必要的语义澄清不得超过固定的最大交互次数；提交成功返回时，信息已经成为可持久读取的长期信息资产，并在既定时延内达到基础可检索状态和既定组织质量。 |
| 4 | 信息组织 | 在输入信息不携带目录、分类方案和关系金标的前提下，第一版由接入的外部智能体兼任语义能力，通过正式语义理解路径提供带来源、依据和不确定性的候选判断。内核验证身份、版本、来源、证据和结构不变量，管理冲突与不确定性并维护组织状态，不得假装独立判断开放语义真伪。固定专项信息分批进入并发生更新后，跨时间关联、多重归属、层级、交叉、组合及场景关系持续达到组织质量基线；明确语义保持率为 100%，不得发生改变信息含义的错误合并、拆分或身份变化；关系组织必须对固定专项任务产生可验证增益。 |
| 5 | 检索质量与时效 | 固定的外部智能体通过内核完整执行四类检索任务；简单检索能够一次完成，复杂检索能够依据累计证据持续调整方向并正确结束，专项集同时覆盖跨时间与多步关联。最终编排必须通过内核前沿优化环、固定专项数据和官方清洗 LongMemEval‑S 公开对标验证，并与《检索体系演进》的当前有效版本一致。质量不低于各自质量前沿，典型延迟与尾部延迟不高于各自时效前沿，并且同一实现同时满足两组条件。任何任务类型未达标即不通过。 |
| 6 | 成长闭环 | 固定闭环场景的首次任务因缺少相关个人信息而失败或走入已知错误路径；智能体将带有适用场景的教训与有效路径补充进体系后，新的独立会话能够检索并正确应用这些信息，避开原错误并按沉淀路径完成任务。验收集中的闭环场景必须全部通过。 |
| 7 | 资产与内核独立 | 长期信息资产自身完整保存稳定身份、内容和明确语义，不依赖模型参数、提示词、索引或未记录的内核逻辑才能成立。在隔离环境中仅保留长期信息资产并移除全部派生状态后重新构建；重建前后的资产 100% 一致，重建后的创建、更新、读取、组织和检索验收全部通过。派生世代完整生成并校验后才能原子切换；生成、校验和切换失败时，上一个有效世代及资产保持可用且不暴露半成品，成功后旧世代能够回收。 |
| 8 | 备份恢复 | 用户独立持有的备份不依赖原设备、第三方服务和原运行实例即可向空白环境执行完整恢复。恢复后的信息身份、内容和不可重建语义与备份源 100% 一致，且检索、读取、创建、更新、信息组织和协作规则验收全部通过。仅复制成功但无法恢复使用，不视为有效备份。 |
| 9 | 轻量与全链路效率 | 信息内核作为 Ownward 自身核心能力独立对标，完整交付资源只评价用户实际承担的产品成本；同一最终版本必须分别通过两条轨道，不得合并评分或相互补偿。完整交付的安装体积、冷启动、空闲与工作状态 CPU、内存、存储和完整进程树均计入，不得排除随包交付或由 Ownward 启动的模型、运行时和子进程；程序体积与资源占用均不高于各自基线，信息写入、持久化、组织和索引效率均不低于各自前沿阈值。反复更新和派生失败不得造成历史资产、旧派生世代、旧索引或恢复日志无界增长，不得以牺牲功能、信息质量、资产耐久性或其他性能指标换取单项达标。 |
| 10 | 产品交付 | 在全新环境中只使用正式发布包完成安装后，《向量模型方案》规定的模型、运行时和完整向量生成配置已经可用，模型、运行时、空间身份、派生向量和索引属于同一有效能力世代，不存在新旧空间混用。完整产品不要求另行配置模型服务、密钥或人工启动附属进程；第一版接入的外部智能体能够经统一契约兼任语义能力并完成语义理解。向量或语义能力暂不可用时信息仍能可靠进入资产并保留明确待处理状态，不依赖相应能力的核心操作继续工作。发布包对 Ownward、EmbeddingGemma 和 llama.cpp 分别保留正确许可身份，并完整包含模型条款、用途限制、`NOTICE`、修改说明和运行时许可证。 |
| 11 | 工程质量 | 最终实现逐项符合架构总纲、存储架构、向量能力架构、语义理解架构、向量模型方案、检索体系当前有效版本和开发规范，适用的格式化、静态检查、测试及构建全部通过，独立代码与架构审查不存在边界内已知缺陷、架构偏离或结构债务。目录、代码、文档和工程入口清晰一致；独立开发者仅依据仓库内容即可理解项目结构并完成构建、运行和整体验收，不依赖仓库未记录的项目知识或步骤。 |

## 四、第一版不包含

1. 不要求同时适配多个外部智能体，也不要求实际接入具身智能体和未来智能个体；第一版接入不得反向绑死统一核心、信息资产或后续接入形态。
2. 不包含面向用户的图形化产品、直接交互入口或内置智能体；面向用户的交互由外部智能体产品承担。
3. 不要求多设备实时同步、高可用、连续备份和自动容灾；但基础完整备份与恢复不能省略。
4. 不要求实现第二代内核或在线切换两套内核；但从长期信息资产重建全部派生状态并恢复核心能力必须通过。
5. 不包含多人协作、公共知识库和特定业务模块；第一版只验证属于单个用户的广义个人信息体系。

## 五、完成判定

完成判定必须先锁定同一份未修改的最终候选版本、发布二进制、验收体系版本、环境、固定材料和工具，从空白环境沿真实生产路径依次完成固定内核基线、固定 Ownward 专项完整集和官方清洗 LongMemEval‑S，并由唯一入口汇总三层报告与原始证据。任何会影响结论的候选、二进制、环境、输入或工具变化，只使其影响层级及上层证据失效；仍满足全部绑定字段的无关证据必须复用，不得整套重做。

完成条件用于证明产品真实成立，不是供执行者寻找字面通过路径。执行验收的智能体必须依据产品意图和实质等价作出判断；任何通过削弱对照、隐藏成本、合并结果或利用未列明空白获得的通过均视为失败。发现可能造成假通过的新路径时，应主动阻断并保留判断依据，不得利用。

模拟实现、测试替身、人工整理、旁路能力、针对验收数据的特殊分支或无法独立复现的结果，均不能作为通过证据。

只有本文件的交付边界和完成条件全部成立、明确排除的内容未进入第一版，且不存在跳过、豁免或边界内已知失败，才能判定第一版完成。否则继续开发，不能以“主体可用”“基本完成”或后续补齐结束任务。
