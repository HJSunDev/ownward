# 第一版交付定义

第一版是产品本质成立的最小完整版本，不是存储、检索或智能体接入的单项原型。它必须在一个可实际运行的产品中完成“共同使用—信息沉淀—自主组织—检索使用—经验回流—再次受益”的闭环，并证明个人信息资产能够脱离当前内核完整恢复。

以下交付边界与完成条件必须全部成立；任何一项未通过，第一版均未完成。

## 一、交付边界

### 统一使用

提供用户可直接使用的入口，并完成至少一种现有主流软件智能体的真实接入。用户与智能体通过同一核心作用于同一份权威信息资产，均能检索、读取、创建和更新信息；智能体能够从体系本身获得使用、维护和主动补充信息所需的规则。

### 信息沉淀

能够承载需求文档规定的广义个人信息，而非局限于项目知识或智能体记忆。依赖场景的信息与场景关联，不依赖场景的信息不被强制场景化。信息进入体系不要求使用方设计目录、分类体系或关系结构。

### 自主组织

体系自主建立并持续维护信息之间的语义关系，能够处理不同时期产生的相关信息，并表达多重归属、层级、交叉、组合和场景关系，不因组织位置不同而复制同一信息或形成彼此割裂的真相。

### 检索使用

第一版覆盖明确对象检索、语义意图检索、关系约束检索和场景适用性检索。各类检索的质量与端到端时效必须同时达到验收时公开可验证的同类系统前沿，不得以牺牲其中一项、缩小信息范围或挑选有利场景换取另一项达标。

### 持续成长

智能体在真实任务中形成的错误教训、解决经验和可复用路径能够回到同一信息体系，经体系组织后被后续独立使用直接获取并正确应用，使同类任务不再重复已经沉淀的错误，并以更短路径完成。

### 资产独立与恢复

个人信息资产与当前内核及其派生组织、索引和检索状态相互独立。仅凭信息资产即可重建派生状态并恢复核心能力；备份副本能够由用户脱离原设备、第三方服务和运行内核独立持有，并在空白环境中完整恢复为可用的信息资产。

## 二、验收基线

在针对验收结果进行实现和调优之前，必须固定第一版验收基线。基线一经固定，只能提高要求，不得因产品未通过而降低标准、替换数据、改变指标或缩小范围。

1. 固定验收环境、资源条件、信息规模、更新要求和并发负载。
2. 固定不参与实现调优的验收集及其权威答案。验收集必须覆盖需求规定的信息范围，同时包含跨时间相关信息、多重归属、层级、交叉、组合、场景依赖和非场景依赖信息。
3. 为四类检索任务分别确定同期公开、可复现且条件等价的质量前沿与时效前沿，记录候选系统、选择依据、复现方法、原始结果和最终阈值。
4. 为信息组织建立权威关系标注，并确定关系准确性、覆盖率、错误合并与拆分、增量一致性、人工干预和检索增益的通过阈值。存在公开可复现的可比能力时不得低于同期最优基线；不存在时，必须在查看本产品结果前固定数值标准。
5. 固定信息持久写入、基础可检索和完成组织的端到端时延上限，以及沉淀信息所需的最大交互次数。

未形成上述基线，或基线无法独立复现，第一版不得进入完成判定。

## 三、完成条件

| 编号 | 验收对象 | 通过条件 |
|---|---|---|
| 1 | 统一核心 | 用户创建的信息可由接入的智能体检索、读取和更新；智能体创建的信息可由用户检索、读取和更新。双方看到相同的信息身份、内容和变更结果，且不存在接入方私有的信息副本或旁路真相。智能体从体系本身取得协作规则后能够完成上述操作。 |
| 2 | 信息范围 | 固定验收集中属于个人经历、心理活动、社会经验、知识、技能、工作信息、实践方法、错误教训、解决经验和可复用路径的信息全部能够进入体系，内容及明确语义无丢失。依赖场景的信息保持正确场景关联；非场景信息不产生强制场景归属。 |
| 3 | 信息沉淀 | 使用方提交信息后无需另行设计或维护目录、分类和关系。必要的语义澄清不得超过固定的最大交互次数；提交成功后信息立即可读取，并在既定时延内达到基础可检索状态和既定组织质量。 |
| 4 | 信息组织 | 在不向体系提供目录、分类方案和关系答案的前提下，固定验收集中的跨时间关联、多重归属、层级、交叉、组合及场景关系均达到组织质量基线；明确语义保持率为 100%，不得发生改变信息含义的错误合并、拆分或身份变化。 |
| 5 | 检索质量与时效 | 四类检索任务分别在固定验收环境和验收集上完整运行。质量不低于各自质量前沿，典型延迟与尾部延迟不高于各自时效前沿，并且同一实现同时满足两组条件。任何任务类型未达标即不通过。 |
| 6 | 成长闭环 | 固定闭环场景的首次任务因缺少相关个人信息而失败或走入已知错误路径；智能体将带有适用场景的教训与有效路径补充进体系后，新的独立会话能够检索并正确应用这些信息，避开原错误并按沉淀路径完成任务。验收集中的闭环场景必须全部通过。 |
| 7 | 内核独立 | 在隔离环境中仅保留长期信息资产，移除全部派生组织状态和检索状态后重新构建。重建前后的信息身份、内容和明确语义 100% 一致，重建后的创建、更新、读取、组织和检索验收全部通过。 |
| 8 | 备份恢复 | 用户独立持有的备份不依赖原设备、第三方服务和原运行内核即可向空白环境执行完整恢复。恢复后的信息身份、内容和不可重建语义与备份源 100% 一致，且统一核心、信息组织和检索验收全部通过。仅复制成功但无法恢复使用，不视为有效备份。 |

## 四、第一版不包含

1. 不要求同时适配多个外部智能体，也不要求实际接入具身智能体和未来智能个体；第一版接入不得反向绑死统一核心、信息资产或后续接入形态。
2. 不要求完整、精美的图形化产品；但用户必须具有能够完成第一版全部核心操作的直接入口。
3. 不要求多设备实时同步、高可用、连续备份和自动容灾；但基础完整备份与恢复不能省略。
4. 不要求实现第二代内核或在线切换两套内核；但从长期信息资产重建全部派生状态并恢复核心能力必须通过。
5. 不包含多人协作、公共知识库和特定业务模块；第一版只验证属于单个用户的广义个人信息体系。

## 五、完成判定

完成判定必须从空白环境执行一次完整、可复现的第一版验收，并生成包含基线版本、产品版本、环境、数据、逐项结果和原始证据的验收报告。

只有本文件全部完成条件均显示为“通过”，且不存在跳过、豁免、人工整理替代产品能力、临时修改验收数据或已知的边界内失败，才能判定第一版完成。否则继续开发，不能以“主体可用”“基本完成”或后续补齐结束任务。
