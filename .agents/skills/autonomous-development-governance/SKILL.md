# 自主开发治理

本技能依据长期自主开发中的真实结果持续演进

## 一、体系核心

高度自主开发体系以**明确起点、约束执行、完成终点**构成闭环，并以稀疏、不可变的关键留痕保持跨周期连续性。体系先把产品意图和完成标准说清，再将范围内的实现决策交给智能体自主完成；自主权不等于无边界，约束也不应退化为逐步指挥。

持续开发提示词是主线任务入口，只标识任务目标与权威依据，并规定如何从项目事实恢复、持续推进和结束；治理机制由本 Skill 与运行时承担，不得让主 Agent 维护治理体系，也不得复制、重述或代替权威文档。

### 起点：目标与设计依据

起点由职责递进的三层文档组成：

1. **用户需求原话**保存未经抽象替代的需求起点，使后续判断能够回到用户真实意图。
2. **产品需求**从原话中凝练产品定位、范围、能力、原则和质量目标，是产品判断的权威依据。
3. **架构总纲**由产品需求推导整体结构、职责边界和长期不变量，为开发提供稳定方向，不反向增加或改变需求。

三层内容逐级收敛但不可互相取代：原话保证意图不失真，产品需求明确要构建什么，架构总纲明确以什么长期结构承载它。

### 执行：受约束的高度自主

开发规范规定代码设计、实现质量、验证方式及必要的工程边界。在已经明确的产品目标、架构方向和完成条件内，智能体自主决定实施顺序、技术方案、代码设计、问题修复和验证路径，持续推进而不依赖人类逐步分派。规范用于守住质量和边界，不负责替代实现判断，也不得借约束扩大产品范围。

### 终点：可判定的完成契约

完成定义必须充分且可判定：全部条件在同一最终成果上成立，必须足以证明开发预期已经完整实现；每项条件都必须明确验收对象、通过标准和可复核证据，使独立执行者无需猜测即可唯一判定通过或不通过。任一条件未满足即继续开发；不能覆盖预期或依赖“基本完成”“主要可用”“后续补齐”等模糊解释的完成定义，本身即不合格。

### 持续记忆：关键工作留痕

关键工作留痕是高度自主开发体系的持续记忆：以稀疏、只增、不可变的记录保存无法从当前代码和权威文档直接还原，却会约束后续方向的重要结论，确保任务中断、上下文压缩或执行者更换后仍能从正确起点继续。它不是过程日志；只有删除某条记录会导致误判关键方向、重复高成本错误或无法确认重要阶段状态时才记录，否则不记录。

在需要维护记录模块时，完整读取 [关键工作留痕搭建规范](references/key-work-records.md)；

## 二、体系必须面对的现实

体系设计必须建立在智能体真实的能力边界上。目前已经确认两项长期存在的现实：

1. **跨上下文连续性不可靠**：大模型的上下文窗口有限，历史对话压缩可能丢失此前的关键语义；体系不能把目标、约束和工作连续性建立在单次对话记忆始终完整的假设上。
2. **自主执行缺少稳定的全局复核**：智能体具备识别低效、无价值或错误路径的能力，受到外部打断后往往能够迅速作出正确判断；但在持续执行中，它可能一直受局部任务牵引，无法主动回到宏观视角复核当前操作的必要性、价值和效率，因而钻入牛角尖并持续消耗资源。已经发生过一次长达 9 小时 30 分钟、经打断后立即确认没有价值的执行过程，这说明问题不在判断能力本身，而在缺少自主触发全局复核的可靠机制。

## 三、自主治理闭环

体系以单一持续开发者为唯一实现主体，并用**可恢复执行状态、确定性看门狗以及固定与事件独立复核**补足持续性与全局视野；不运行第二个常驻开发者，也不把监督责任交还给人类。

### 可恢复执行状态

执行状态是可覆盖更新的当前事实，不是关键工作留痕。它持续映射尚未满足的完成条件、当前工作焦点及其价值、涉及范围、预期证据、当前证据检查点、最近有效检查点、可复用结果和唯一下一动作。任务开始、恢复或上下文压缩后必须先读取权威依据与该状态，再继续工作。

### 固定与事件复核

每次主任务首次启动、恢复或完成上下文压缩后，都在自然边界触发一次独立 Governor 复核并取得反馈，不依赖主开发者判断当前是否已经到了“关键时刻”，也不抢占正在执行的正常动作。Governor 必须先从目标、完成条件、仓库事实和原始证据独立重建整体进度，找出最关键的未满足条件，再审视主开发者的当前路径是否必要、高效且为现有事实下的最优选择；发现浪费、低效或次优路径时，必须指出问题并给出能够直接执行的更优方案。

**Governor 的反馈必须进入主 Agent 的决策过程，但执行决定始终属于主 Agent。**主 Agent 必须阅读并明确回应反馈，可以采纳，也可以基于可复核事实说明不采纳的理由和下一验证点；Governor 不得替代主 Agent 作出或强制执行决定，Hook 也不因此获得任何执行控制权。

Governor 是没有刹车权和方向盘的副驾驶：它必须在规定时机把风险和更优路线说清楚，主 Agent 负责回应和判断，并始终掌握执行权。工作关系固定为“明确复核边界 → 主 Agent 启动只读 Governor → Governor 返回风险与更优方案 → 主 Agent 回应并继续开发”。Governor 与 Hook 不得拦截工具、拒绝写入、冻结、暂停或接管任务，也不得限制其他任务；Governor 不可用至多使本次独立反馈缺失，不能阻止主线继续。

启动标识只负责把治理顾问接入这个目标，绝不能把整个对话锁进一种模式。治理开启后，用户仍然可以在同一对话安排任何其他工作，主 Agent 必须正常执行。同一主任务只设一个 Governor，并由同一份治理状态贯穿始终；同一触发重复投递时复用已有复核，新的合法触发仍由这个 Governor 后续处理，不得另建第二条治理支线。

固定复核之外，确定性看门狗在到达证据检查点却未取得预期证据、同类失败重复、范围漂移、代表性探测准备扩大投入、阶段结束和准备宣称完成时触发事件复核。Governor 不实现功能，只提出具有明确价值、范围和下一证据检查点的工作建议，或保留有效结果并给出更优方案。两类复核之间，正确路径不受额外流程干扰。

批量、付费、不可逆或资源密集的动作先以最小代表性样本证明路径有效并取得客观资源事实；这不是开发工时预估，也不产生任务时长上限。独立有效结果即时形成检查点，后续只补失败或缺失部分。除真正的产品决策或经事实确认无法自行取得的外部权限、凭证与状态外，技术问题、路径失效和效率异常均由治理闭环自主处理并继续。真实用户介入必须形成可持久的待处理事项；用户答复与原事项绑定并恢复工作连续性，后续复核只负责检查恢复路径是否仍符合目标，不得依赖对话记忆。
