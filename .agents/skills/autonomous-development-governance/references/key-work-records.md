# 关键工作留痕搭建规范

本规范仅用于建立、复用、迁移或审查关键工作留痕子模块。

## 建立模块

```text
records/
├─ README.md          — 体系规则与分卷索引
└─ work-log-NNNN.md   — 每 50 条递增的记录分卷
```

初始化时创建 `README.md` 和 `work-log-0001.md`。`README.md` 写入本规范中的准入、不可变、内容、分卷和恢复规则，并在末尾维护分卷索引：

```markdown
## 分卷索引

`work-log-0001.md` — 自 R-000001 起。
```

每卷以卷号、起始编号和不可变声明开头：

```markdown
# 关键工作留痕 0001

> 本卷自 R-000001 起，只能在末尾追加记录，不得修改、删除、覆盖、重排或重新编号既有内容。
```

## 准入与颗粒度

只有删除某条记录会导致后续智能体误判关键方向、重复高成本错误或无法确认重要阶段状态时才记录；无法证明必要性时默认不记录。

- **关键进展**：改变项目阶段或后续工作起点的重要结果。
- **关键决策**：确定或改变产品、架构、技术方向、项目结构、质量或交付边界的结论。
- **关键问题**：会改变后续路径或避免重大重复损失的根因判断与解决方案。

决策在结论确定时记录；进展和问题在结果明确后记录。尚未解决的问题只有已经阻断后续工作时才允许提前记录一次。同一事项只保留一条；结论或影响实质变化时再追加关联记录。例行操作、普通故障、局部实现、格式调整、重复验证及可由代码或权威文档直接还原的内容不记录。

## 不可变与分卷

- 记录使用全局连续且永不复用的 `R-NNNNNN`，跨分卷递增。
- 只能向当前分卷末尾追加，不得修改、删除、覆盖、重排或重新编号既有记录。
- 错误、推翻、补充和替代必须新增记录并引用原编号。
- 实质性规则变化先追加关键决策记录，再更新 `README.md`；不得改写历史记录或既有索引项。
- 每卷 50 条；当前卷写满后，只在下一条记录产生时创建下一编号分卷，从上一卷的下一全局编号开始，并向索引末尾追加一行。

## 内容与格式

单条正文不超过 300 个汉字，标题和证据路径不计入。只写结论及不可缺少的依据和影响，不复制需求、设计、代码、日志或验证报告；详细内容引用权威来源。无信息增量的字段省略，不得记录密钥、凭证或个人敏感信息。

```markdown
## R-NNNNNN｜关键进展/关键决策/关键问题｜标题

- **时间**：YYYY-MM-DD HH:mm（Asia/Shanghai）
- **结论**：必须保留的结果、决策或问题解决方案。
- **依据**：仅在结论无法自行说明时填写。
- **影响**：仅在会约束后续工作时填写。
- **证据**：相关记录编号或权威文档、代码和验证位置。
```

## 恢复读取

恢复任务时只读取 `README.md` 的分卷索引、当前分卷和当前工作直接引用的历史记录，不无差别加载全部历史。
