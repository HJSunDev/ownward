# 剧本·独立复核（固定 2 角色，串行）

依据 [权威文档 §5.2](../../../../docs/workbench/cross-session-collaboration.md)；入口遵循 §3.12 独立模式，完成判定遵循 §3.5。

发起人=被审方（用户所在会话优先）。审查方对被审产物只读；运行测试/构建须持资源租约，验证绑定冻结快照。

| 相位 | 动作与约束 | 产物 |
| --- | --- | --- |
| request | 提供目标、范围、变更、逐项验收标准、材料来源与筛选说明、已知故障证据和完整被审对象；作者猜测与重点建议在独立发现落盘后交换，不限制检查范围；正文按消息模板分区；被审版本冻结（记录哈希） | `request.md` + 冻结快照（expectation: review） |
| independent-review | 审查方可自行查找补充证据；findings 落盘前不与被审方讨论判断或解法，事实澄清可附证据进行；每条含严重度/证据/影响/建议/置信度 | `findings/<reviewer>.md` |
| disposition | 被审方逐条 accept\|reject\|defer + 理由 + 证据；禁止无理由全盘接受 | `disposition.md` |
| fix | 修复 accepted 项；写改了什么、没改什么、为什么 | `changes.md` |
| verify | 审查方独立验证修复（不能只看摘要）；可 reopen | `verification.md` |
| close | 全部发现已处置且**全部 blocker 已关闭**，并逐项证明成功标准达成才可 completed；reject/defer 不能代替达标，摘要顶部列未关闭 major/minor 与残余分歧 | 关闭状态消息 |

**blocker 关闭仅三条路径**：①修复并经审查方 verify；②审查方书面接受降级并附证据；③用户明确接受并记录。被 reject 的 blocker 不得视为关闭——继续查证或修复，授权与预算内无法消除争议再升级用户；待裁决先 waiting，超时按 §3.7 记 dead-letter，不得带着 blocker 宣布完成。

**冻结失效**：被审版本身份变化即失效，必须重审；提交时核对提交哈希与冻结哈希一致。

**无否决权**：审查方无 veto；被审方拥有最终决定权，异议保留、高严重度分歧不得埋没。

**未达标与重开**：按具体缺口修复、补证和复验，无新信息不重复辩论；确实受阻或硬预算耗尽如实报告未达项、证据、阻碍和推荐，不能降标报成功。客观项由角色举证，用户偏好/用户明确保留的验收引用用户裁决；待裁决保持 waiting 并按超时纪律处理。发现有证据的客观缺陷可在授权内重开修复，不等用户否决，也不代判满意或擅改用户已接受的取舍。

**发现条目格式**：

```markdown
- [<blocker|major|minor>] <标题>
  - 位置：<文件:行 或 缺失点>；证据：<为什么是问题>；影响：<后果>
  - 建议：<修复方向>；置信度：高|中|低
```
